## 第 0 章 环境与学习姿势

### 0.1 编译器与标准开关

C++11 是 2011 年发布的标准，现在（GCC / Clang / MSVC）早已完整支持。关键是**显式指定标准版本**，否则默认可能是 C++98 或 C++17。

```bash
# 单文件编译（推荐起步就用这一串）
g++ -std=c++11 -Wall -Wextra -Wpedantic -O2 -pthread main.cpp -o main

# 想看清「拷贝/移动到底发生了几次」时，关掉编译器的优化（复制消除）
g++ -std=c++11 -fno-elide-constructors demo.cpp -o demo

# 开启 sanitizer 查内存/线程问题（学习期强烈建议）
g++ -std=c++11 -g -fsanitize=address,undefined main.cpp -o main
g++ -std=c++11 -g -fsanitize=thread -pthread main.cpp -o main
```

| 选项 | 作用 |
|---|---|
| `-std=c++11` | 指定语言标准（也可用 `c++14` / `c++17`） |
| `-Wall -Wextra -Wpedantic` | 打开大部分警告，**新手必须开** |
| `-O2` | 优化；调试时换成 `-g -O0` |
| `-pthread` | 使用 `std::thread` 时在 Linux 下必须链接 |

> ⚠️ 常见坑：忘了 `-pthread`，程序编译通过但运行时抛 `std::system_error: Enable multithreading to use std::thread`。

### 0.2 CMake 最小模板

只要超过 1 个源文件，就用 CMake，别手敲 g++。

```cmake
cmake_minimum_required(VERSION 3.10)
project(WordCount CXX)

set(CMAKE_CXX_STANDARD 11)
set(CMAKE_CXX_STANDARD_REQUIRED ON)   # 不支持就报错，绝不悄悄降级
set(CMAKE_CXX_EXTENSIONS OFF)         # 关掉 GNU 扩展，保证可移植

set(CMAKE_CXX_FLAGS "${CMAKE_CXX_FLAGS} -Wall -Wextra")

find_package(Threads REQUIRED)
add_executable(wordcount main.cpp)
target_link_libraries(wordcount PRIVATE Threads::Threads)
```

### 0.3 三条学习建议

1. **先懂「为什么」，再记「怎么写」**。C++11 几乎每个特性都是为了解决 98 的一个具体痛点（拷贝太贵、类型写太长、回调太啰嗦、没有标准线程等）。
2. **每个特性写一份 30 行的小 demo**，加打印，亲手验证。移动语义一定要打印地址/计数，否则永远学不会。
3. **不要一次吞下所有特性**。优先级建议：
   `auto / 范围 for / nullptr / 统一初始化` → `移动语义` → `智能指针` → `lambda` → `override/delete/default` → `STL 新容器` → `并发` → `模板进阶`。

## 第 1 章 让代码变短：类型推导与语法糖

### 1.1 `auto`：让编译器替你写类型

```cpp
std::map<std::string, std::vector<int>> table;

// C++98
std::map<std::string, std::vector<int>>::iterator it = table.begin();

// C++11
auto it = table.begin();          // it 的类型由初始化表达式推导
auto pos = table.find("key");     // 少写 60 个字符，且改容器类型时不用改代码
```

规则与注意点：

| 写法 | 含义 |
|---|---|
| `auto x = expr;` | 按值拷贝，**丢掉引用和顶层 const** |
| `const auto x = expr;` | 按值拷贝，得到 const 值 |
| `auto& x = expr;` | 保留底层 const，绑定到左值 |
| `const auto& x = expr;` | **遍历容器时的首选**，不拷贝不修改 |
| `auto&& x = expr;` | 万能引用（第 2 章详讲） |

```cpp
const std::vector<int> v{1,2,3};
auto  a = v;          // a 是 vector<int>          （顶层 const 被丢掉）
auto& b = v;          // b 是 const vector<int>&
for (const auto& n : v) { /* 只读，零拷贝 */ }
```

> ⚠️ `auto` 会丢掉引用，所以 `auto x = *it;` 是**一次拷贝**。想要引用必须显式写 `auto&`。

**什么时候不该用 `auto`**：类型本身是重要信息、且无法从上下文一眼看出时（例如 `auto rate = calc();` 看不出是 `double` 还是 `int`）。接口边界处宁可写显式类型。

### 1.2 `decltype`：我要「表达式的类型」，但不要它的值

```cpp
int a = 0;
decltype(a)      b = 1;   // int
decltype((a))    c = a;   // int&  —— 注意括号！(a) 是左值表达式，得到引用
decltype(a + 0)  d = 2;   // int

// 典型用途：函数模板的返回类型依赖于参数
template <typename A, typename B>
auto add(A a, B b) -> decltype(a + b) {   // 尾置返回类型
    return a + b;
}
```

`decltype` 最常见的两个用途：
1. **尾置返回类型**（`auto f(...) -> decltype(...)`）：C++11 的 lambda 与模板函数常需要。
2. **类型别名中转**：`using T = decltype(container.begin());`

> C++14 起可以直接写 `decltype(auto)` 和省略尾置返回类型（`auto add(A a, B b) { return a + b; }`），更省心。

### 1.3 范围 for（Range-based for）

```cpp
std::vector<std::string> names{"Ann", "Bob"};

for (const auto& s : names)  std::cout << s << '\n';  // 只读 → const auto&
for (auto& s : names)        s += "!";                // 要改元素 → auto&
for (auto s : names)         { /* 拷贝一份，通常没必要 */ }
```

它本质上是语法糖，等价于：

```cpp
{
    auto&& __range = names;
    auto __begin = begin(__range), __end = end(__range);
    for (; __begin != __end; ++__begin) {
        const auto& s = *__begin;
        /* 循环体 */
    }
}
```

**注意**：
- 循环体内**不要增删容器元素**（迭代器失效，同普通 for）。
- 想遍历自定义类型，只需提供 `begin()` / `end()` 成员（或非成员 `begin(T)` / `end(T)`）。
- C++11 中不能在范围 for 里 `std::move` 元素吗？可以，但要写 `auto&&` 或 `auto&` 再 `std::move(s)`。

### 1.4 `nullptr`：干掉 `NULL` 和 `0`

```cpp
void f(int);
void f(char*);

f(NULL);      // 灾难：NULL 通常是 0 → 调用 f(int)
f(0);         // 同上
f(nullptr);   // ✅ 明确调用 f(char*)
```

`nullptr` 的类型是 `std::nullptr_t`，**不是整数**，能隐式转换成任意指针类型，不能转成 `int`。
**新代码里永远不要写 `NULL`，也不要用 `0` 表示空指针。**

### 1.5 统一初始化 `{}` 与 `std::initializer_list`

```cpp
int  x{10};            // 直接初始化
int  y = {10};         // 拷贝列表初始化
int  z{};              // 零初始化 → 0（不再有"忘了初始化"的 bug）

std::vector<int> v{1, 2, 3, 4};
std::map<std::string, int> m{{"a", 1}, {"b", 2}};

struct Point { int x, y; };
Point p{1, 2};                       // 聚合初始化
Point* q = new Point{3, 4};
```

**`{}` 的三大好处**：

1. **禁止窄化转换（narrowing）**，编译期报错：
   ```cpp
   int  a{3.14};   // ❌ 编译错误：double → int 是窄化
   char c{300};    // ❌ 编译错误
   int  b(3.14);   // ⚠️ 通过，悄悄变成 3
   ```
2. **解决"最令人头疼的解析"（most vexing parse）**：
   ```cpp
   std::vector<int> v1();    // ⚠️ 这不是变量！这是声明了一个返回 vector<int> 的函数 v1
   std::vector<int> v2{};    // ✅ 空的 vector
   std::vector<int> v3(10);  // ✅ 10 个 0
   std::vector<int> v4{10};  // ⚠️ 1 个元素，值为 10（因为有 initializer_list 构造函数）
   ```
3. **成员默认初始值**（C++11 新增，强烈推荐）：
   ```cpp
   class Widget {
       int      id_   = 0;              // 类内初始值
       std::string name_{"unknown"};    // 用 {} 或 = 都行
       bool     ready_ = false;
   };
   ```

**`std::initializer_list<T>`** 让你自己的类型也支持 `{...}`：

```cpp
#include <initializer_list>
#include <algorithm>

class IntSet {
public:
    IntSet(std::initializer_list<int> init) {
        for (int v : init) data_.push_back(v);
        std::sort(data_.begin(), data_.end());
    }
private:
    std::vector<int> data_;
};

IntSet s{3, 1, 2};   // ✅
```

### 1.6 `using` 别名：比 `typedef` 更清爽

```cpp
// C++98
typedef void (*Callback)(int, void*);
typedef std::map<std::string, std::vector<int>> Table;

// C++11：可读性大幅提升，且支持模板别名
using Callback = void (*)(int, void*);
using Table    = std::map<std::string, std::vector<int>>;

// typedef 做不到的：别名模板
template <typename T>
using Vec = std::vector<T, MyAllocator<T>>;   // 固定分配器
Vec<int> a;      // == std::vector<int, MyAllocator<int>>

template <typename T>
using Ptr = T*;
Ptr<const int> p;  // == const int*
```

### 1.7 `enum class`：强类型枚举

C++98 的 `enum` 会**把名字泄漏到外层作用域**，且能隐式转 int：

```cpp
// 老式：污染作用域
enum Color { Red, Green, Blue };
enum Fruit { Apple, Green };   // ❌ 重定义冲突！

// C++11
enum class Color : uint8_t { Red, Green, Blue };   // 可指定底层类型
enum class Fruit { Apple, Banana };

Color c = Color::Red;
// int  n = c;                  // ❌ 不能隐式转换
int  n = static_cast<int>(c);   // ✅ 必须显式
```

> 想让 `enum class` 支持位运算（如 `Flags::A | Flags::B`），需要自己重载 `operator|`；C++11 没有自动支持。

### 1.8 其他零散但常用的小特性

| 特性 | 示例 | 说明 |
|---|---|---|
| 原始字符串 | `auto s = R"(C:\path\to\n)";` | 反斜杠不转义，写正则/路径神器 |
| 自定义分隔符 | `R"delim(有 )" 也不怕)delim"` | 处理含 `)"` 的文本 |
| `long long` | `long long n = 9e18;` | 至少 64 位，正式入标准 |
| `>>` 不再需要空格 | `vector<vector<int>> v;` | C++98 必须写 `> >` |
| `static_assert` | `static_assert(sizeof(int)==4, "need 32-bit int");` | **编译期断言** |
| `noexcept` | `void f() noexcept;` | 承诺不抛异常（见 2.6） |
| `thread_local` | `thread_local int tls;` | 线程局部存储 |
| `alignof/alignas` | `alignas(16) float buf[4];` | 对齐控制 |
| `char16_t/char32_t` | `char16_t c = u'中';` | Unicode 字符类型 |
| UTF-8 字面量 | `u8"中文"` | C++11 起（C++20 才是真正的 `char8_t`） |

## 第 2 章 右值引用与移动语义（本章最重要）

> 如果 C++11 只能学一件事，那就是这一章。
> 它直接决定了你写的类**快不快**，也决定了你能不能看懂 STL 源码和别人的代码。

### 2.1 左值 vs 右值：先分清这两个词

- **左值（lvalue）**：有名字、有地址、可以出现在 `=` 左边（非 const 时）。`a`、`*p`、`v[0]`、返回左值引用的函数调用。
- **右值（rvalue）**：临时的、即将消亡的、不能取地址的值。`42`、`a + b`、`std::string("hi")`、`f()`（返回非引用）、`std::move(x)` 的结果。

```cpp
int  a = 10;
int& lr = a;        // ✅ 左值引用绑左值
// int&  bad = 10;  // ❌ 非常量左值引用不能绑右值
const int& cr = 10; // ✅ const 左值引用可以绑右值（延长生命周期）
int&& rr = 10;      // ✅ 右值引用绑右值
// int&& bad2 = a;  // ❌ 右值引用不能绑左值
```

> 判断口诀：**能取地址的、能长期存在的 → 左值；临时的、表达式结果 → 右值**。

### 2.2 为什么需要移动：解决「无意义的深拷贝」

```cpp
std::vector<std::string> makeNames() {
    std::vector<std::string> v;
    v.push_back("Alice");
    v.push_back("Bob");
    return v;   // C++98：理论上要拷贝 2 个 string（实际被 RVO 优化掉）
}

std::vector<std::string> names = makeNames();   // 又一次拷贝？
```

对于持有堆资源的对象（string、vector、你自己写的 `Buffer`），**拷贝 = 重新分配内存 + 逐元素复制**，代价昂贵。
但很多时候，源对象马上就要销毁了（临时对象、返回值、`std::move` 后的对象）——**既然你都要死了，把资源直接"偷"过来不就行了？**

这就是移动语义：**把资源所有权从一个对象转移到另一个对象，源对象被"掏空"但保持可析构、可赋值的合法状态。**

### 2.3 `std::move`：它不移动任何东西

> ⚠️ 新手最大的误解：**`std::move` 只是个强制类型转换**（把左值转成右值引用，即 `static_cast<T&&>`），真正执行移动的是**移动构造函数 / 移动赋值运算符**。

```cpp
template <typename T>
typename std::remove_reference<T>::type&& move(T&& t) noexcept {
    return static_cast<typename std::remove_reference<T>::type&&>(t);
}
```

```cpp
std::string a = "hello";
std::string b = std::move(a);
// a 现在是"有效但未指定状态"（通常是空的，但标准不保证），不要再读它的值
std::cout << a.size();   // ⚠️ 合法但结果不可预期，别这么写
a = "world";             // ✅ 可以赋值，可以析构
```

**何时用 `std::move`**：当你确定「这个对象我不再需要了」，把它标记为可移动，从而触发移动构造/赋值。

### 2.4 写一个完整的、带移动语义的类

```cpp
#include <algorithm>
#include <cstddef>
#include <utility>   // std::move, std::swap

class Buffer {
public:
    explicit Buffer(std::size_t n)
        : data_(n ? new char[n] : nullptr), size_(n) {}

    ~Buffer() { delete[] data_; }                 // 1. 析构

    // 2. 拷贝构造：真·深拷贝
    Buffer(const Buffer& other)
        : data_(other.size_ ? new char[other.size_] : nullptr), size_(other.size_) {
        std::copy(other.data_, other.data_ + size_, data_);
    }

    // 3. 拷贝赋值：先"新后旧" → 强异常安全
    Buffer& operator=(const Buffer& other) {
        if (this != &other) {
            char* tmp = other.size_ ? new char[other.size_] : nullptr;  // 可能抛
            std::copy(other.data_, other.data_ + other.size_, tmp);
            delete[] data_;      // 到这里不会再抛
            data_  = tmp;
            size_  = other.size_;
        }
        return *this;
    }

    // 4. 移动构造：偷指针，noexcept！
    Buffer(Buffer&& other) noexcept
        : data_(other.data_), size_(other.size_) {
        other.data_ = nullptr;   // 关键：让源对象析构时不会 delete 我们刚偷的内存
        other.size_ = 0;
    }

    // 5. 移动赋值：先释放自己的，再偷
    Buffer& operator=(Buffer&& other) noexcept {
        if (this != &other) {
            delete[] data_;
            data_       = other.data_;
            size_       = other.size_;
            other.data_ = nullptr;
            other.size_ = 0;
        }
        return *this;
    }

    std::size_t size() const noexcept { return size_; }

private:
    char*       data_;
    std::size_t size_;
};
```

**三条铁律**：

1. **移动构造/移动赋值必须标 `noexcept`**（见 2.6），否则 `std::vector` 扩容时不敢用你的移动构造，会退化成拷贝！
2. **移动后，源对象必须处于"有效但未指定"状态**——至少能安全析构、能被赋值。通常做法是**把源指针置空**。
3. **一旦你写了析构函数/拷贝构造/拷贝赋值中的任意一个，编译器就不再自动生成移动操作**。这就是后面要讲的 Rule of Five。

### 2.5 Rule of Three / Five / Zero

| 规则 | 内容 |
|---|---|
| **Rule of Three**（C++98） | 如果你需要自定义 `析构 / 拷贝构造 / 拷贝赋值` 中的**任意一个**，通常需要三个都写（因为你在手动管理资源） |
| **Rule of Five**（C++11） | 上面的三个 + `移动构造` + `移动赋值`，共 5 个特殊成员函数 |
| **Rule of Zero**（现代推荐 ⭐） | **根本别手动管理资源**：用 `std::vector`、`std::string`、`std::unique_ptr` 等 RAII 成员拼装你的类，编译器自动生成的 5 个函数就都是对的，你一个都不用写 |

```cpp
// Rule of Zero 示例：一个字都不用手写资源管理
class Person {
public:
    Person(std::string name, std::vector<int> scores)
        : name_(std::move(name)), scores_(std::move(scores)) {}
    // 拷贝/移动/析构：编译器全搞定，而且都是最优的
private:
    std::string        name_;
    std::vector<int>   scores_;
};
```

> 💡 **现代 C++ 的第一原则**：优先 Rule of Zero。只有在你真的在封装裸资源（文件句柄、socket、内存池）时才写 Rule of Five。

### 2.6 `noexcept`：为什么移动构造必须标它

```cpp
class X {
public:
    X(X&&) noexcept;   // ✅
    X(X&&);            // ⚠️ 没标 → vector 扩容时改用拷贝构造
};
```

原因：`std::vector::push_back` 触发扩容时，需要把旧元素搬到新内存。
- 如果移动构造 `noexcept`：即使搬到一半出事也没关系（因为承诺不抛），可以放心**用移动**。
- 如果不承诺：搬到一半抛异常，容器就处于"一半搬了一半没搬"的损坏状态，无法回滚 —— 所以 `vector` 会保守地**用拷贝**（拷贝失败可以回滚）。

`noexcept` 的两张面孔：

```cpp
void f() noexcept;          // 承诺不抛；抛了就 std::terminate（不会传播，也不会析构栈）
void g() noexcept(true);    // 等价写法
bool b = noexcept(f());     // noexcept 运算符：编译期查询表达式是否不抛
```

> 析构函数**默认就是 `noexcept`** 的（C++11 起），不要在析构里抛异常。

### 2.7 完美转发与引用折叠（模板必学）

问题：写一个工厂函数，把参数原封不动（保留左值/右值、const 属性）传给构造函数。

```cpp
template <typename T, typename... Args>
std::unique_ptr<T> make_unique(Args&&... args) {   // 注：C++14 才有 std::make_unique
    return std::unique_ptr<T>(new T(std::forward<Args>(args)...));
}

auto p1 = make_unique<std::string>(5, 'x');   // 参数原样转发
std::string s = "hi";
auto p2 = make_unique<std::string>(s);        // 传左值 → 拷贝
auto p3 = make_unique<std::string>(std::move(s)); // 传右值 → 移动
```

两个关键机制：

**① 万能引用（Universal Reference / Forwarding Reference）**
`T&&` 出现在**模板参数推导**场景时（`template<class T> void f(T&&)`），它不是纯右值引用，而是万能引用：
- 传入左值 `int` → `T` 被推导为 `int&` → `T&&` = `int& &&` → 折叠为 `int&`
- 传入右值 `int` → `T` 被推导为 `int` → `T&&` = `int&&`

**② 引用折叠规则**（只在模板/typedef 场景发生）：

| 组合 | 结果 |
|---|---|
| `& &` | `&` |
| `& &&` | `&` |
| `&& &` | `&` |
| `&& &&` | `&&` |

**③ `std::forward<T>`**：**有条件**的 `static_cast<T&&>`。当 `T` 是 `int&` 时什么都不做（保持左值），当 `T` 是 `int` 时转成 `int&&`（变成右值）。这就是"完美"的含义。

```cpp
template <typename T>
void wrapper(T&& arg) {
    // ❌ 错：arg 是具名变量，本身永远是左值！直接传会丢掉右值性
    // target(arg);
    // ✅ 对：
    target(std::forward<T>(arg));
}
```

> 记忆：`std::move(x)` = **无条件**转右值；`std::forward<T>(x)` = **按 T 的原始属性**转发。

### 2.8 不要对返回值滥用 `std::move`

```cpp
std::vector<int> build() {
    std::vector<int> v;
    // ...
    return v;                 // ✅ 好：编译器会做 NRVO（具名返回值优化），一次构造都不用
    // return std::move(v);   // ❌ 坏：反而阻止了 NRVO，强制调用移动构造
}

std::string getName() const {
    return name_;             // ✅ 成员也一样，直接返回，别 std::move
}
```

**例外**：返回的是函数参数、或与返回类型不同的对象时，编译器不一定能自动移动，这时可以显式 `std::move`。但默认写法永远是**直接返回**。

### 2.9 移动语义在 STL 中的落地

```cpp
std::vector<std::string> v;
v.push_back(std::string(10000, 'x'));   // 临时对象 → 调用移动构造
v.emplace_back(10000, 'x');             // ✅ 更好：直接在容器内存里构造，连移动都省了

std::string a = "hello";
v.push_back(std::move(a));              // 明确放弃 a → 移动

// 算法层面：std::move（<algorithm>）把整个区间的元素"搬"过去
std::vector<std::string> dst;
std::move(src.begin(), src.end(), std::back_inserter(dst));  // 注意是 algorithm 的 std::move
std::vector<std::string> dst2(std::make_move_iterator(src.begin()),
                              std::make_move_iterator(src.end()));
```

> ⚠️ 名字撞车：`std::move(x)`（`<utility>`，转型）和 `std::move(first, last, d_first)`（`<algorithm>`，区间搬运算法）是完全不同的两个东西。

## 第 3 章 智能指针与 RAII

> **核心原则**：现代 C++ 里，**裸 `new`/`delete` 应该几乎绝迹**。所有权交给智能指针，生命周期交给作用域。

### 3.1 RAII 复习

RAII（Resource Acquisition Is Initialization）：**资源的获取 = 对象的构造，资源的释放 = 对象的析构**。
只要对象在栈上，无论函数正常返回还是抛异常，析构都保证被调用 → 资源不泄漏。

```cpp
// 手写 RAII 文件句柄（比智能指针更通用的模式）
class File {
public:
    explicit File(const char* path) : fp_(std::fopen(path, "r")) {
        if (!fp_) throw std::runtime_error("open failed");
    }
    ~File() { if (fp_) std::fclose(fp_); }

    File(const File&)            = delete;   // 禁止拷贝（见第 5 章）
    File& operator=(const File&) = delete;

    File(File&& other) noexcept : fp_(other.fp_) { other.fp_ = nullptr; }
    File& operator=(File&& other) noexcept {
        if (this != &other) {
            if (fp_) std::fclose(fp_);
            fp_ = other.fp_;
            other.fp_ = nullptr;
        }
        return *this;
    }
    std::FILE* get() const noexcept { return fp_; }
private:
    std::FILE* fp_;
};
```

### 3.2 `std::unique_ptr`：独占所有权（首选，90% 场景用它）

```cpp
#include <memory>

std::unique_ptr<Foo> p1(new Foo(1, 2));   // OK
auto p2 = std::make_unique<Foo>(1, 2);    // ✅ 更好（C++14，强烈推荐；C++11 可自己写 make_unique）

// 独占：不可拷贝
// auto p3 = p1;              // ❌ 编译错误
auto p3 = std::move(p1);      // ✅ 所有权转移，p1 变成 nullptr

p3->doSomething();
Foo& ref = *p3;
Foo* raw = p3.get();          // 只是"借用"，不拥有，绝不能 delete

p3.reset();                   // 释放资源，p3 = nullptr
p3.reset(new Foo());          // 释放旧的，拥有新的
Foo* leaked = p3.release();   // 放弃所有权并返回裸指针（你得自己管，慎用）
```

**关键能力**：

```cpp
// 1. 数组特化
std::unique_ptr<int[]> arr(new int[10]);
arr[0] = 1;                            // 有 operator[]，无 operator*

// 2. 自定义删除器（FILE*、malloc、SDL 资源…）
auto fileDeleter = [](std::FILE* f) { if (f) std::fclose(f); };
using FilePtr = std::unique_ptr<std::FILE, decltype(fileDeleter)>;
FilePtr fp(std::fopen("a.txt", "r"), fileDeleter);

// 3. 作为容器元素（vector<unique_ptr<T>> 完全合法，因为它可移动）
std::vector<std::unique_ptr<Shape>> shapes;
shapes.push_back(std::make_unique<Circle>(1.0));
shapes.emplace_back(new Square(2.0));   // 也可以（但 make_unique 更安全）

// 4. 多态工厂返回值（天然表达"所有权转移"）
std::unique_ptr<Shape> createShape(Kind k) {
    switch (k) {
        case Kind::Circle: return std::make_unique<Circle>(1.0);
        case Kind::Square: return std::make_unique<Square>(2.0);
    }
    return nullptr;
}
```

**函数参数该怎么写？**

| 意图 | 写法 |
|---|---|
| 只是用一下，不接管所有权 | `void f(Foo* p)` 或 `void f(Foo& r)` |
| 要接管所有权（转移） | `void f(std::unique_ptr<Foo> p)`（调用方写 `f(std::move(ptr))`） |
| 函数内部重新绑定到别的对象 | `void f(std::unique_ptr<Foo>& p)` |
| 返回值表达"交给你了" | `std::unique_ptr<Foo> make()` |

> ⚠️ `unique_ptr` 作**值传递**时必须 `std::move`。如果函数只接受 `unique_ptr` 但内部不保存，说明设计错了，应该传 `Foo&`。

**C++11 没有 `std::make_unique`？自己补 8 行**：

```cpp
template <typename T, typename... Args>
std::unique_ptr<T> make_unique(Args&&... args) {
    return std::unique_ptr<T>(new T(std::forward<Args>(args)...));
}
```

### 3.3 `std::shared_ptr`：共享所有权（有代价，别滥用）

```cpp
auto sp1 = std::make_shared<Foo>(1, 2);   // ✅ 永远用 make_shared，不用 new
std::shared_ptr<Foo> sp2 = sp1;           // 引用计数 +1 = 2
std::cout << sp1.use_count();             // 2

sp1.reset();                              // 计数 -1，sp2 仍持有
// sp2 析构 → 计数归零 → 对象销毁
```

**为什么一定要 `make_shared`**：

```cpp
std::shared_ptr<Foo> a(new Foo());   // ❌ 两次内存分配（对象 + 控制块），且异常不安全
auto b = std::make_shared<Foo>();    // ✅ 一次分配，异常安全，更快更小
```

> `std::shared_ptr<Foo> f(std::shared_ptr<Foo>(new Foo), g());` 这种写法在参数求值顺序不确定时可能泄漏 —— `make_shared` 彻底规避。

**自定义删除器**（写法与 `unique_ptr` 不同，删除器不是类型的一部分）：

```cpp
std::shared_ptr<std::FILE> fp(std::fopen("a.txt", "r"),
                              [](std::FILE* f) { if (f) std::fclose(f); });
```

### 3.4 `weak_ptr`：打破循环引用

```cpp
struct Node {
    std::shared_ptr<Node> parent;   // ❌ 父子互相 shared_ptr → 谁也析构不了 → 内存泄漏
    std::shared_ptr<Node> child;
};
```

正确做法：**"从属"方向用 `weak_ptr`**。

```cpp
struct Node {
    std::weak_ptr<Node>   parent;   // ✅ 弱引用，不增加引用计数
    std::shared_ptr<Node> child;
};

std::shared_ptr<Node> parent = std::make_shared<Node>();
std::shared_ptr<Node> child  = std::make_shared<Node>();
parent->child  = child;
child->parent  = parent;      // 弱引用

// 使用 weak_ptr 前必须"提升"为 shared_ptr（因为对象可能已经死了）
if (auto p = child->parent.lock()) {   // lock() 返回 shared_ptr，失败则为空
    p->doSomething();
} else {
    // parent 已销毁
}
// 也可以用 expired() 检查，但 lock() 才是正确用法（避免检查与使用之间的竞态）
```

其他用途：**缓存**、**观察者列表**、**打破双向关联**。

### 3.5 `enable_shared_from_this`：在成员函数中拿到指向自己的 `shared_ptr`

```cpp
class Session : public std::enable_shared_from_this<Session> {
public:
    void start() {
        // 想把自己传给异步回调，让回调期间对象活着
        auto self = shared_from_this();     // 得到 shared_ptr<Session>
        doAsync([self] { self->onDone(); });
    }
private:
    void onDone();
};

auto s = std::make_shared<Session>();
s->start();     // ✅
// Session s2; s2.start();  // ❌ 崩溃：对象不由 shared_ptr 管理，shared_from_this 抛 bad_weak_ptr
```

> ⚠️ **绝对不能在构造函数里调用 `shared_from_this()`** —— 此时对象还没被 `shared_ptr` 接管。

### 3.6 选型决策表

| 场景 | 选择 |
|---|---|
| 独占资源、明确单一所有者 | `unique_ptr` ⭐ |
| 需要共享、生命周期难以静态确定 | `shared_ptr` |
| 存在循环引用 / 需要"观察"但不拥有 | `weak_ptr` |
| 不拥有，只是借用 | **裸指针 `T*` 或引用 `T&`** |
| 局部对象 | 直接栈上对象，不用指针 |

> **一句话**：默认 `unique_ptr`，共享才 `shared_ptr`，不拥有就用 `T&`/`T*`。不要因为"怕出错"就把所有东西都塞进 `shared_ptr` —— 那会让所有权关系变得无法分析。

## 第 4 章 Lambda 与可调用对象

### 4.1 Lambda 基本语法

```cpp
[capture](parameters) mutable noexcept -> return_type { body }
         ^^^^^^^^^^^  ^^^^^^^^^^^^^^^ ^^^^^^^^^^^^^^^^^^^^^^^^
         捕获列表      可选（全部可省）  尾置返回类型（通常可省，编译器推导）
```

最常见形态：

```cpp
auto add = [](int a, int b) { return a + b; };   // 返回类型自动推导为 int
std::cout << add(1, 2);   // 3
```

### 4.2 捕获列表（`[]` 里能写什么）

| 写法 | 含义 |
|---|---|
| `[]` | 不捕获任何东西 |
| `[x]` | 按**值**捕获 `x`（默认拷贝，且在 C++11 中是 const 的） |
| `[&x]` | 按**引用**捕获 `x` |
| `[=]` | 按值捕获**所有**被用到的自动变量 |
| `[&]` | 按引用捕获**所有**被用到的自动变量 |
| `[=, &y]` | 默认按值，但 `y` 按引用 |
| `[&, x]` | 默认按引用，但 `x` 按值 |
| `[this]` | 捕获当前对象的 `this` 指针（访问成员） |
| `[=]` 或 `[&]` 在成员函数内 | 隐式捕获 `this` ⚠️ |

```cpp
int factor = 10;
auto mul = [factor](int x) { return x * factor; };   // 值捕获

int sum = 0;
std::for_each(v.begin(), v.end(), [&sum](int x) { sum += x; });  // 引用捕获，累加

// C++11 中，值捕获的变量默认是 const，想修改要加 mutable
int counter = 0;
auto tick = [counter]() mutable { return ++counter; };  // 改的是副本
tick(); tick();
std::cout << counter;   // 仍然是 0！

// 想改外部变量必须引用捕获
auto tick2 = [&counter]() { return ++counter; };
tick2();
std::cout << counter;   // 1
```

> 💡 C++14 引入了 **init-capture**：`[x = std::move(p)] { ... }`，可以在捕获时移动构造。C++11 只能值拷贝/引用。

### 4.3 Lambda 与 STL 算法（最爽的用法）

```cpp
std::vector<int> v{5, 2, 8, 1};

std::sort(v.begin(), v.end(), [](int a, int b) { return a > b; });        // 降序
auto it = std::find_if(v.begin(), v.end(), [](int x) { return x % 2 == 0; });
int  n  = std::count_if(v.begin(), v.end(), [](int x) { return x > 3; });
std::for_each(v.begin(), v.end(), [](int x) { std::cout << x << ' '; });

// 按自定义规则排序对象
std::sort(users.begin(), users.end(),
          [](const User& a, const User& b) { return a.name < b.name; });
```

对比 C++98 写 `operator()` 的仿函数类或 `std::bind1st` —— lambda 让**"就地定义行为"**成为可能，代码可读性提升一个量级。

### 4.4 `std::function`：统一的可调用对象容器

`std::function<R(Args...)>` 可以装下任何**签名匹配**的可调用物：普通函数、函数对象、lambda、`bind` 结果、成员函数指针（配合 `bind`）。

```cpp
#include <functional>

std::function<int(int, int)> op;

op = [](int a, int b) { return a + b; };      // lambda
op = std::multiplies<int>();                  // 函数对象
op = &myFunc;                                 // 普通函数
int r = op(3, 4);

// 典型：回调注册
class Button {
public:
    using OnClick = std::function<void(int x, int y)>;
    void setOnClick(OnClick cb) { onClick_ = std::move(cb); }
private:
    OnClick onClick_;
};

Button btn;
btn.setOnClick([](int x, int y) { std::cout << "clicked at " << x << ',' << y; });
```

**代价要知道**：`std::function` 做了**类型擦除**，有动态分配 + 一次间接调用的开销，且**不可内联**。
- 如果只是**当场用一次**（比如传给 `std::sort`）→ 用 **`template` 参数**或 `auto`（C++14），不要塞进 `std::function`。
- 如果需要**存储回调**（成员变量、容器里放一堆回调）→ 用 `std::function`。

### 4.5 `std::bind`：参数绑定（C++11 有，但 lambda 往往更好）

```cpp
#include <functional>
using namespace std::placeholders;   // _1, _2, _3...

void log(int level, const std::string& msg);
auto errLog = std::bind(log, 3, _1);         // 固定第一个参数为 3
errLog("something wrong");                   // == log(3, "something wrong")

// 成员函数绑定（第二参数是对象）
struct Foo { void bar(int); };
Foo f;
auto cb = std::bind(&Foo::bar, &f, _1);
cb(42);                                       // == f.bar(42)
// 注意：用 &f 时要保证 f 的生命周期长于 cb！否则用 shared_ptr 或值拷贝对象
auto cb2 = std::bind(&Foo::bar, f, _1);       // 拷贝 f（需要 Foo 可拷贝）

// 参数重排
auto f3 = std::bind(divide, _2, _1);          // f3(a, b) == divide(b, a)
```

> **建议**：C++11 里 `bind` 只在**必须**时（成员函数调用、参数重排）使用；普通场景优先 lambda，可读性更好、更容易内联。
> 传引用参数给 `bind` 时要用 `std::ref(x)` / `std::cref(x)`，否则会被拷贝（因为 `bind` 默认 decay-copy）。

```cpp
void inc(int& n) { ++n; }
int x = 0;
// auto bad  = std::bind(inc, x);      // ❌ 拷贝了一份，改不到 x
auto good = std::bind(inc, std::ref(x)); // ✅
```

## 第 5 章 OOP 的现代化改写

### 5.1 `override` 与 `final`

```cpp
class Base {
public:
    virtual void draw(int) const;
    virtual ~Base() = default;      // ✅ 基类必须有虚析构
};

class Derived : public Base {
public:
    void draw(int) const override;   // ✅ 明确"我是重写"，写错签名就编译报错
    // void draw(float) const override;  // ❌ 编译错误：基类没有这个虚函数
};
```

`override` 解决的经典 bug：以为重写了虚函数，实际因为签名不一致（少了 `const`、参数类型不同）**新建了一个函数**，多态静默失效。加上 `override`，编译器替你兜底。

```cpp
class FinalThing final { /* 不能被继承 */ };

class Base2 {
public:
    virtual void f() final;   // 子类不能再重写 f
};
```

> `final` 还能帮助编译器**去虚拟化**（devirtualization）优化。

### 5.2 `= default` 与 `= delete`

```cpp
class NonCopyable {
public:
    NonCopyable()                       = default;   // ✅ 显式要求编译器生成默认版本
    ~NonCopyable()                      = default;
    NonCopyable(const NonCopyable&)     = delete;    // ❌ 禁止拷贝构造
    NonCopyable& operator=(const NonCopyable&) = delete;

    // 允许移动
    NonCopyable(NonCopyable&&)            = default;
    NonCopyable& operator=(NonCopyable&&) = default;
};
```

用途清单：

| 写法 | 用途 |
|---|---|
| `X() = default;` | 恢复被抑制的默认构造（比如你自己写了带参构造后） |
| `X(const X&) = delete;` | 禁用拷贝（C++11 里实现不可拷贝类的标准做法） |
| `~X() = default;` | 明确虚析构，且不抑制移动操作 |
| `void f(int) = delete;`<br>`void f(double) = delete;` | 禁用某些重载/隐式转换（比 private 不定义更好，报错更早更清楚） |

```cpp
// 经典：禁止不想要的隐式转换
void process(long);
void process(char) = delete;   // 传 char 直接编译错
// process('a');  // ❌
```

> ⚠️ **重要副作用**：手动声明析构函数（哪怕写 `~X() = default;`）**不会**抑制移动操作的生成，但手动声明拷贝构造**会**抑制移动操作生成。
> 所以：要移动语义时，要么全交给编译器（Rule of Zero），要么 5 个都显式写出来。

### 5.3 委托构造函数（Delegating Constructor）

```cpp
class Connection {
public:
    Connection() : Connection("localhost", 8080) {}     // 委托给下面的构造
    Connection(std::string host) : Connection(std::move(host), 8080) {}
    Connection(std::string host, int port)
        : host_(std::move(host)), port_(port) { connect(); }
private:
    std::string host_;
    int         port_;
    void connect();
};
```

消灭了 C++98 里"公共 `init()` 私有函数"的丑陋写法。

### 5.4 继承构造函数（Inheriting Constructor）

```cpp
class Base {
public:
    Base(int);
    Base(int, double);
    Base(const std::string&);
};

class Derived : public Base {
public:
    using Base::Base;     // ✅ 把 Base 的所有构造函数"继承"下来
};

Derived d1(1);
Derived d2(1, 2.0);
Derived d3("hi");
```

> 注意：继承来的构造函数**不会**初始化 `Derived` 自己的新成员（它们用类内初始值或默认初始化）。默认构造、拷贝构造、移动构造不继承。

### 5.5 `explicit` 现在能用于转换运算符

```cpp
class SafeBool {
public:
    explicit operator bool() const { return ok_; }   // C++11 起 explicit 可用于转换函数
private:
    bool ok_ = false;
};

SafeBool b;
if (b) { /* ✅ 语境转换允许 */ }
// int n = b;      // ❌ 禁止隐式转换
```

### 5.6 移动语义与多态的结合

- **基类析构必须是 `virtual`**（老规矩不变）。
- 如果类有虚函数（多态基类），**通常应该把拷贝构造声明为 `= delete` 或 `protected`**，避免"对象切片"（object slicing）。
- 移动构造**不能**是虚的；多态对象的移动通过 `clone()` 或 `unique_ptr<Base>` 转移完成。

```cpp
class Shape {
public:
    virtual ~Shape() = default;
    virtual double area() const = 0;
    virtual std::unique_ptr<Shape> clone() const = 0;   // 虚拷贝惯用法

    Shape() = default;
    Shape(const Shape&) = delete;             // 防切片
    Shape& operator=(const Shape&) = delete;
};

class Circle : public Shape {
public:
    explicit Circle(double r) : r_(r) {}
    double area() const override { return 3.14159 * r_ * r_; }
    std::unique_ptr<Shape> clone() const override { return std::make_unique<Circle>(*this); }
private:
    double r_;
};
```

### 5.7 `constexpr`：编译期计算

```cpp
constexpr int square(int x) { return x * x; }   // 编译期可求值
constexpr int n = square(5);                    // ✅ 编译期常量，n = 25
int arr[n];                                     // ✅ 可作数组长度

int x = 5;
// constexpr int m = square(x);   // ❌ x 不是常量表达式
int m = square(x);                // ✅ 运行时也能用，constexpr 函数同时是普通函数
```

C++11 的限制（C++14 大幅放宽，记住这条就能看懂老代码）：
- **函数体只能有一条 `return` 语句**（不能有循环、局部变量、if）。
- 递归是允许的：

```cpp
constexpr unsigned factorial(unsigned n) {
    return n <= 1 ? 1 : n * factorial(n - 1);   // ✅ 三元表达式算一条 return
}
static_assert(factorial(5) == 120, "compile-time check");
```

> `constexpr` 变量隐式为 `const`，且必须用常量表达式初始化。
> 与 `const` 的区别：`const` 只表示"运行时不可改"，`constexpr` 表示"**编译期就已知**"。

## 第 6 章 模板进阶：变参、完美转发、类型萃取

> 这一章是"能读懂 STL / 库源码"的分水岭。写业务代码时用得不多，但**读**得懂非常重要。

### 6.1 变长模板（Variadic Templates）

```cpp
// 基础：递归展开参数包
void printAll() {}    // 递归终止（0 参数版本）

template <typename T, typename... Rest>
void printAll(const T& first, const Rest&... rest) {
    std::cout << first << ' ';
    printAll(rest...);        // 递归展开
}

printAll(1, 2.5, "hello", 'c');   // 输出：1 2.5 hello c
```

`typename... Args` 是**模板参数包**，`Args... args` 是**函数参数包**，`args...` 是**包展开**。

更常见的写法是用**初始化列表**一次性展开（避免递归，且保证求值顺序）：

```cpp
template <typename... Args>
void print(Args&&... args) {
    using expander = int[];
    (void)expander{0, (std::cout << std::forward<Args>(args) << ' ', 0)...};
}
```

> C++17 有折叠表达式 `(std::cout << ... << args)`；C++11 只能用上面这些技巧。

**`sizeof...`** 获取参数个数：

```cpp
template <typename... Args>
constexpr std::size_t count(Args... args) { return sizeof...(Args); }
```

### 6.2 完美转发实战：实现一个 `emplace` 风格的函数

```cpp
template <typename T>
class Holder {
public:
    template <typename... Args>
    void emplaceConstruct(Args&&... args) {
        ptr_.reset(new T(std::forward<Args>(args)...));   // 参数原样交给 T 的构造函数
    }
    T* get() const { return ptr_.get(); }
private:
    std::unique_ptr<T> ptr_;
};

Holder<std::string> h;
h.emplaceConstruct(3, 'x');     // 构造 "xxx"，全程零拷贝
```

```cpp
std::is_base_of<Base, Derived>::value       // true

// C++14 起有 _t / _v 简写：std::remove_const_t<const int>、std::is_same_v<...>
```


### 6.4 SFINAE 入门：用类型条件约束模板

SFINAE = Substitution Failure Is Not An Error（替换失败不是错误）。配合 `enable_if` 可以"按类型选择重载"：

```cpp
#include <type_traits>
#include <iostream>

// 版本 1：只对整数类型启用
template <typename T>
typename std::enable_if<std::is_integral<T>::value, void>::type
printType(T) { std::cout << "integral\n"; }

// 版本 2：只对浮点类型启用
template <typename T>
typename std::enable_if<std::is_floating_point<T>::value, void>::type
printType(T) { std::cout << "floating\n"; }

printType(42);     // integral
printType(3.14);   // floating
// printType("hi"); // ❌ 无匹配（这是好事，错误信息更清晰）
```

> C++20 的 Concepts 就是这玩意的漂亮替代品（`requires std::integral<T>`）。C++11 只能这么写。

### 6.5 模板的两阶段查找与 `typename` / `template` 关键字

```cpp
template <typename T>
void f() {
    T::iterator it;                 // ❌ 编译错误：编译器不知道 T::iterator 是类型还是静态成员
    typename T::iterator it2;       // ✅ 必须加 typename

    T obj;
    obj.template get<int>();        // 依赖名的成员模板调用要加 template
}
```

记不住就一条：**凡是用 `::` 从模板参数里取东西当类型用，前面加 `typename`**。

## 第 7 章 STL 新容器与新算法

### 7.1 新增容器一览

| 容器 | 头文件 | 何时用 |
|---|---|---|
| `std::array<T, N>` | `<array>` | **固定大小数组**，替代 C 数组。零开销，知道自己的大小，支持迭代器 |
| `std::forward_list<T>` | `<forward_list>` | 单向链表，比 `list` 省内存；只能前向，插入用 `insert_after` |
| `std::unordered_map<K,V>` | `<unordered_map>` | 哈希表，平均 O(1) 查找，**无序** |
| `std::unordered_set<T>` | `<unordered_set>` | 哈希集合 |
| `std::unordered_multimap/set` | 同上 | 允许重复 key |
| `std::tuple<T...>` | `<tuple>` | 异构定长组，函数多返回值的轻量方案 |

### 7.2 `std::array`

```cpp
#include <array>
std::array<int, 5> a = {1, 2, 3, 4, 5};

a[0] = 10;
a.at(1) = 20;          // 带边界检查（抛 out_of_range）

std::sort(a.begin(), a.end());
std::get<0>(a);        // 编译期索引访问

// 传参不会退化成指针
void f(const std::array<int, 5>& arr);   // ✅ 大小信息保留

// ⚠️ 注意：array 在栈上，元素多时会爆栈；大数组用 vector
```

### 7.3 `std::unordered_map`

```cpp
#include <unordered_map>
std::unordered_map<std::string, int> wordCount;
wordCount["hello"]++;                      // 平均 O(1)
wordCount.emplace("world", 1);             // ✅ 避免临时对象

// 查找（不要用 [] 查找，[] 会插入默认值！）
auto it = wordCount.find("hello");
if (it != wordCount.end()) { /* it->second */ }

// 遍历（顺序不确定！）
for (const auto& kv : wordCount) {
    std::cout << kv.first << ": " << kv.second << '\n';
}
// C++17 起可写 for (const auto& [k, v] : wordCount)

// 性能调优
wordCount.reserve(10000);                  // 预分配桶，避免 rehash
std::cout << wordCount.bucket_count() << " " << wordCount.load_factor();
```

**自定义 key 需要提供 hash**：

```cpp
struct Point { int x, y; };
struct PointHash {
    std::size_t operator()(const Point& p) const {
        return std::hash<int>()(p.x) ^ (std::hash<int>()(p.y) << 1);
    }
};
struct PointEq {
    bool operator()(const Point& a, const Point& b) const {
        return a.x == b.x && a.y == b.y;
    }
};
std::unordered_map<Point, std::string, PointHash, PointEq> m;
```

**选型：`map`（红黑树）还是 `unordered_map`（哈希）？**

| 维度 | `map` | `unordered_map` |
|---|---|---|
| 复杂度 | 稳定 O(log n) | 平均 O(1)，最坏 O(n) |
| 顺序 | **有序**，可范围查询 | 无序 |
| 内存 | 较低 | 较高（桶数组） |
| 要求 | key 需要 `<` | key 需要 `hash` + `==` |
| 迭代器稳定性 | 好 | rehash 时全部失效 |

> 默认选 `std::map`（更可预测）；**确认"不需要顺序 + 数据量大 + 只做点查"**时才换 `unordered_map`。

### 7.4 `std::tuple`

```cpp
#include <tuple>

std::tuple<int, std::string, double> t{1, "hi", 3.14};
```

### 7.5 `emplace` 系列：就地构造

```cpp
struct Person { Person(std::string n, int a); };

std::vector<Person> v;
v.push_back(Person("Ann", 20));     // 构造临时对象 → 移动进容器
v.emplace_back("Ann", 20);          // ✅ 直接在容器内存里构造，省一次移动

std::map<std::string, int> m;
m.insert(std::make_pair("a", 1));   // 老写法
m.emplace("a", 1);                  // ✅
m.insert({"a", 1});                 // ✅ 也可以
```

> ⚠️ `emplace_back` 不总是更快。如果参数已是一个完整对象，`push_back(obj)` 与 `emplace_back(obj)` 等价。
> ⚠️ `emplace` 系列会绕过 `explicit` 的部分保护吗？不会 —— 它调用的仍是构造函数，`explicit` 依然生效（但 `emplace_back("x")` 可能意外调用 `explicit` 构造，而 `push_back("x")` 会报错，这是少数 `emplace` 反而危险的场景）。

## 第 8 章 并发编程基础

> 在 C++11 之前，C++ 标准里**没有线程**。多线程只能靠 pthread / WinAPI / Boost。
> C++11 带来了 `std::thread`、`std::mutex`、`std::atomic`、`std::future` —— 终于可以写可移植的多线程。

### 8.1 `std::thread`

```cpp
#include <thread>

void worker(int id) { /* ... */ }

std::thread t1(worker, 42);          // 立刻开始执行
std::thread t2([] { /* 做点事 */ });

// ⚠️ 必须 join 或 detach，否则 thread 析构时调用 std::terminate()！
t1.join();                           // 等待结束
t2.detach();                         // 分离（之后无法控制，慎用）

std::cout << std::thread::hardware_concurrency();   // 硬件并发数（可能是 0）
```

**RAII 包装线程（强烈推荐）**：

```cpp
class ThreadGuard {
public:
    template <typename... Args>
    explicit ThreadGuard(Args&&... args) : t_(std::forward<Args>(args)...) {}
    ~ThreadGuard() { if (t_.joinable()) t_.join(); }   // 析构自动 join，异常安全
    ThreadGuard(const ThreadGuard&) = delete;
    ThreadGuard& operator=(const ThreadGuard&) = delete;
private:
    std::thread t_;
};
```

### 8.2 互斥量与锁

```cpp
#include <mutex>

std::mutex mtx;
int shared = 0;

void safe_inc() {
    std::lock_guard<std::mutex> lock(mtx);   // ✅ 构造加锁，析构解锁（RAII）
    ++shared;
}   // 自动解锁，哪怕中途抛异常

// 需要手动解锁/条件变量时用 unique_lock（更重，但灵活）
void flexible() {
    std::unique_lock<std::mutex> lock(mtx);
    // ...
    lock.unlock();
    // 不持有锁的部分
    lock.lock();
}
```

> 💡 **永远用 `lock_guard` / `unique_lock`，不要手写 `mtx.lock()` / `mtx.unlock()`**（异常或早退会导致死锁）。
> C++17 有 `std::scoped_lock` 可同时锁多个互斥量，C++11 用 `std::lock(m1, m2)` + `std::lock_guard(m1, std::adopt_lock)`。

**避免死锁**：所有线程**按固定顺序**加锁，或用 `std::lock` 一次性锁多个。

```cpp
std::mutex m1, m2;
void f() {
    std::lock(m1, m2);                                   // 原子地锁住两个，不会死锁
    std::lock_guard<std::mutex> l1(m1, std::adopt_lock);  // adopt：已锁，只接管解锁责任
    std::lock_guard<std::mutex> l2(m2, std::adopt_lock);
    // ...
}
```

### 8.3 条件变量

```cpp
#include <condition_variable>

std::mutex              mtx;
std::condition_variable cv;
std::queue<int>         jobs;
bool                    done = false;

void consumer() {
    for (;;) {
        std::unique_lock<std::mutex> lock(mtx);
        cv.wait(lock, [] { return !jobs.empty() || done; });   // ✅ 必须用谓词版本（防虚假唤醒）
        if (jobs.empty() && done) return;
        int job = jobs.front(); jobs.pop();
        lock.unlock();
        process(job);       // 在锁外做耗时工作
    }
}

void producer() {
    for (int i = 0; i < 10; ++i) {
        {
            std::lock_guard<std::mutex> lock(mtx);
            jobs.push(i);
        }
        cv.notify_one();    // 通知一个等待者（notify_all 通知全部）
    }
    {
        std::lock_guard<std::mutex> lock(mtx);
        done = true;
    }
    cv.notify_all();
}
```

**三条铁律**：
1. `wait` **必须**配合 `unique_lock`（不能是 `lock_guard`）。
2. `wait` **必须**用带谓词的重载，因为存在**虚假唤醒**（spurious wakeup）。
3. 修改共享状态要在**持有锁时**做；`notify` 之后是否立即释放锁是性能优化问题，不影响正确性。

### 8.4 `std::atomic`：无锁的轻量同步

```cpp
#include <atomic>

std::atomic<int>  counter{0};
std::atomic<bool> ready{false};

counter++;                       // 原子自增
counter.fetch_add(1);            // 显式
counter.load();                  // 读
counter.store(5);                // 写
int old = counter.exchange(0);   // 交换

// CAS（Compare-And-Swap）：无锁算法的核心
int expected = counter.load();
while (!counter.compare_exchange_weak(expected, expected + 1)) {
    // expected 被更新为当前值，重试
}

// 最常用场景：停止标志
std::atomic<bool> stop{false};
void worker() { while (!stop.load(std::memory_order_relaxed)) { /* ... */ } }
stop.store(true);
```

> ⚠️ `std::atomic` 不可拷贝（拷贝构造被 delete）。
> ⚠️ 内存序（`memory_order_*`）默认是最强的 `seq_cst`（顺序一致），**新手就用默认值**，`memory_order_relaxed` 等只有在明确知道自己在做什么时才用。
> 💡 `atomic` 适合**单个变量**（计数器、标志位）；保护**一组数据的不变式**还是要用 mutex。

### 8.5 `std::async` / `future` / `promise` / `packaged_task`

```cpp
#include <future>

// 1. 最简单的异步：async
auto fut = std::async(std::launch::async, [] {
    std::this_thread::sleep_for(std::chrono::seconds(1));
    return 42;
});
// 期间做别的事...
int result = fut.get();     // 阻塞等待结果（只能调用一次）

// 2. promise：在一个线程里"承诺"结果，另一个线程取
std::promise<int> p;
std::future<int>  f = p.get_future();
std::thread([&p] {
    try {
        p.set_value(compute());
    } catch (...) {
        p.set_exception(std::current_exception());   // 异常可以跨线程传递
    }
}).detach();
int v = f.get();   // 可能抛出 compute() 里的异常

// 3. packaged_task：把"任务"和"取结果的 future"打包
std::packaged_task<int(int, int)> task([](int a, int b) { return a + b; });
std::future<int> f2 = task.get_future();
std::thread t(std::move(task), 2, 3);   // packaged_task 只能移动
t.join();
std::cout << f2.get();   // 5
```

`std::async` 的启动策略：

| 策略 | 行为 |
|---|---|
| `std::launch::async` | **必须**在新线程里跑 |
| `std::launch::deferred` | 延迟到 `get()`/`wait()` 时才在**调用者线程**同步执行 |
| 默认（不写，即 `async|deferred`） | 由实现决定 ⚠️  unpredictable，**显式指定** |

> ⚠️ `std::future` 的析构：由 `std::async` 产生的 future 若被丢弃，析构会**阻塞等待**任务完成（这是标准的一个特殊规定，容易踩坑）。

## 第 10 章 20 个高频陷阱清单

| # | 陷阱 | 正确做法 |
|---|---|---|
| 1 | 以为 `std::move(x)` 会移动 | 它只是转型；移动由移动构造/赋值完成。调用后 x 仍存在，只是状态不确定 |
| 2 | `return std::move(localVar);` | 直接 `return localVar;`（否则阻止 NRVO） |
| 3 | 移动构造忘了 `noexcept` | 加上。否则 `vector` 扩容时不敢用移动，性能退化成拷贝 |
| 4 | 写了析构/拷贝却指望编译器生成移动 | 编译器不会生成。要遵循 Rule of Five，或改用 Rule of Zero |
| 5 | `const` 返回值 | `const T f()` 会阻止移动，也阻止 NRVO。返回值不要加顶层 const |
| 6 | 移动后又去读源对象 | 源对象处于"有效但未指定"状态，只能析构或赋值 |
| 7 | `unique_ptr` 当值传参忘了 `move` | `f(std::move(p))`；不转移所有权就传 `T&`/`T*` |
| 8 | 两个 `shared_ptr` 互相持有 | 用 `weak_ptr` 打破循环 |
| 9 | 用 `get()` 的裸指针又构造一个智能指针 | 会导致 double free。所有权只能有一处 |
| 10 | 在构造函数里调 `shared_from_this()` | 抛 `bad_weak_ptr`。只能在对象已被 `shared_ptr` 管理后调用 |
| 11 | lambda 按引用捕获局部变量后异步使用 | 局部变量已销毁 → 悬空引用崩溃。异步场景按值捕获（或捕获 `shared_ptr`） |
| 12 | `[=]` 在成员函数里隐式捕获 `this` | 若 lambda 生命周期超过对象就崩。显式写 `[this]` 或捕获需要的成员副本 |
| 13 | 到处用 `std::function` | 有类型擦除开销且不可内联。只用于**存储**回调；临时调用用模板/`auto` |
| 14 | 忘了 `join`/`detach` | `std::thread` 析构时若仍 joinable → `std::terminate()`。用 RAII 包装 |
| 15 | 手写 `lock()`/`unlock()` | 用 `lock_guard`。异常路径必然漏解锁 |
| 16 | 多把锁顺序不一致 | 死锁。固定顺序或用 `std::lock(m1, m2)` |
| 17 | `cv.wait(lock)` 不带谓词 | 虚假唤醒会导致错误。必须写 `cv.wait(lock, pred)` |
| 18 | `std::vector<bool>` | 特化版本，元素是代理引用，`auto b = v[0]` 得到代理类型而非 bool。需要真 bool 用 `vector<char>` 或 `deque<bool>` |
| 19 | 遍历中修改容器 | 迭代器失效。用 `erase-remove` 惯用法：`v.erase(std::remove_if(...), v.end())` |
| 20 | `unordered_map::operator[]` 用于查找 | 会**插入**默认值。查找用 `find()` |

**补充几个**：

```cpp
// 陷阱 21：Windows 下 min/max 宏冲突
#define NOMINMAX          // 在包含 windows.h 前定义
#include <windows.h>
// 或用 (std::min)(a, b) 这种怪写法绕过宏展开

// 陷阱 22：静态变量的初始化顺序（不同编译单元之间未定义）
// ✅ 用函数内静态局部变量（C++11 起初始化是线程安全的！）
Config& config() {

    return c;
}

// 陷阱 23：跨动态库（.so/.dll）边界传递 STL 对象
// ABI 不统一（不同编译器/标准库实现），会崩。接口层只用 POD 或不透明指针

// 陷阱 24：enum class 想做位标记
enum class Flags { None = 0, A = 1, B = 2 };
// Flags::A | Flags::B  // ❌ 编译错误
```

### 11.2 参数传递的现代规则

```cpp
// 1) 只读、不修改、不保存 → const T&
void print(const std::string& s);

// 2) 只读基本类型（int/double/指针）→ 值传递
void setCount(int n);

// 3) 要"存下来"（sink）→ 按值传 + move（只写一份代码，同时支持拷贝和移动）
class Person {
public:
    Person(std::string name) : name_(std::move(name)) {}   // ✅ 一份代码搞定左值和右值
private:
    std::string name_;
};
std::string n = "Ann";
Person p1(n);                  // 拷贝一次 + 移动一次
Person p2(std::move(n));       // 移动两次（无堆分配）
```

### 11.3 异常安全三级别

| 级别 | 含义 |
|---|---|
| **基本保证** | 异常抛出后，对象仍有效、无资源泄漏，但状态可能改变 |
| **强保证** | 失败则**完全回滚**到操作前状态（copy-and-swap 惯用法） |
| **不抛保证（nothrow）** | 绝不抛异常（析构、移动、swap 应尽量做到） |

```cpp
// copy-and-swap 实现强异常安全的赋值运算符
class Widget {
public:
    Widget(const Widget& other) : data_(other.data_) {}   // 可能抛 → 在这步抛最安全
    void swap(Widget& other) noexcept { using std::swap; swap(data_, other.data_); }

    Widget& operator=(Widget other) noexcept {   // 注意：按值传参 = 拷贝/移动
        swap(other);
        return *this;
    }
private:
    std::vector<int> data_;
};
```

### 11.4 头文件的现代写法

```cpp
// Foo.h
#ifndef FOO_H_          // 或用 #pragma once（非标准但被所有主流编译器支持）
#define FOO_H_

#include <memory>
#include <string>
#include <vector>

class Foo {
public:
    explicit Foo(std::string name);
    ~Foo();                                  // 必须在 .cpp 定义（Pimpl 要求）
    Foo(Foo&&) noexcept;                     // 移动也要在 .cpp 定义
    Foo& operator=(Foo&&) noexcept;
    Foo(const Foo&) = delete;
    Foo& operator=(const Foo&) = delete;

    void doWork();
private:
    struct Impl;                             // Pimpl：隐藏实现细节，减少编译依赖
    std::unique_ptr<Impl> impl_;
};
#endif

// Foo.cpp
#include "Foo.h"
struct Foo::Impl {
    std::string name;
    std::vector<int> data;
};
Foo::Foo(std::string name) : impl_(new Impl{std::move(name), {}}) {}
Foo::~Foo() = default;      // ⚠️ 必须在 Impl 完整定义可见的地方，否则 unique_ptr 析构报错
Foo::Foo(Foo&&) noexcept = default;
Foo& Foo::operator=(Foo&&) noexcept = default;
void Foo::doWork() { impl_->data.push_back(1); }
```

> **Pimpl + `unique_ptr` 的坑**：`unique_ptr<Impl>` 的析构需要 `Impl` 是完整类型，所以析构/移动必须在 `.cpp` 里定义（不能在头文件里 `= default`）。

## 第 12 章 综合实战：并发词频统计器

把前面所有特性串起来：**文件 RAII + unique_ptr + 移动语义 + unordered_map + 线程池 + future + mutex + chrono + lambda + 算法排序**。

### 12.1 线程池 `ThreadPool.h`

```cpp
#ifndef THREAD_POOL_H_
#define THREAD_POOL_H_

#include <condition_variable>
#include <functional>
#include <future>
#include <memory>
#include <mutex>
#include <queue>
#include <stdexcept>
#include <thread>
#include <type_traits>
#include <utility>
#include <vector>

class ThreadPool {
public:
    explicit ThreadPool(std::size_t n) : stop_(false) {
        for (std::size_t i = 0; i < n; ++i) {
            workers_.emplace_back([this] { workerLoop(); });
        }
    }

    // 禁止拷贝/移动（内部有 mutex、线程，不可复制）
    ThreadPool(const ThreadPool&)            = delete;
    ThreadPool& operator=(const ThreadPool&) = delete;

    ~ThreadPool() {
        {
            std::lock_guard<std::mutex> lk(queueMutex_);
            stop_ = true;
        }
        cond_.notify_all();
        for (std::thread& t : workers_) {
            if (t.joinable()) t.join();
        }
    }

    // 提交任务，返回 future 拿结果
    template <typename F, typename... Args>
    auto submit(F&& f, Args&&... args)
        -> std::future<typename std::result_of<F(Args...)>::type> {
        using ResultType = typename std::result_of<F(Args...)>::type;

        auto task = std::make_shared<std::packaged_task<ResultType()>>(
            std::bind(std::forward<F>(f), std::forward<Args>(args)...));

        std::future<ResultType> fut = task->get_future();
        {
            std::lock_guard<std::mutex> lk(queueMutex_);
            if (stop_) throw std::runtime_error("submit on stopped ThreadPool");
            tasks_.emplace([task] { (*task)(); });   // 类型擦除成 void()
        }
        cond_.notify_one();
        return fut;
    }

    std::size_t size() const { return workers_.size(); }

private:
    void workerLoop() {
        for (;;) {
            std::function<void()> job;
            {
                std::unique_lock<std::mutex> lk(queueMutex_);
                cond_.wait(lk, [this] { return stop_ || !tasks_.empty(); });
                if (stop_ && tasks_.empty()) return;
                job = std::move(tasks_.front());
                tasks_.pop();
            }   // 提前解锁：执行任务时不持锁
            job();
        }
    }

    std::vector<std::thread>          workers_;
    std::queue<std::function<void()>> tasks_;
    std::mutex                        queueMutex_;
    std::condition_variable           cond_;
    bool                              stop_;
};

#endif  // THREAD_POOL_H_
```

> 📌 说明：`std::result_of` 在 C++17 弃用、C++20 移除，新项目应改用 `std::invoke_result_t<F, Args...>`。
> 📌 `std::bind` 会把参数 decay 后保存；若参数是 move-only 类型（如 `unique_ptr`），C++11 下需改写为 lambda 捕获（C++14 init-capture 或 C++11 的 `std::shared_ptr` 中转）。

### 12.2 词频统计 `main.cpp`

```cpp
#include <algorithm>
#include <cctype>
#include <chrono>
#include <cstdio>
#include <fstream>
#include <iostream>
#include <memory>
#include <sstream>
#include <string>
#include <unordered_map>
#include <utility>
#include <vector>

#include "ThreadPool.h"

// ---------- RAII 文件读取：异常安全，返回可移动的 string ----------
std::string readFile(const std::string& path) {
    std::ifstream in(path, std::ios::binary);   // 析构自动关闭
    if (!in) throw std::runtime_error("cannot open: " + path);
    std::ostringstream ss;
    ss << in.rdbuf();
    return ss.str();   // 直接返回 → NRVO / 移动
}

// ---------- 统计单个文本的单词频次 ----------
using WordCount = std::unordered_map<std::string, std::size_t>;

WordCount countWords(const std::string& text) {
    WordCount local;
    local.reserve(1024);                 // 减少 rehash
    std::string word;
    for (char ch : text) {
        unsigned char uc = static_cast<unsigned char>(ch);
        if (std::isalpha(uc)) {
            word.push_back(static_cast<char>(std::tolower(uc)));
        } else if (!word.empty()) {
            ++local[word];               // 平均 O(1)
            word.clear();
        }
    }
    if (!word.empty()) ++local[word];
    return local;                        // 返回值自动移动（NRVO）
}

// ---------- 合并结果 ----------
void mergeInto(WordCount& target, WordCount&& src) {
    for (const auto& kv : src) target[kv.first] += kv.second;
}

int main(int argc, char** argv) {
    if (argc < 2) {
        std::cerr << "usage: " << argv[0] << " file1 [file2 ...]\n";
        return 1;
    }

    const std::size_t topN = 20;
    std::vector<std::string> paths(argv + 1, argv + argc);

    auto start = std::chrono::steady_clock::now();

    ThreadPool pool(std::max<std::size_t>(
        1, std::thread::hardware_concurrency() ? std::thread::hardware_concurrency() : 4));

    // 每个文件提交一个任务；future 保存结果
    std::vector<std::future<WordCount>> futures;
    futures.reserve(paths.size());
    for (const auto& p : paths) {
        futures.push_back(pool.submit([p] {          // 按值捕获路径，安全
            return countWords(readFile(p));
        }));
    }

    WordCount total;
    total.reserve(4096);
    for (auto& f : futures) {
        mergeInto(total, f.get());      // get() 阻塞；若任务抛异常，这里重新抛出
    }

    // 取 Top N：拷到 vector 里排序
    std::vector<std::pair<std::string, std::size_t>> sorted(total.begin(), total.end());
    std::sort(sorted.begin(), sorted.end(),
              [](const auto& a, const auto& b) {     // ⚠️ 泛型 lambda 是 C++14！
                  if (a.second != b.second) return a.second > b.second;
                  return a.first < b.first;
              });
    // C++11 写法：把 auto 换成 const std::pair<std::string, std::size_t>&

    if (sorted.size() > topN) sorted.resize(topN);

    for (const auto& kv : sorted) {
        std::cout << kv.first << '\t' << kv.second << '\n';
    }

    auto elapsed = std::chrono::duration_cast<std::chrono::milliseconds>(
        std::chrono::steady_clock::now() - start);
    std::cerr << "\n" << paths.size() << " files, "
              << total.size() << " unique words, "
              << elapsed.count() << " ms\n";
    return 0;
}
```

> ⚠️ 上面代码里 `const auto&` 作为 lambda 参数是 **C++14** 泛型 lambda。若严格用 `-std=c++11`，请改成显式类型：
> ```cpp
> [](const std::pair<std::string, std::size_t>& a,
>    const std::pair<std::string, std::size_t>& b) { ... }
> ```

```cpp
#include <condition_variable>
#include <mutex>

class Foo {
    std::mutex mtx;
    std::condition_variable cv;
    int stage = 0;   // 0: first, 1: second, 2: third
public:
    void first(std::function<void()> printFirst) {
        std::unique_lock<std::mutex> lock(mtx);
        cv.wait(lock, [this] { return stage == 0; });
        printFirst();
        stage = 1;
        cv.notify_all();
    }
    void second(std::function<void()> printSecond) {
        std::unique_lock<std::mutex> lock(mtx);
        cv.wait(lock, [this] { return stage == 1; });
        printSecond();
        stage = 2;
        cv.notify_all();
    }
    void third(std::function<void()> printThird) {
        std::unique_lock<std::mutex> lock(mtx);
        cv.wait(lock, [this] { return stage == 2; });
        printThird();
        stage = 0;
        cv.notify_all();
    }
};
```

## 附录 B 自检题（含答案提示）

1. `std::move(x)` 到底做了什么？移动之后 `x` 处于什么状态？
   → 只是 `static_cast<T&&>`；x 处于"有效但未指定"，可析构可赋值，但值不可预期。

2. 为什么移动构造函数要标 `noexcept`？
   → `vector` 扩容时只有移动不抛才能保证异常安全，否则退化为拷贝。

3. Rule of Three / Five / Zero 分别是什么？你更该用哪个？
   → Three：析构/拷贝构造/拷贝赋值；Five：+移动构造/移动赋值；Zero：用 RAII 成员，一个都不写（推荐）。

4. `unique_ptr` 与 `shared_ptr` 的核心区别？默认该选哪个？
   → 独占 vs 引用计数共享；默认 `unique_ptr`。

5. 什么情况会产生 `shared_ptr` 循环引用？怎么破？
   → 父子/双向关联互相持有 `shared_ptr`；从属方改 `weak_ptr`。

6. `std::forward` 和 `std::move` 的区别？
   → `move` 无条件转右值；`forward<T>` 按 T 的推导结果有条件转发（保留左/右值性）。

7. `override` 关键字解决了什么问题？
   → 签名写错导致"以为重写其实是新建函数"，多态静默失效。

8. lambda 的 `[=]` 和 `[&]` 有何风险？
   → `[=]` 在成员函数内隐式捕获 `this`（悬空风险）；`[&]` 捕获局部变量引用，异步场景必崩。

9. `condition_variable::wait` 为什么必须用谓词版本？
   → 存在虚假唤醒（spurious wakeup）。

10. `std::async` 默认启动策略有什么坑？
    → 默认 `async|deferred` 由实现决定，可能根本没开线程；显式指定 `std::launch::async`。

11. `emplace_back` 一定比 `push_back` 快吗？
    → 不一定；参数已是完整对象时等价，且 `emplace` 可能绕过 `explicit` 的意外构造。

12. `vector<bool>` 有什么问题？
    → 特化压缩存储，`operator[]` 返回代理引用，`auto` 会拿到代理类型而非 bool。

13. 为什么要用 `std::make_shared`？
    → 一次内存分配（对象 + 控制块）、异常安全、更快。

14. `const` 和 `constexpr` 的区别？
    → `const` 是"运行时不可改"；`constexpr` 是"编译期就已知"。

15. 析构函数为什么不能抛异常？
    → 栈展开时析构抛异常会导致 `std::terminate`；C++11 起析构默认 `noexcept`。

### C++11 之后（按优先级）

1. **先把 C++11 用熟**：写 3~5 个小项目（文件解析、HTTP 客户端、小游戏、线程池、JSON 解析）。
2. **C++14 / C++17 的高价值特性**：`make_unique`、泛型 lambda、`optional`、`string_view`、`filesystem`、结构化绑定、`if constexpr`。
3. **读源码/好书**：
   - 书：《Effective Modern C++》（Scott Meyers，C++11/14 必读）、《C++ Primer 第 5 版》（C++11 全面教材）、《Effective STL》。
   - 网站：[cppreference.com](https://en.cppreference.com)（查特性与示例的第一选择）、[isocpp.org](https://isocpp.org)、C++ Core Guidelines。
4. **工具链**：CMake、clang-format（统一风格）、clang-tidy（静态检查）、ASan/UBSan/TSan（查内存与竞态）、valgrind、perf。
5. **编译期观察**：[Compiler Explorer](https://godbolt.org) —— 看 `-std=c++11` 下你的代码生成了什么汇编，理解 NRVO、内联、移动是否真的发生。
6. **下一步方向**：模板元编程 → C++20 Concepts/Ranges → 协程与异步 → 高性能/低延迟编程。

### 推荐的每日练习法

- **每天一个特性**：30 行 demo + 打印验证 + 记一条"什么时候用/什么时候别用"。
- **每周一个小项目**：强制自己用 `unique_ptr`、lambda、范围 for、`chrono` 写，不用裸 `new`、不用 `NULL`、不用 `[&]` 捕获异步 lambda。
- **每月一次重构**：把以前写的 C++98 风格代码改写成现代风格，对比行数、可读性、性能差异。

---

> **结束语**：C++11 不是一个"多了几个语法糖"的版本，它标志着 **Modern C++** 的开端。
> 学会它之后你会发现：C++ 代码可以写得更短、更快、更安全，而"手动管理内存、类型写到手抽筋、临时对象疯狂拷贝"这些痛苦，基本都可以交给语言和库去解决。
>
> 祝你写出让自己三个月后还能看懂的代码。 🚀
