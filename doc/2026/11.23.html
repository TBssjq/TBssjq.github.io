本文面向已经有扎实 C/C++ 基础、但第一次系统学单片机的读者。我们不复述「什么是变量、什么是指针」，而是把你已经熟悉的那些概念——内存、地址、对象、编译链接、RAII、模板——一一映射到一块真实的电路板上，再从一颗电阻开始，把 STM32 与 ESP32 两块板子从硬件到固件、从裸机到 RTOS、从点灯到联网上云完整走一遍。

  • 双平台案例：STM32（以 STM32F103C8T6「蓝板」/ STM32F407 为主）代表传统裸机 + 实时控制路线；ESP32（以 ESP32-WROOM-32 / ESP32-S3 为主）代表SoC + Wi-Fi/BLE + FreeRTOS路线。同一概念两边对照讲，你会更快抓住「哪些是 MCU 通识、哪些是厂商特性」。
  • 代码约定：STM32 用 HAL + CubeIDE/CLion + arm-none-eabi-gcc；ESP32 用 ESP-IDF（Native C）为主，必要处给 Arduino-ESP32 对照。C++ 示例统一 -std=gnu++17，关闭异常与 RTTI（-fno-exceptions -fno-rtti）时会有说明。
  • 动手命令：idf.py build flash monitor、openocd -f interface/stlink.cfg -f target/stm32f1x.cfg、arm-none-eabi-gdb、esptool.py flash_id 等，遇到就直接敲一遍。
  • 阅读顺序：建议按章节顺序；只想快速点灯可跳到第 5 章，但第 1、3、4 章（元件 / 内存映射 / 时钟树）决定了你后面能不能独立排错，强烈建议别跳。
  • 安全前提：全程只涉及 3.3 V / 5 V 低压直流；任何市电、电机驱动、锂电池充电电路都不在本文范围，请勿用本文知识直接碰 220 V。

0.1 你已经会什么，还差什么

写 PC 程序时，操作系统替你兜住了一切：内存不够有虚拟内存、卡住了有调度器、外设靠驱动、崩溃了有 core dump。单片机上这些统统没有——或者更准确地说，得由你自己决定要不要有。先把这层思维落差摊开，后面每一章其实都是在填这张表。

0.3 工具链：编译 → 链接 → 烧录 → 调试

你在 PC 上敲 g++ main.cpp -o main && ./main 就完事了。嵌入式里这条链被拉长成四步，每一步都可能出错，所以先把命令摆出来：

# ===== STM32（命令行派）=====
arm-none-eabi-g++ -std=gnu++17 -mcpu=cortex-m3 -mthumb -Os -Wall -Wextra \
  -fno-exceptions -fno-rtti -ffunction-sections -fdata-sections \
  -T STM32F103C8Tx_FLASH.ld main.cpp startup_stm32f103xb.s -o firmware.elf \
  -Wl,--gc-sections -lm
arm-none-eabi-objcopy -O binary firmware.elf firmware.bin   # elf -> 裸二进制
arm-none-eabi-size firmware.elf                             # 看 text/data/bss 占多少
openocd -f interface/stlink.cfg -f target/stm32f1x.cfg \
  -c "program firmware.elf verify reset exit"               # SWD 烧录

# ===== ESP32（ESP-IDF）=====
idf.py set-target esp32          # 选芯片，生成 sdkconfig
idf.py menuconfig                # 图形化配置：Flash 大小、分区表、日志等级…
idf.py build                     # CMake + xtensa-esp32-elf-gcc
idf.py -p /dev/ttyUSB0 flash monitor   # 串口烧录 + 打开串口监视器
idf.py erase-flash               # 擦干净（换分区表后必做）
esptool.py flash_id              # 读 Flash 芯片 ID，确认没买错料

# ===== 通用调试 =====
arm-none-eabi-gdb firmware.elf -ex "target extended-remote :3333"
# ESP32 侧：idf.py openocd / idf.py gdb，或直接用内置 USB-Serial-JTAG（S3/C3）

逐段解释这几个新东西：

  1. 交叉编译（cross compile）：编译器跑在 x86 电脑上，产出的却是 ARM / Xtensa 指令，所以工具链名字带前缀 arm-none-eabi-、xtensa-esp32-elf-。none 表示「无操作系统」，eabi 是嵌入式应用二进制接口。
  2. 链接脚本 .ld：你写 int x; 时，链接器必须知道把它放到 0x20000000 开头的哪一段 SRAM；脚本里 MEMORY { FLASH(rx) : ORIGIN = 0x08000000, LENGTH = 64K RAM(rwx) : ORIGIN = 0x20000000, LENGTH = 20K } 就是这块板子的「地图」。第 3 章会完整拆它。
  3. ELF → BIN/HEX：ELF 带符号表和调试信息，给 GDB 用；烧进 Flash 的是纯机器码 .bin，或带地址记录的 Intel HEX。
  4. 烧录（flash/program）：通过 SWD（STM32）或 UART bootloader（ESP32，靠 BOOT/EN 引脚进下载模式）把字节写进 Flash。
  5. 调试：OpenOCD 把 GDB 的「读内存、下断点」翻译成 SWD/JTAG 时序，经 ST-Link 这类调试器送到芯片。这是你排查 HardFault 时唯一的眼睛。

第一部分 · 硬件地基：把板子看懂

第 1 章 一块开发板上的所有元件

很多人学单片机的第一道坎不是 C 语言，而是拿起板子不知道上面那些小疙瘩是干什么的。这一章我们把一块最小系统板拆成零件清单，逐个讲清楚「它长什么样、电气上干什么、坏了会怎样、选型看哪个参数」。看完你就能对着原理图讲出每一条线为什么存在。

1.1 什么叫「最小系统」

一颗 MCU 芯片本身几乎不能工作。要让它上电后能跑第一行代码，至少得凑齐五件事，合称最小系统（Minimum System）：

  1. 供电：稳定的 3.3 V（或 1.8 V～5 V，看型号），且每个电源引脚旁都有去耦电容。
  2. 时钟：一个时钟源（内部 RC 或外部晶振），CPU 靠它一步一步取指。
  3. 复位：上电时把内部状态清成确定值，通常一个 RC 电路 + 一个按键。
  4. 启动配置：告诉芯片「上电后从哪块存储器开始执行」——STM32 靠 BOOT0/BOOT1 引脚电平，ESP32 靠 eFuse + strap 引脚。
  5. 程序下载与调试通道：SWD/JTAG，或 UART bootloader。

去耦电容为什么必须是 100 nF 且「紧贴引脚」？这是最值得理解的一条。CMOS 数字电路在时钟沿瞬间会同时翻转成千上万个门，电流阶跃很大；电源走线有寄生电感，长走线来不及从 LDO 补电流，VDD 就会瞬间塌陷。电容相当于在芯片旁边放了个小水缸：ΔV = I·Δt / C，容值越大、距离越近（寄生电感越小），塌陷越小。经验法则是每个 VDD 引脚一颗 100 nF，走线先过电容再进引脚，电源入口再加一颗 10 µF。你在 C++ 里习惯的「抽象隔离」，在这里对应的是「电源完整性」。

动手算一次LED 限流电阻：R = (VCC − Vf) / If。3.3 V 供电、红色 LED 正向压降 Vf ≈ 2.0 V、想要 If = 5 mA，则 R = (3.3−2.0)/0.005 = 260 Ω，取标准值 330 Ω，实际电流约 3.9 mA，足够亮且不伤 IO。蓝色/白色 LED 的 Vf ≈ 3.0～3.2 V，同样电阻会明显更暗——这就是「同一种代码，换颗灯效果不同」的物理原因。

1.4 复位、启动配置与时钟电路

这三块电路决定了「上电之后发生什么」，是第 3 章启动流程的物理前提。

复位电路：经典组合是 10 kΩ 上拉到 3.3 V + 100 nF 电容到地 + 按键并到地。上电瞬间电容相当于短路，NRST 被拉低；电容充电完成后 NRST 变高，芯片才开始跑。粗略延时 τ = RC = 10 kΩ × 100 nF = 1 ms，配合芯片内部的上电复位（POR）足够。按下按键则电容放电，产生一次手动复位。

启动配置：STM32F1 靠 BOOT0（和 BOOT1）在上电复位第 4 个 SYSCLK 上升沿被锁存：BOOT0=0 从主 Flash（0x08000000）启动，这是正常模式；BOOT0=1 进系统存储器里的出厂 Bootloader，可通过 USART1 串口烧录；还有一种是从 SRAM 启动，用于调试。ESP32 没有 BOOT 跳线，而是上电时采样 strapping 引脚（如 GPIO0、GPIO2、GPIO12、EN），拉低 GPIO0 再复位即进入 UART 下载模式——开发板上的两个按键（BOOT / EN）和 USB 转串口的 DTR/RTS 就是自动帮你做这套时序。

时钟：STM32 常有 HSE（外部 8 MHz 晶振）、HSI（内部 8 MHz RC）、LSE（32.768 kHz RTC 晶振）、LSI（内部 ~40 kHz 看门狗时钟）四路源，经 PLL 倍频后再分频给 AHB/APB。ESP32 主时钟来自外部 40 MHz 晶振，经 PLL 得到 80/160/240 MHz CPU 频率，另有 RTC 慢时钟用于深度睡眠。晶振走线要短、包地、下方不要走数字信号线，负载电容按晶振 datasheet 的 CL 计算——25 ppm 的频偏，在 115200 波特率下就是每千帧一个错帧的隐患。

1.5 连接器、机械件与「看得见的」东西

  • 排针 / 排母 / 杜邦线：2.54 mm 间距是面包板生态的通用语言。注意「公对母、母对母」别买错；杜邦线接触不良是调试期最常见的假故障。
  • USB Type-C / Micro-USB：Type-C 座上 CC 引脚要接 5.1 kΩ 下拉（作为 UFP 设备）才能从充电器取电，只焊了 VBUS/GND/D+/D− 的板子在部分 C-to-C 线材下不通电，这是很经典的坑。
  • SWD / JTAG 连接器：SWD 只需 SWDIO、SWCLK、GND、Vref（可选）、NRST（可选） 五根线，比 20 针 JTAG 省地方；Vref 是给调试器做电平参考的，不是给目标板供电。
  • 天线（ESP32 专属）：模组有 PCB 板载天线或 IPEX 外接天线两种。板载天线周围必须按 datasheet 做净空区（keep-out），下方不能铺铜、不能放电池/金属壳；天线旁边走线或塞个螺丝，Wi-Fi 距离能差十倍。
  • 丝印与极性标记：电解电容的白色条是负极、LED 的长脚是阳极、芯片的「小圆点 / 缺口」是 1 脚。焊之前先找 1 脚，这是硬件界的「先看函数签名」。
  • 测试点 TP：量产的板子会留圆形裸铜焊盘给示波器/夹具，原型阶段自己也可预留 GND 测试点，夹地线会方便很多。

STM32F103C8T6 是一颗裸 MCU 芯片：LQFP48 封装、48 个引脚，你得自己配晶振、电源、去耦、复位。ESP32-WROOM-32 是一个模组（module）：里面已经封好了 ESP32-D0WDQ6 芯片、40 MHz 晶振、SPI Flash、PCB 天线和射频匹配网络，并通过了射频认证。所以「ESP32 最小系统」反而简单：给 3.3 V、加 EN/BOOT 按键、引出 USB 转串口就行。

第 2 章 够用的电路常识：把「电平」这件事想透

你不需要成为模拟电路工程师，但必须建立一套电压 / 电流 / 时间的直觉。因为单片机程序里绝大多数「玄学 bug」——按键乱触发、I2C 扫不到设备、ADC 读数跳、串口时好时坏——根子都在这一章。

2.1 电压、电流、地：三个必须先统一的词

电压永远是两个点之间的电位差。说「这个引脚是 3.3 V」，完整意思是「相对 GND 是 3.3 V」。所以两块板子要通信，必须共地（GND 相连）——否则 TX 线上的 3.3 V 在对方眼里没有参考点，读出来全是浮空噪声。这是「接了 TX/RX 就是不通」的第一嫌疑。

电流由负载决定，不是由电源「推」出来。一个标 3.3 V / 500 mA 的 LDO 意思是「最多能供 500 mA」，芯片只吃 20 mA 时就只给 20 mA。反过来，一个 5 V / 2 A 电源接到只吃 100 mA 的板子完全安全；但把 12 V 接到 3.3 V 的板子，电压超标会瞬间击穿——电压看匹配，电流看余量。

2.2 推挽、开漏、上拉：GPIO 内部的三种状态

这是理解 I2C、按键、总线仲裁的钥匙。一个 GPIO 输出级可以简化成一对 MOS 管：

  • 推挽（Push-Pull）：上管接 VDD、下管接 GND。输出 1 时上管导通「推」出高电平，输出 0 时下管导通「拉」向地。高低电平都主动驱动，边沿陡、速度快，是默认模式。缺点：两个推挽输出直接相连且一个输出高一个输出低，就是电源对地短路。
  • 开漏 / 开集（Open-Drain / Open-Collector）：只有下拉管，输出 0 时拉地，输出 1 时干脆断开（高阻），电平靠外部上拉电阻拉到 VDD。好处是多个设备可以并在同一根线上：谁想发 0 就拉低，谁都不拉时电阻把线拉高，天然实现「线与」仲裁——这正是 I2C 的物理基础，也是它能做多主、能做时钟拉伸的原因。
  • 高阻 / 浮空（Floating / Hi-Z）：输入模式且既不上拉也不下拉。此时引脚电压由外部决定；如果什么都没接，读数会随机漂，还会让输入级 CMOS 半导通、增加功耗。所以未使用的输入引脚要么配置内部上/下拉，要么设成模拟输入。

上拉电阻取值是一场拉锯：阻值小则上升沿快、抗干扰强，但低电平时灌电流大（I = V/R）；阻值大则省电，但线与寄生电容形成 RC，上升沿变慢，高速时波形变圆。I2C 标准模式常用 4.7 kΩ（3.3 V 时约 0.7 mA），快速模式 400 kHz 常降到 2.2 kΩ，总线电容大时还要再小。粗略校核：

上拉电阻下限（低电平时别灌太多电流）：
    R_min = (VDD − V_OL) / I_OL
    3.3 V、允许灌 3 mA、V_OL ≈ 0.4 V  →  R_min ≈ 967 Ω  →  取 ≥ 1 kΩ

上拉电阻上限（上升沿要在规定时间内爬上来）：
    t_r ≈ 0.8473 · R_p · C_bus
    I2C 快速模式要求 t_r ≤ 300 ns，若 C_bus = 100 pF
    R_max ≈ 300 ns / (0.8473 × 100 pF) ≈ 3.5 kΩ

    → 合理区间约 1 kΩ ~ 3.5 kΩ，常用 2.2 kΩ ~ 4.7 kΩ

2.3 按键抖动与 RC：软件为什么要「等一等」

机械按键闭合时，弹片会在几毫秒内反复弹跳，电平是一串毛刺，不是干净的阶跃。若用外部中断下降沿触发，一次按下可能进十次 ISR。解决思路有三种，后面第 5、6 章会各写一遍代码：

  1. 硬件 RC 滤波：按键并 100 nF + 串 1 kΩ，把毛刺抹平，再进施密特触发输入（STM32 多数 IO 带施密特）。
  2. 软件延时消抖：检测到变化后等 20 ms 再读一次，一致才确认。裸机最简单，但会阻塞。
  3. 状态机 / 定时采样：每 1 ms 由定时器采样一次，连续 N 次一致才翻转状态。既不阻塞又能长按/双击，工程上最推荐。

上电复位电路也是同一个 RC 原理，只是把「时间常数」用在了启动上：τ = R·C，电容电压充到约 63% VDD 需要一个 τ，充到 95% 约需 3τ。理解了 τ，你就理解了为什么复位电容从 100 nF 换成 10 µF 会让板子「上电要等一下才启动」。

2.4 别让引脚过载：驱动能力与灌拉电流

STM32 单个 IO 通常允许 ±20 mA 左右（绝对最大值 ±25 mA），但整颗芯片所有 VDD/VSS 的总电流还有上限。ESP32 单 IO 推荐 ≤ 20 mA（部分引脚 40 mA）。所以：

  • 点亮一颗 LED（3～10 mA）直接用 IO 没问题；
  • 驱动继电器（70～150 mA）、灯带、直流电机，必须经 MOSFET / 三极管 / 驱动芯片，IO 只负责给栅极一个逻辑电平；
  • 感性负载（继电器、电机、螺线管）断开瞬间会产生反向高压，必须并续流二极管，否则会打穿驱动管甚至窜回 MCU。
  • 还要区分 拉电流（Source，IO 输出高，电流从芯片流出） 与 灌电流（Sink，IO 输出低，电流流进芯片）。很多芯片灌电流能力更强，所以「LED 接 VCC、IO 拉低点亮」的接法（低电平有效）反而更常见，Blue Pill 的 PC13 用户灯就是这样。

第二部分 · MCU 内核与裸机编程：程序到底怎么跑起来

第 3 章 内核、内存映射与启动流程

这一章是把 C++ 的「地址」概念落到物理硅片的一章。你会第一次看到 0x4001080C 这种地址不是随机数，而是「GPIOA 的输出数据寄存器」；也会明白为什么 volatile 在嵌入式里不是可选项。

3.1 冯诺依曼 / 哈佛，以及 Cortex-M 与 Xtensa 的差异

PC 上程序和数据都在内存里（冯诺依曼）。Cortex-M 采用改进的哈佛架构：指令总线（I-Code）和数据总线（D-Code）分开，可以同时取指和读数据，但对外呈现统一的 4 GB 地址空间——也就是说，从程序员视角看，Flash、SRAM、外设寄存器、内核私有寄存器都只是这段地址里的不同区间。这一点极其重要：

一句话在单片机里，操作外设 = 读写某个固定内存地址。没有 syscall，没有驱动 ioctl，没有 /dev。你把 0x4001080C 的最低位置 1，PA0 就输出高电平——因为硬件把这块地址解码到了 GPIO 的寄存器上。C++ 里「指针指向对象」的直觉在这里完全够用，只是对象由硅片实现。

3.2 内存映射：4 GB 地址空间怎么切

映射到 C++ 语言层面：所谓「外设」，就是厂商头文件里用结构体把这段地址排好，例如

// CMSIS 风格的寄存器块：结构体成员顺序 = 地址偏移
typedef struct {
    __IO uint32_t CRL;      // +0x00 端口配置低寄存器
    __IO uint32_t CRH;      // +0x04 端口配置高寄存器
    __IO uint32_t IDR;      // +0x08 输入数据
    __IO uint32_t ODR;      // +0x0C 输出数据
    __IO uint32_t BSRR;     // +0x10 置位/复位（原子！写 1 有效，写 0 无影响）
    __IO uint32_t BRR;      // +0x14 复位
    __IO uint32_t LCKR;     // +0x18 配置锁定
} GPIO_TypeDef;

#define GPIOA_BASE   0x40010800UL
#define GPIOA        ((GPIO_TypeDef *)GPIOA_BASE)

// 于是「PA0 输出高」就是一次普通的指针写：
GPIOA->BSRR = (1u << 0);      // 置位：原子操作，不会被中断打断成读-改-写
GPIOA->BSRR = (1u << 16);     // 复位：低 16 位置位，高 16 位清零

// 为什么用 BSRR 而不是 ODR |= (1<<0)？
// ODR |= 会编译成「读 ODR → 或 → 写回」，若中断里改了别的位，会把它覆盖掉（竞态）。
// BSRR 是硬件保证的单次写原子置位，这正是 C++ 里「不要手动读-改-写共享状态」的硬件版答案。

3.3 volatile：不是「优化开关」，是「别替我撒谎」

编译器的优化前提是「内存只有本程序会改」。外设寄存器、中断里改的标志位、DMA 正在写的缓冲区，都会被程序之外的硬件改动。不加 volatile，编译器完全可以认为「这个变量刚读过、没人改，直接用寄存器里的旧值」，于是：

// ❌ 危险：编译成「读一次 flag，若为 0 就死循环」，中断改了它也不会再看内存
bool uart_rx_done = false;
void USART1_IRQHandler() { uart_rx_done = true; }
while (!uart_rx_done) { }          // -O2 下可能永远不退出

// ✅ 正确：每次都真的去内存读
volatile bool uart_rx_done = false;

// ✅ 但注意：volatile 不等于线程安全、不等于原子、不提供内存屏障
// 多字节数据（如 32 位计数器）在 8/16 位访问下仍可能撕裂；
// 跨核 / RTOS 场景请用原子类型、临界区或队列，而不是只加 volatile。

// 更地道的 C++ 写法：把「寄存器」建模成类型
template<std::uintptr_t Addr, class T = std::uint32_t>
struct Reg {
    static volatile T& ref() { return *reinterpret_cast<volatile T*>(Addr); }
    static void set(T m)     { ref() |= m; }        // 仅用于不与他人共享位的场合
    static void write(T v)   { ref() = v; }
    static T    read()       { return ref(); }
};
// 编译期就定死地址，零运行时开销，和你在 PC 上写模板策略类是一回事

3.4 启动流程：从复位向量到 main（以及 C++ 全局构造）

把链接脚本和启动文件摊开看，C++ 里那些「理所当然」的事情才露出成本：

/* ===== 链接脚本 STM32F103C8Tx_FLASH.ld（节选）===== */
MEMORY
{
  RAM   (xrw) : ORIGIN = 0x20000000, LENGTH = 20K
  FLASH (rx)  : ORIGIN = 0x08000000, LENGTH = 64K
}
_estack = ORIGIN(RAM) + LENGTH(RAM);      /* 栈顶 = SRAM 末尾，栈向下生长 */

SECTIONS {
  .isr_vector : { . = ALIGN(4); KEEP(*(.isr_vector)) } >FLASH
  .text       : { *(.text) *(.text*) *(.rodata) } >FLASH
  /* .data 有初值：运行时在 RAM，但初值必须存在 Flash 里，上电后搬过去 */
  .data : {
    _sdata = .;                 /* RAM 中的目标地址 */
    *(.data) *(.data*)
    _edata = .;
  } >RAM AT> FLASH
  _sidata = LOADADDR(.data);   /* Flash 中初值的起始地址 */
  .bss : {
    _sbss = .;  *(.bss) *(COMMON)  _ebss = .;   /* 未初始化全局 → 只清零 */
  } >RAM
}

/* ===== startup_*.s 里的 Reset_Handler（伪码，ARM 汇编）===== */
Reset_Handler:
  ldr  r0, =_estack
  mov  sp, r0                 ; 1) 设栈指针（没有栈就没法调 C 函数）
  ldr  r1, =_sidata          ; 2) Flash 里 .data 的初值
  ldr  r2, =_sdata
  ldr  r3, =_edata
  bl   copy_data              ; 3) 搬 .data
  mov  r0, #0
  ldr  r1, =_sbss / =_ebss
  bl   zero_bss               ; 4) 清 .bss
  bl   SystemInit             ; 5) 配时钟（Flash 等待周期、PLL…）
  bl   __libc_init_array      ; 6) ★ 调用 C++ 全局/静态对象构造函数
  bl   main                   ; 7) 终于到你写的第一行
  b    .                      ;    main 若返回就死在这（裸机没有 OS 可回）

/* ===== 由此得到几条嵌入式 C++ 铁律 ===== */
// 1. 全局对象的构造函数在 main 之前跑，此时时钟/外设可能还没初始化 → 别在构造里碰硬件
// 2. 全局对象占用 .bss/.data；一个 std::string / std::vector 可能悄悄吃掉几百字节 + 堆
// 3. 关掉异常与 RTTI（-fno-exceptions -fno-rtti）能省下可观的 Flash
// 4. 静态初始化顺序跨编译单元未定义 → 用「函数内局部静态」或显式 init() 控制顺序
// 5. 栈向下生长，堆向上生长，二者碰头就是栈溢出：用 -Wl,--gc-sections + 充足余量

第 4 章 时钟树与电源：所有外设的「心跳」

新手最常问的一句是：「代码一模一样，为什么我的串口全是乱码 / 延时不准 / PWM 频率不对？」十有八九是时钟没配对。因为几乎所有外设的速率——波特率、定时器计数、ADC 采样、SPI SCK——都是从系统时钟分频出来的。

4.1 STM32 时钟树逐段拆解

逐段说人话：

  • HSE / HSI / LSE / LSI 是四个「源」。外部晶振精度高（±10～30 ppm），内部 RC 起振快但温漂大（±1% 量级）。做 USB、CAN、高精度串口，必须用 HSE；做电池低功耗，可能反而用 LSI 跑 RTC。
  • PLL 是倍频器：8 MHz × 9 = 72 MHz。F4/H7 的 PLL 有多级分频/倍频（M/N/P/Q），CubeMX 会帮你解约束方程。
  • AHB / APB 预分频 决定各总线速度。外设挂在哪条总线上，就吃哪条总线的时钟——这是查「为什么 USART2 波特率不对」时必须先确认的事。
  • 外设时钟门控：RCC->APB2ENR |= RCC_APB2ENR_IOPAEN。STM32 上电后绝大多数外设时钟是关的，没开时钟就去配寄存器，写进去完全无效且不报错。这是「代码看着对但引脚没反应」的冠军原因。
  • Flash 等待周期：CPU 跑 72 MHz 时 Flash 跟不上，要设 FLASH_ACR 的 latency（F1 在 48～72 MHz 需 2 个等待周期）。SystemInit 里做了这件事，自己写启动代码时别漏。
// 波特率是怎么从时钟算出来的（USARTDIV = f_PCLK / (16 × 波特率)）
// PCLK2 = 72 MHz，目标 115200：
//   USARTDIV = 72'000'000 / (16 × 115200) = 39.0625
//   整数部分 39 = 0x27，小数部分 0.0625 × 16 = 1  → BRR = 0x271
//   实际波特率 = 72'000'000 / (16 × 39.0625) = 115200，误差 0%
// 若误以为 PCLK1=36 MHz 却按 72 MHz 算，误差 50% → 满屏乱码

// HAL 把这套计算藏在 UART 初始化里，但你要能自己反推：
UART_HandleTypeDef huart1 = {
    .Instance = USART1,
    .Init    = { .BaudRate = 115200, .WordLength = UART_WORDLENGTH_8B,
                 .StopBits = UART_STOPBITS_1, .Parity = UART_PARITY_NONE,
                 .Mode = UART_MODE_TX_RX, .HwFlowCtl = UART_HWCONTROL_NONE }
};
// huart1.Init.BaudRate 最终被换算成 USART1->BRR，源头就是 PCLK2

4.2 ESP32 的时钟：简单，但有三处要注意

ESP-IDF 通过 sdkconfig 把 CPU 频率设成 80/160/240 MHz，绝大多数外设时钟由 APB（通常 80 MHz） 分频得到，你很少需要手工画时钟树。但有三个坑值得记住：

  1. 改 CPU 频率会影响 APB 与外设：动态调频（DFS）时部分外设的分频源会跟着变，做精确 PWM / 定时采样前先固定频率或在驱动里显式指定 clock source（如 ledc_timer_config_t::clk_cfg = LEDC_AUTO_CLK）。
  2. RTC 慢时钟：深度睡眠时主晶振关闭，靠 150 kHz 内部 RC 或外部 32.768 kHz 晶振维持计时；用内部 RC 时唤醒时间会有明显误差，做定时上报要外挂 32 k 晶振或联网校时。
  3. 射频对电源和时钟极敏感：Wi-Fi 发射瞬间电流峰值可达数百 mA，若 LDO 余量不足或去耦不够，会出现「一联网就重启」；晶振频偏超标则表现为「连不上路由器 / 蓝牙配对失败」。

第 5 章 GPIO 点灯：三个平台的第一种写法

现在终于可以让硬件动起来了。但在敲第一行代码前，先把「点不亮」的排查顺序刻进肌肉记忆——它比代码本身更值钱。

5.1 点灯前的七项检查

  1. 供电正常吗：万用表量 3V3 与 GND 之间是不是 3.25～3.35 V；LDO 烫手说明短路或压差过大。
  2. 共地了吗：外接模块/ST-Link/USB 转串口，GND 必须连在一起。
  3. 外设时钟开了吗：STM32 用 GPIO 前必须置位 RCC->APB2ENR 对应位；没开时钟，写配置寄存器毫无效果。
  4. 引脚模式对了吗：输出要点灯得设成推挽输出；设成输入或开漏（没上拉）就永远不会亮。
  5. 极性对了吗：Blue Pill 的 PC13 是低电平点亮（LED 接 VCC，IO 灌电流），写 1 反而是灭。ESP32-DevKitC 的板载 LED 常见 GPIO2，也是看原理图确认。
  6. 限流电阻有了吗：直连 LED 到 IO 会超出引脚电流额定值，轻则 IO 老化，重则芯片报废。
  7. 引脚是不是被占用了：调试口（SWDIO/SWCLK）、晶振脚（OSC_IN/OUT）、ESP32 的 strapping 脚（GPIO0/2/12/15）与 Flash 占用脚（GPIO6～11）都不能随便当普通 IO。

ESP32 引脚雷区GPIO6～11 通常接模组内部 SPI Flash，绝对不能用作普通 IO；GPIO0 决定下载模式，接了下拉外设会导致上电进不了程序；GPIO12 在上电时会影响 Flash 电压选择（ strapping ），拉高可能烧 Flash；GPIO34～39 是仅输入引脚，没有输出驱动也没有内部上拉。选引脚前先查「ESP32 DevKitC pinout」图，别凭编号顺序猜。

5.2 写法一：直接寄存器（STM32F103，PA0 推挽输出）

#include "stm32f1xx.h"

int main(void) {
    SystemInit();                                     // 由 startup 调用过则不必重复

    // 1) 开 GPIOA 时钟 + 辅助功能时钟（AFIO 在使用重映射时才需要）
    RCC->APB2ENR |= RCC_APB2ENR_IOPAEN;

    // 2) PA0 配置为「通用推挽输出，速度 2 MHz」
    //    CRL 每个引脚占 4 bit：CNF[1:0] + MODE[1:0]
    //    00/10/… 中：MODE=10 表示输出 2 MHz，CNF=00 表示推挽
    GPIOA->CRL &= ~(0xFu << (0 * 4));
    GPIOA->CRL |=  (0x2u << (0 * 4));

    // 3) 用 BSRR 原子置位 / 复位，避免 ODR |= 的读-改-写竞态
    for (;;) {
        GPIOA->BSRR = (1u << 0);       // PA0 = 1
        for (volatile int i = 0; i < 500000; ++i) { }   // 粗糙延时，仅演示
        GPIOA->BSRR = (1u << 16);      // PA0 = 0（BSRR 高 16 位 = 复位）
        for (volatile int i = 0; i < 500000; ++i) { }
    }
}

注意 volatile int i：没有 volatile，优化器会把整个空循环删掉（因为它没有可观察副作用），灯就会以 MHz 频率闪烁，肉眼看是常亮。这是 volatile 的第二个经典用途。当然，这种延时既不精确又烧电，第 7 章就换成定时器。

5.3 写法二：HAL（CubeMX 生成的工业写法）

/* CubeMX 里：PA0 → GPIO_Output；SYSCLK 配 72 MHz；生成代码 */
#include "main.h"

static void MX_GPIO_Init(void) {
    __HAL_RCC_GPIOA_CLK_ENABLE();                 // 宏展开就是 RCC->APB2ENR |= ...
    GPIO_InitTypeDef g = {0};
    g.Pin   = GPIO_PIN_0;
    g.Mode  = GPIO_MODE_OUTPUT_PP;               // 推挽
    g.Pull  = GPIO_NOPULL;
    g.Speed = GPIO_SPEED_FREQ_LOW;
    HAL_GPIO_Init(GPIOA, &g);
    HAL_GPIO_WritePin(GPIOA, GPIO_PIN_0, GPIO_PIN_SET);
}

int main(void) {
    HAL_Init();          // 配 SysTick 1 ms 中断、NVIC 分组、Flash 预取
    SystemClock_Config();
    MX_GPIO_Init();
    for (;;) {
        HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_0);
        HAL_Delay(500);  // 依赖 SysTick 中断递增的 uwTick，不阻塞式忙等
    }
}

HAL_Delay 内部是「记录当前 uwTick，然后 while 等它涨够」，仍然是忙等，但 tick 由 1 ms 的 SysTick 中断维护，所以至少是可预测的。这也埋了一个经典坑：如果你在某个中断优先级高于或等于 SysTick 的 ISR 里调用 HAL_Delay，SysTick 中断进不来，uwTick 不涨，程序就永远卡死——第 6 章会正式处理这件事。

#include "driver/gpio.h"
#include "freertos/FreeRTOS.h"

    cfg.pin_bit_mask = (1ULL << LED_PIN);
    cfg.mode         = GPIO_MODE_OUTPUT;       // ESP32 输出默认推挽

    cfg.pull_down_en = GPIO_PULLDOWN_DISABLE;

        gpio_set_level(LED_PIN, 1);
        vTaskDelay(pdMS_TO_TICKS(500));        // ★ 真正让出 CPU 给别的任务

5.5 用 C++ 写零开销的 GPIO 封装

你熟悉的 RAII、模板、constexpr 在这里不是「炫技」，而是把配置从运行时搬到编译期：地址、位掩码、模式全部在编译期算好，最终生成的汇编和一双手写寄存器一模一样，却好读得多。

// gpio_cpp.hpp —— 编译期引脚，零虚函数、零动态分配（STM32F1 示例）
#include <cstdint>

template<std::uintptr_t Base>
struct Port {
    static constexpr auto CRL  = reinterpret_cast<volatile std::uint32_t*>(Base + 0x00);
    static constexpr auto ODR  = reinterpret_cast<volatile std::uint32_t*>(Base + 0x0C);
    static constexpr auto BSRR = reinterpret_cast<volatile std::uint32_t*>(Base + 0x10);
};
using PA = Port<0x40010800UL>;
using PC = Port<0x40011000UL>;

template<class P, unsigned N>
struct GpioOut {
    static_assert(N < 16, "only pin 0..15 on this port");
    static constexpr std::uint32_t mask = 1u << N;

    // 构造即配置：RAII 把「忘记初始化」变成编译期/启动期必然发生的事
    GpioOut() {
        // 实际工程里 RCC 使能应集中做一次（略）
        auto shift = (N < 8 ? N : N - 8) * 4;
        auto& cr   = (N < 8 ? *P::CRL : *reinterpret_cast<volatile std::uint32_t*>(reinterpret_cast<std::uintptr_t>(P::CRL) + 4));
        cr = (cr & ~(0xFu << shift)) | (0x2u << shift);   // 推挽 2 MHz
    }
    __attribute__((always_inline)) void high() const { *P::BSRR = mask; }
    __attribute__((always_inline)) void low()  const { *P::BSRR = mask << 16; }
    __attribute__((always_inline)) void toggle() const {
        *P::ODR ^= mask;     // 单核裸机 OK；RTOS/多任务下改用 BSRR + 状态变量
    }
};

// 使用：类型即引脚，编译期就知道地址
GpioOut<PC, 13> led;        // Blue Pill 板载灯（低电平点亮）
int main() {
    for (;;) {
        led.low();  for (volatile int i=0;i<400000;++i){}
        led.high(); for (volatile int i=0;i<400000;++i){}
    }
}
// 编译产物里没有对象、没有构造调用、没有间接跳转：所有函数内联成几条 str 指令。
// 这就是 C++ 的「零开销抽象」，也是嵌入式偏爱模板胜过虚函数的原因。

5.6 输入：按键 + 不阻塞的状态机消抖

按键一般接成「IO — 按键 — GND」，并使能内部上拉：未按时读 1，按下读 0（低电平有效）。千万别让输入浮空。下面这个状态机每 1 ms 被定时器调用一次，既能消抖又能识别长按，全程不阻塞：

// 每 1 ms 调用一次 tick()，返回「刚按下」/「刚松开」/「长按中」事件
class Button {
public:
    explicit Button(bool (*readRaw)()) : read_(readRaw) {}

    enum class Ev { None, Pressed, Released, LongPress };

    Ev tick() {
        const bool pressed_now = !read_();          // 低电平 = 按下
        Ev e = Ev::None;
        if (pressed_now == stable_) {
            counter_ = 0;
        } else if (++counter_ >= 20) {              // 连续 20 ms 一致才认
            stable_  = pressed_now;
            counter_ = 0;
            if (stable_) { e = Ev::Pressed; held_ms_ = 0; }
            else         { e = Ev::Released; }
        }
        if (stable_) {
            held_ms_ += 1;
            if (held_ms_ == 1000) e = Ev::LongPress;   // 长按 1 s 上报一次
        }
        return e;
    }
    bool isDown() const { return stable_; }
private:
    bool (*read_)();          // 函数指针；也可改成模板策略类，编译期内联
    bool     stable_  = false;
    uint16_t counter_ = 0;
    uint16_t held_ms_ = 0;
};

// 用法（STM32 HAL 版）：
// Button btn([]{ return HAL_GPIO_ReadPin(GPIOB, GPIO_PIN_0) == GPIO_PIN_SET; });
// 在 TIM 中断 / SysTick 回调里： if (btn.tick() == Button::Ev::Pressed) { /* 事件 */ }
// 主循环只处理事件，不再 while(等待按键) —— 这就是事件驱动的雏形。

中断 Interrupt事件到来时跳进 ISRµs 级，可预测按键、定时器、串口字节、外部事件
DMA只在开始/结束介入硬件级大批量数据搬运（见第 11 章）

中断的本质是：硬件在满足条件时，把当前 PC 与寄存器压栈，强制跳到向量表里登记的函数地址。执行完 ISR 再出栈回到被中断的代码。对 C++ 程序员来说，它像一个由硬件触发的回调，但有两条硬约束：不能阻塞、不能假设执行上下文。

6.2 NVIC：优先级分组与嵌套

Cortex-M 的 NVIC 用「抢占优先级（preemption）+ 子优先级（subpriority）」两级：

  • 抢占优先级高的中断可以打断正在执行的低优先级 ISR，形成嵌套；
  • 子优先级只在多个中断同时挂起时决定谁先执行，不能打断别人；
  • 优先级数值越小越高（0 最高），用 HAL_NVIC_SetPriorityGrouping(NVIC_PRIORITYGROUP_4) 划分 4 位全给抢占、0 位给子优先级，工程上最省心；
  • PRIMASK 一置位就屏蔽所有可屏蔽中断（__disable_irq()），用来做极短临界区；BASEPRI 可以只屏蔽低于某阈值的中断，FreeRTOS 就是用 BASEPRI 实现临界区而不影响高优先级硬实时中断。
// ===== STM32：EXTI0（PA0 下降沿）中断完整配置 =====

6.3 HardFault：单片机里的「段错误」

没有 MMU、没有操作系统兜底，非法访问会直接跳进 HardFault_Handler（或 MemManage / BusFault / UsageFault）。常见触发：

  • 空指针 / 野指针写寄存器地址（比如外设时钟没开却访问了它的寄存器，某些型号会直接 BusFault）；
  • 数组越界踩到栈或 .data；
  • 栈溢出（大局部数组、递归、RTOS 任务栈给太小）；
  • 非对齐访问（某些架构）、除零（UsageFault）、FPU 未使能却用了浮点；
  • 函数指针被破坏、向量表被写到非法地址。

第 7 章 定时器、PWM 与精确的时间

7.1 时基：PSC / ARR / 更新事件

定时器本质是一个按时钟递增的计数器，配两个寄存器就能定义时间：

计数时钟 f_cnt = f_timer / (PSC + 1)
溢出周期 T     = (ARR + 1) / f_cnt          （向上计数模式）
频率     f     = f_cnt / (ARR + 1)

例：TIM2 时钟 72 MHz（注意第 4 章的 ×2 陷阱），要 1 ms 中断一次：
    PSC = 72 - 1 = 71      → f_cnt = 1 MHz（1 µs 一步）
    ARR = 1000 - 1 = 999   → 每 1000 µs 溢出一次 → 1 kHz

PWM 频率同样由 ARR 决定，占空比由 CCR（捕获比较寄存器）决定：
    duty = CCR / (ARR + 1)
    ARR = 999, CCR = 250 → 25% 占空比，频率 1 kHz

还要分清三个概念：更新事件（Update / 溢出）可触发中断或 DMA；输出比较（OC）在计数等于 CCR 时翻转/置位引脚，就是 PWM；输入捕获（IC）在外部边沿到来时把当前计数值锁存进 CCR，用来测脉宽、频率、解码红外或读编码器。

7.3 输入捕获：测频率与解码

把外部信号接到 TIM_CHx，配置为「上升沿捕获」，每来一个边沿就产生 CCR 值并触发中断。相邻两次 CCR 之差（注意处理计数器回绕）就是周期：f = f_cnt / Δ。若同时测高、低电平时间，还能解出占空比；配合两路相位差 90° 的编码器信号，TIM 的编码器模式能硬件四倍频计数，电机闭环全靠它。ESP32 侧对应的是 PCNT（Pulse Counter） 与 MCPWM 捕获，同样不占用 CPU。

8.3 高效接收：空闲中断 + DMA + 环形缓冲

#define RX_BUF_SZ 256
uint8_t rx_buf[RX_BUF_SZ];

void uart_start_rx(void) {
    __HAL_UART_ENABLE_IT(&huart1, UART_IT_IDLE);            // 空闲中断
    HAL_UART_Receive_DMA(&huart1, rx_buf, RX_BUF_SZ);       // 循环/普通 DMA
}

void USART1_IRQHandler(void) {
    if (__HAL_UART_GET_FLAG(&huart1, UART_FLAG_IDLE)) {
        __HAL_UART_CLEAR_IDLEFLAG(&huart1);
        // 已收字节数 = 缓冲区总长 − DMA 剩余计数（NDTR）

        // ★ ISR 里只做标记，把 rx_buf[0..n) 交给主循环解析（下半部）
        frame_ready = true; frame_len = n;
    }
    HAL_UART_IRQHandler(&huart1);
}

第 9 章 I2C 与 SPI：两根线和四根线

9.1 I2C：开漏 + 上拉 + 地址寻址

I2C（Inter-Integrated Circuit，读「I-squared-C」）只有两根线：SCL 时钟与 SDA 数据，两者都是开漏 + 上拉，因此可以挂多个从设备、支持多主仲裁与时钟拉伸。速率标准模式 100 kHz、快速 400 kHz、高速 3.4 MHz。

9.2 SPI：四根线、全双工、快得多

SPI（Serial Peripheral Interface）是同步、全双工、主从、四线：SCK 时钟、MOSI 主出从入、MISO 主入从出、CS/SS 片选（每个从设备一根）。没有地址、没有 ACK、没有仲裁，靠 CS 选人，所以速度轻松到 10～80 MHz，适合屏幕、Flash、高速 ADC。

第 10 章 ADC / DAC：把连续世界变成数字

10.1 分辨率、参考电压与量化

ADC（Analog-to-Digital Converter）把引脚电压变成整数。核心公式：

code = round( Vin / Vref × (2^N − 1) )
Vin  = code × Vref / (2^N − 1)

12 位 ADC、Vref = 3.3 V：1 LSB = 3.3 / 4095 ≈ 0.806 mV
code = 2048  →  Vin ≈ 1.650 V

★ Vref 比分辨率更重要：很多板子用 VDDA 当参考，
  USB 供电从 4.75 V 掉到 4.5 V 时 LDO 输出纹波会直接反映到读数里。
  精密测量要用外部基准（如 REF3033 / TL431）或芯片内部带隙基准 +
  出厂校准值（STM32 有 VREFINT，ESP32 有 eFuse 校准）。

另外三个必须知道的参数：采样时间（Sampling Time）——内部采样电容需要时间充电，信号源阻抗越大就要设越长；转换时间——SAR ADC 逐次逼近需 N 个时钟；总转换速率——F1 的 ADC 时钟上限 14 MHz，最快约 1 µs/次。ESP32 的 ADC 有两个注意点：ADC2 与 Wi-Fi 共用，Wi-Fi 开启时不能用 ADC2；且片上 ADC 线性度一般，精密测量建议外挂 ADS1115（I2C，16 位）之类。

10.2 分压、滤波与传感器接口

  • 电阻分压：Vout = Vin × R2/(R1+R2)。测 0～12 V 要用 10 kΩ + 2.2 kΩ 之类；注意分压后的源阻抗会拖慢采样电容充电，必要时加电压跟随器（运放）或在分压点并 100 nF。
  • NTC 热敏电阻：与固定电阻分压 → 查表或 Steinhart-Hart 公式换算温度，注意自热效应（别让电流太大）。
  • 抗混叠滤波：ADC 前加 RC 低通，截止频率低于采样率一半，否则高频噪声会「折叠」进读数。
  • 软件滤波：多次取平均、中值滤波剔除毛刺、一阶低通 y = α·x + (1−α)·y_prev，比硬件改板便宜得多。
  • 校准：两点校准（零点 + 满量程）比迷信 datasheet 精度有效得多：real = (code − offset) × gain。

第 11 章 DMA：给 CPU 找个搬运工

12.1 STM32：自己划分 Flash

STM32 片内 Flash 是线性的一块（F103 64 KB，典型页 1 KB）。做 IAP（In-Application Programming，在应用编程）时通常切成三段：

两个必须处理的技术点：

  • 向量表重定向：App 从 0x08004000 开始，中断发生时 CPU 仍会去 0x00000000（映射到 Flash 开头）找向量表。所以 App 启动后要设 SCB->VTOR = 0x08004000，并在 linker script 里把 FLASH ORIGIN 改成新地址。忘了这一步的表现是「程序能跑，一开中断就 HardFault」。
  • Bootloader 跳转：关中断、停外设、把 App 向量表第 0 字设为 MSP、第 1 字设为 Reset_Handler 地址，然后函数指针跳过去。写 Flash 前必须解锁、擦页（只能 1→0 的位要擦成 1）、按半字/字写入、再上锁，且写 Flash 期间不能从同一块 Flash 取指（部分型号会 stall，必要时把擦写函数放到 RAM 执行）。
#define APP_ADDR 0x08004000UL
typedef void (*pfn_t)(void);

void jump_to_app(void) {
    uint32_t msp = *(volatile uint32_t*)APP_ADDR;         // 向量表第 0 字：栈顶
    pfn_t    rst = (pfn_t)*(volatile uint32_t*)(APP_ADDR + 4);
    __disable_irq();
    HAL_DeInit();                                          // 关掉已开的外设/时钟
    __set_MSP(msp);
    SCB->VTOR = APP_ADDR;                                 // ★ 重定向向量表
    rst();                                                // 一去不回
}

12.4 OTA 升级的最小闭环

  1. 设备通过 MQTT/HTTP 拿到固件 URL 与版本号、长度、校验值；
  2. esp_ota_begin(esp_ota_get_next_update_partition(NULL), size, &handle) 开始写备用槽；
  3. 分块下载 → esp_ota_write(handle, chunk, len)，每块校验；
  4. esp_ota_end() → esp_ota_set_boot_partition() → esp_restart()；
  5. 新固件起来后自检通过再调用 esp_ota_mark_app_valid_cancel_rollback()；否则回滚。

第 13 章 FreeRTOS：从 while(1) 到多个任务

裸机程序长到一定程度就会变成「超级循环 + 一堆标志位」：既要 1 ms 采样、又要 500 ms 上报、还要处理按键和串口，任何一处 HAL_Delay 都会拖慢全局。RTOS 的价值不是「更快」，而是让互相无关的时间节奏解耦。ESP32 的 ESP-IDF 天生跑在 FreeRTOS 上；STM32 也能用 CubeMX 一键加 FreeRTOS。

13.1 任务、调度与栈

每个任务是一个永不返回的函数 + 独立的栈 + 一个 TCB（任务控制块）。调度器按优先级抢占：高优先级一旦就绪立刻抢走 CPU；同优先级按时间片轮转。任务有四种基本状态：运行（Running）、就绪（Ready）、阻塞（Blocked）、挂起（Suspended）。只有「阻塞」会让出 CPU——vTaskDelay、等队列、等信号量都是阻塞；纯计算循环会饿死低优先级任务。

// ===== 三个任务，三种节奏，互不干扰 =====
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"
#include "freertos/queue.h"

QueueHandle_t g_samples;       // ADC 采样值队列

void adc_task(void*) {
    for (;;) {
        int v = read_adc();
        xQueueSend(g_samples, &v, 0);           // 不阻塞：满了就丢（或用 0 超时策略）
        vTaskDelay(pdMS_TO_TICKS(1));            // 1 ms 采样
    }
}
void report_task(void*) {
    int v;
    for (;;) {
        if (xQueueReceive(g_samples, &v, portMAX_DELAY) == pdTRUE) {
            ESP_LOGI("REPORT", "value=%d", v);   // 日志慢一点也不会拖慢采样
        }
    }
}
void blink_task(void*) {
    for (;;) {
        gpio_set_level(LED, !gpio_get_level(LED));
        vTaskDelay(pdMS_TO_TICKS(500));          // 500 ms 心跳
    }
}

extern "C" void app_main(void) {
    g_samples = xQueueCreate(32, sizeof(int));
    xTaskCreate(adc_task,    "adc",    3072, nullptr, 5, nullptr);
    xTaskCreate(report_task, "report", 4096, nullptr, 3, nullptr);
    xTaskCreate(blink_task,  "blink",  2048, nullptr, 2, nullptr);
    // app_main 返回后任务仍在跑；ESP-IDF 会自动删除 app_main 任务本身
}

13.4 看门狗与任务健康检查

嵌入式产品必须假设「软件总会卡住」。看门狗（Watchdog）是一个独立定时器，程序必须定期「喂狗」，超时就复位。ESP-IDF 有 Task WDT：默认监控 Idle 任务，可把关键任务 esp_task_wdt_add(NULL) 加入监控；如果某任务死循环不阻塞，Idle 任务吃不到 CPU，WDT 就会触发并打印出到底哪个任务卡住了。STM32 侧有独立看门狗 IWDG（LSI 时钟，完全独立于主时钟）与窗口看门狗 WWDG。调试期可以先关 WDT，量产必须开。

14.2 BLE：GATT 的心智模型

蓝牙低功耗（BLE）在 ESP32 上用 NimBLE / Bluedroid 主机栈。别被一堆缩写吓到，抓住一条主线：GATT Server 暴露一组「服务 → 特征（Characteristic）→ 值」，客户端读写这些特征。

  • GAP 管广播、扫描、连接（设备「被看见」与「连上」）；
  • GATT 管数据组织：Service（UUID）里包含若干 Characteristic，每个特征带属性（读 / 写 / 通知 Notify / 指示 Indicate）；
  • UUID 16 位的是蓝牙联盟标准（如 0x180F 电池服务），自定义功能用 128 位 UUID；
  • Notify / Indicate 是服务器主动推数据（Indicate 需要客户端确认），适合传感器周期上报，比轮询省电；
  • MTU 默认 23 字节，实际有效载荷约 20 字节，协商后可到 517；分包逻辑要自己处理。

典型结构：手机 App 作为 GATT Client 连上 ESP32，订阅温度特征的 Notify，板子每 1 s 用 esp_ble_gatts_send_indicate() 推一次。STM32 本身没有射频，需要外接 HM-10 / nRF52 / ESP32-C3 协处理器，通过 UART AT 指令或自定义帧通信——这正是第 15 章项目 C 的形态。

15.3 项目 C：双板协作——STM32 实时采集 + ESP32 上云

这是把本文两条主线缝在一起的项目，也是工业里非常常见的架构：STM32 负责确定性实时采集与执行，ESP32 负责联网与人机交互，中间用 UART 传结构化帧。为什么要分两块？因为 Wi-Fi 协议栈会带来不可预测的中断与延迟，把精密控制放在同一个核上会被拖抖；分开后各自的时间节奏互不干扰。

// ===== 双板共用：帧协议 + CRC16（可直接两边复制，注意字节序统一小端）=====
#pragma pack(push, 1)
struct Frame {
    uint8_t  head[2];   // 0xAA, 0x55
    uint8_t  len;       // PAYLOAD 长度（不含头/CRC）
    uint8_t  cmd;       // 0x01 采样上行 / 0x10 设置周期 / 0x11 控制继电器
    uint32_t seq;       // 序号，检测丢帧
    int32_t  value;     // 定点化：温度 ×100，避免浮点跨编译器 ABI 差异
    uint16_t crc;       // 从头到 value 的 CRC16/CCITT
};
#pragma pack(pop)

uint16_t crc16_ccitt(const uint8_t* p, size_t n) {
    uint16_t crc = 0xFFFF;
    for (size_t i = 0; i < n; ++i) {
        crc ^= (uint16_t)p[i] << 8;
        for (int b = 0; b < 8; ++b)
            crc = (crc & 0x8000) ? (crc << 1) ^ 0x1021 : (crc << 1);
    }
    return crc;
}

// ===== 接收端：逐字节状态机（ISR/IDLE 之后在任务里跑，不阻塞）=====
enum class St { Head1, Head2, Len, Body, CrcL, CrcH };
class Parser {
public:
    // 返回 true 表示收到一帧完整且 CRC 正确的帧
    bool feed(uint8_t b) {
        switch (st_) {
        case St::Head1: if (b == 0xAA) st_ = St::Head2; break;
        case St::Head2: st_ = (b == 0x55) ? St::Len : St::Head1; break;
        case St::Len:   need_ = b + 2; idx_ = 0; st_ = St::Body; buf_[idx_++] = b; break;
        case St::Body:
            buf_[idx_++] = b;
            if (idx_ >= need_) st_ = St::CrcL;
            break;
        case St::CrcL:  crc_rx_ = b; st_ = St::CrcH; break;
        case St::CrcH: {
            crc_rx_ |= (uint16_t)b << 8;
            bool ok = (crc_rx_ == crc16_ccitt(buf_, need_));
            st_ = St::Head1;
            return ok;
        }
        }
        return false;
    }
    const uint8_t* body() const { return buf_; }
private:
    St      st_ = St::Head1;
    uint8_t buf_[64]{};
    uint8_t need_ = 0, idx_ = 0;
    uint16_t crc_rx_ = 0;
};

第 17 章 从原型到产品：面包板之后的事

面包板能跑 ≠ 能出货。产品化要解决的是一致性、可靠性、可制造性三件事。下面按真实流程过一遍，你不必立刻全做，但要知道每一步在防什么。

17.1 原理图 → PCB：布局比布线更重要

  1. 先锁电源树：输入保护（TVS/保险丝/防反接）→ DC-DC/LDO → 各路电源域；给每路标清电流预算，射频/电机/模拟分开供电或磁珠隔离。
  2. 去耦电容紧贴引脚：100 nF 优先摆在 VDD 引脚同一面、走线「先经过电容再进芯片」；bulk 电容放电源入口。这是第 1 章那条铁律的 PCB 版。
  3. 晶振走线短、包地、下方禁布数字线；负载电容靠近晶振；晶振外壳接地（若 datasheet 要求）。
  4. 地平面尽量完整：不要被信号线切成碎岛；模拟地与数字地常用「单点连接」或统一地平面 + 分区布局，别盲目割地。
  5. 高速/差分线（USB、以太网、SPI Flash、SDIO）做等长、阻抗控制、少打过孔、远离晶振与天线。
  6. 天线净空：ESP32 模组天线区域按 datasheet 做 keep-out，四周不铺铜、不放电池与金属件、外壳别用金属或加喷涂；留 π 型匹配网络以备调试。
  7. 留出可测性：SWD/UART 测试点、GND 测试点、关键电源测试点、Boot/Reset 按键、状态 LED，量产能省大量时间。
  8. DFM：元件间距满足贴片机与返修要求、极性丝印清晰、 Mark 点与工艺边、拼板与 V-cut、避免 0402 以下除非必要。

附录 D　该读哪些官方资料

本文是「地图」，真正做产品时要以官方文档的最新版本为准。按优先级列：

  1. STM32：对应型号的 Datasheet（引脚、电气参数）、Reference Manual（如 F1 的 RM0008，寄存器与功能框图）、UM 用户手册（HAL/LL 驱动说明）、AN 应用笔记（电源、ADC 精度、EMC 设计）、CubeMX / CubeIDE 文档。
  2. ESP32：对应芯片的 Datasheet、Technical Reference Manual、ESP-IDF Programming Guide（组件 API 与示例）、模组 Hardware Design Guidelines（天线净空、电源、推荐布局，画板前必读）、ESP-IDF examples/ 目录里的官方例程。
  3. 内核与 RTOS：ARM 的 Cortex-M3/M4 Devices Generic User Guide、ARMv7-M Architecture Reference Manual；FreeRTOS 官方 Mastering the FreeRTOS Real Time Kernel 与 API 参考。
  4. 器件：任何传感器/屏幕/驱动芯片的 datasheet，重点看「电气特性、时序图、寄存器表、初始化流程」四块，其余按需查。

结语

单片机不是「把 C 语言搬到一块小板子上」，而是用确定性的时序、有限的资源、真实的电压，去兑现代码里的每一个判断。

回顾本文的主线：

  1. 硬件地基让你知道每一行代码最终落在哪颗电阻、哪条走线上（第 1、2 章）；
  2. 内存映射与启动流程把「地址」从抽象概念还原成物理硅片（第 3 章）；
  3. 时钟树解释了所有速率与「明明一样的代码怎么就不对」（第 4 章）；
  4. 中断、DMA、RTOS让 CPU 从忙等里解放出来，学会用事件驱动组织系统（第 6、11、13 章）；
  5. 总线与协议把传感器、屏幕、另一块芯片、云端串成一条数据流（第 8、9、15 章）；
  6. 分区、OTA、调试、量产让「能跑」变成「能交付、能维护」（第 12、16、17 章）。

最后给三条最重要的建议：

  • 先量电压，再改代码：一半以上的「玄学 bug」是没共地、没上拉、没开时钟、供电掉压；
  • 让硬件干硬件的活：精确时序交给定时器/PWM/DMA，业务节奏交给 RTOS，别用空循环硬扛；
  • 把 C++ 的好习惯带过来：RAII 管资源、模板做零开销抽象、状态机替代散落的标志位、编译期能定的事绝不留到运行时——你会写出比多数教程示例更稳的固件。

祝你第一次上电就亮灯，之后的每一次 HardFault 都能查到行号。Happy soldering & happy coding!
