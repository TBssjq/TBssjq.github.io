第一部分 · 基础篇

第 1 章 为什么需要面向对象

1.1 从面向过程到面向对象

面向过程编程把程序看成一系列步骤：数据用结构体装起来，函数负责操作这些数据。

// 面向过程：数据与行为分离
#include <cstdio>
#include <cstring>

struct Student {          // 只有数据
    char name[32];
    int  age;
    double score;
};

// 行为散落在全局函数中
void student_print(const Student* s) {
    printf("%s, %d, %.1f\n", s->name, s->age, s->score);
}

void student_set_score(Student* s, double v) {
    if (v < 0 || v > 100) return;   // 校验逻辑暴露在外面，谁都能绕过
    s->score = v;
}

int main() {
    Student s;
    strcpy(s.name, "Alice");
    s.age = 18;
    s.score = 95.5;
    s.score = 999;                  // 直接改，没有任何约束
    student_print(&s);              // 输出 999，数据已经不合法
}

问题在哪？

  1. 数据可以被任意修改：s.score = 999 无人阻拦，非法状态随时产生。
  2. 函数与数据没有绑定关系：调用者必须自己知道"这个函数是给 Student 用的"。
  3. 命名冲突：全局函数名越来越长（student_xxx、teacher_xxx）。
  4. 修改成本高：一旦 Student 的内部表示变了（比如 char name[32] 改成 std::string），所有操作它的函数都得改。

面向对象把数据和操作数据的行为打包成一个"类"，并对外只暴露必要的接口：

// 面向对象：数据与行为封装在一起
#include <iostream>
#include <string>
#include <stdexcept>

class Student {
public:
    Student(std::string name, int age) : name_(std::move(name)), age_(age) {}

    void set_score(double v) {
        if (v < 0.0 || v > 100.0) throw std::out_of_range("score must be in [0, 100]");
        score_ = v;
    }
    double score() const { return score_; }        // 只读访问
    void   print() const {
        std::cout << name_ << ", " << age_ << ", " << score_ << "\n";
    }
private:
    std::string name_;
    int    age_;
    double score_ = 0.0;
};

int main() {
    Student s("Alice", 18);
    s.set_score(95.5);
    s.print();                 // Alice, 18, 95.5
    // s.score_ = 999;         // 编译错误：private 成员不可访问
    try { s.set_score(999); }  // 运行时抛出异常，非法状态进不来
    catch (const std::out_of_range& e) { std::cout << "拒绝：" << e.what() << "\n"; }
}

核心变化：类成为"不变式（invariant）的守护者"。只要对象存在，它的状态就一定是合法的——这是 OOP 最本质的价值，远比"语法糖"重要。

1.2 面向对象三大支柱

支柱 一句话解释 解决的问题
封装 Encapsulation 隐藏实现细节，只暴露接口 数据被随意改坏；实现变化波及全局
继承 Inheritance 在已有类型基础上扩展，表达"是一种（is-a）"关系 相同逻辑重复写 N 遍
多态 Polymorphism 同一接口，不同实现，运行时决定调用哪个 大量 if/switch 分支判断类型

有些教材会把"抽象（Abstraction）"单列为第四支柱。抽象指的是"只关注对象能做什么，不关心怎么做"，它往往通过抽象类/接口体现，本文在第 8 章详细展开。

1.3 一个直观的多态例子

假设要写一个绘图程序，支持圆形、矩形、三角形，未来还要加椭圆、多边形……

不用多态（每加一种图形就要改这个函数）：

void draw_all(const std::vector<Shape>& shapes) {
    for (const auto& s : shapes) {
        if (s.type == ShapeType::Circle)       draw_circle(s);
        else if (s.type == ShapeType::Rect)    draw_rect(s);
        else if (s.type == ShapeType::Triangle)draw_triangle(s);
        // 每新增一种图形，这里都要加一个分支
    }
}

用多态（新增图形时，这个函数一行都不用改）：

struct Shape {
    virtual ~Shape() = default;
    virtual void draw() const = 0;   // 纯虚函数：接口
    virtual double area() const = 0;
};

void draw_all(const std::vector<std::unique_ptr<Shape>>& shapes) {
    for (const auto& s : shapes) s->draw();   // 调用哪个 draw？运行时决定
}

这就是所谓的"对扩展开放，对修改关闭"（开闭原则）。第 8 章会把这个例子完整实现。

1.4 C++ 的 OOP 哲学：不为抽象付费

C++ 与 Java/C# 的一个重要区别：C++ 不强迫你把所有东西都塞进类里。

  • 不需要运行时多态时，就用普通函数、模板——零额外开销；
  • 需要运行时多态时才用 virtual——付出一次间接寻址的代价。

这条"你只为你使用的东西付费（zero-overhead principle）"贯穿整个 C++ 设计，也是 C++ 能同时胜任系统级编程和高层抽象的原因。

一个提醒：不要为了"看起来像面向对象"而滥用继承。C++ 中优秀的库（如 STL）大量使用值语义 + 模板而非继承体系。判断标准很简单：如果类之间确实是"是一种"的关系且需要运行时替换，用继承 + 虚函数；否则优先考虑组合与模板。

第 2 章 类与对象

2.1 类的定义与访问控制

class ClassName {
public:      // 公有：外部可以访问，构成类的"接口"
    ...
protected:   // 保护：派生类可以访问，外部不能（第 7 章详解）
    ...
private:     // 私有：只有本类的成员函数和友元可以访问（默认）
    ...
};           // 注意这个分号，忘了是经典编译错误

一个完整的例子：银行账户

#include <iostream>
#include <string>
#include <stdexcept>

class BankAccount {
public:
    // 构造：开户
    BankAccount(std::string owner, double init = 0.0)
        : owner_(std::move(owner)) {
        if (init < 0) throw std::invalid_argument("初始余额不能为负");
        balance_ = init;
    }

    // 接口：存款、取款、查询
    void deposit(double amount) {
        if (amount <= 0) throw std::invalid_argument("存款必须为正");
        balance_ += amount;
        log("deposit");
    }

    bool withdraw(double amount) {
        if (amount <= 0)      throw std::invalid_argument("取款必须为正");
        if (amount > balance_) return false;
        balance_ -= amount;
        log("withdraw");
        return true;
    }

    double      balance() const { return balance_; }   // const 成员函数：不修改对象
    const std::string& owner() const { return owner_; }

private:
    void log(const char* op) const {           // 实现细节，外部无需知道
        std::cout << "[" << op << "] " << owner_ << " 余额 " << balance_ << "\n";
    }

    std::string owner_;
    double balance_ = 0.0;
};

int main() {
    BankAccount acc("张三", 1000);
    acc.deposit(500);
    acc.withdraw(200);
    std::cout << acc.balance() << "\n";     // 1300
    // acc.balance_ = 1e9;                  // 编译错误
    // acc.log("hack");                     // 编译错误
}

要点：

  1. public 放前面（接口优先，读代码的人先看到怎么用），private 放后面；
  2. 成员变量几乎总是 private，通过成员函数访问——这叫数据隐藏；
  3. 只读的成员函数加 const，这样 const 对象也能调用（见 2.5）。

2.2 class 与 struct 的区别

只有默认访问权限不同：

关键字 默认成员访问权限 默认继承方式
class private private
struct public public 
struct Point { int x; int y; };             // 等价于 public: int x; int y;
class  Point2 { int x; int y; };            // x, y 都是 private

惯例：

  • struct：用于纯数据聚合（POD/aggregate），没有不变式需要维护，如 Point、Config；
  • class：用于有行为、有不变式、需要封装的类型，如 BankAccount、String。
struct Point { double x = 0, y = 0; };      // 数据聚合，用 struct 很自然

class Vec2 {                                 // 有不变式（长度 >= 0）、有行为，用 class
public:
    Vec2(double x, double y) : x_(x), y_(y) {}
    double length() const { return std::sqrt(x_ * x_ + y_ * y_); }
private:
    double x_, y_;
};

2.3 对象的创建与生命周期

class Foo { public: Foo() { std::cout << "构造\n"; }
                    ~Foo() { std::cout << "析构\n"; } };

int main() {
    Foo a;                       // 栈对象：离开作用域自动析构
    {
        Foo b;                   // 内层作用域
    }                            // b 在这里析构（后进先出）
    Foo* p = new Foo;            // 堆对象：手动 new
    delete p;                    // 必须手动 delete，否则泄漏
                                 // 现代 C++ 应优先用 std::make_unique（第 11 章）
}                                // a 在这里析构

四种常见对象：

类别 存储期 创建方式 销毁
局部对象（栈） 自动 Foo a; 离开作用域自动析构
全局/静态对象 静态 static Foo g; main 结束前后析构
堆对象 动态 new Foo delete（或智能指针）
临时对象 自动 表达式中间结果 完整表达式结束时析构

C++ 核心习惯：优先使用栈对象（值语义）。栈对象析构时机确定，天然异常安全，也不需要记忆 delete。

2.4 成员函数的定义位置：类内 vs 类外

// Vec2.h
#pragma once
class Vec2 {
public:
    Vec2(double x, double y);
    double length() const;          // 声明
    double dot(const Vec2& rhs) const {
        return x_ * rhs.x_ + y_ * rhs.y_;   // 类内定义 = 隐式 inline
    }
private:
    double x_, y_;
};

// Vec2.cpp
#include "Vec2.h"
#include <cmath>
Vec2::Vec2(double x, double y) : x_(x), y_(y) {}       // 类外定义要加 Vec2::
double Vec2::length() const { return std::sqrt(x_ * x_ + y_ * y_); }
  • 类内定义的函数隐含 inline（只是建议，编译器可忽略）；
  • 短小、频繁调用的函数（getter、运算符）适合放类内；
  • 把实现放到 .cpp 可以减少编译依赖、加快编译、隐藏实现（也是"物理封装"的一部分）。

2.5 this 指针与 const 成员函数

每个非静态成员函数都有一个隐藏参数 this，指向调用该函数的对象：

class Counter {
public:
    Counter& inc() { ++count_; return *this; }   // 返回 *this 支持链式调用
    Counter& inc(int n) { count_ += n; return *this; }
    int count() const { return count_; }         // 等价于：int count(const Counter* this)
private:
    int count_ = 0;
};

Counter c;
c.inc().inc().inc(5);
std::cout << c.count();   // 7

const 成员函数：在函数声明后加 const，表示不修改对象状态。其本质是 this 类型从 T* 变成 const T*。

class Text {
public:
    char at(size_t i) const { return data_[i]; }   // const 对象也能调用
    void set(size_t i, char c) { data_[i] = c; }   // 非 const
private:
    std::string data_;
};

const Text t("hello");
t.at(0);      // OK
// t.set(0,'H');  // 编译错误：const 对象不能调用非 const 成员函数

规则：能加 const 的成员函数就加 const。 这既是文档（告诉调用者"我不会改对象"），也让 const 对象可用。

mutable 关键字：允许在 const 成员函数中修改某个成员（常用于缓存、互斥锁）：

class Expensive {
public:
    double value() const {
        if (!cached_) {             // 即使在 const 函数中也能改
            cache_ = compute();
            cached_ = true;
        }
        return cache_;
    }
private:
    double compute() const;
    mutable double cache_;
    mutable bool   cached_ = false;
};

2.6 对象的内存布局（入门版）

理解内存布局能帮你避开很多坑：

class Empty {};                        // sizeof(Empty) == 1（不允许两个对象同地址）
class A { int x; };                    // sizeof == 4
class B { int x; double d; };          // sizeof == 16（8 字节对齐 + 4 字节 padding）
class C { virtual void f(); int x; };  // sizeof == 16（8 字节 vptr + 4 字节 int + padding）

关键事实：

  1. 成员函数不占对象空间：所有对象共享同一份函数代码，靠 this 区分；
  2. 成员变量按声明顺序排列，编译器可能插入 padding 做内存对齐；
  3. 虚函数会给对象加一个虚表指针（vptr），通常 8 字节（64 位）——这是多态的成本（第 8 章详解）。

可以用工具观察布局：clang++ -Xclang -fdump-record-layouts -fsyntax-only file.cpp。

2.7 前向声明与 Pimpl 惯用法

为了减少头文件耦合，可以只声明类型而不定义：

// widget.h —— 客户端只看到接口
#pragma once
#include <memory>
class Impl;                 // 前向声明：不完整类型

class Widget {
public:
    Widget();
    ~Widget();              // 必须在 .cpp 中定义（因为 unique_ptr<Impl> 析构需要完整类型）
    void do_work();
private:
    std::unique_ptr<Impl> pImpl_;   // Pimpl：pointer to implementation
};
// widget.cpp
#include "widget.h"
#include <iostream>
class Impl {                 // 实现细节完全隐藏
public: void do_work() { std::cout << "work\n"; }
};
Widget::Widget()  : pImpl_(std::make_unique<Impl>()) {}
Widget::~Widget() = default;
void Widget::do_work() { pImpl_->do_work(); }

好处：修改 Impl 不需要重新编译所有包含 widget.h 的文件（大型项目编译提速神器）；头文件也不会泄漏私有依赖。

第 3 章 构造函数与析构函数

构造函数负责建立对象的不变式，析构函数负责释放资源。这是 C++ 资源管理（RAII）的基石。

3.1 构造函数的基本形式

class Date {
public:
    Date() = default;                             // ① 默认构造函数
    Date(int y, int m, int d) : y_(y), m_(m), d_(d) {}  // ② 带参构造（初始化列表）
    Date(int y) : Date(y, 1, 1) {}                // ③ 委托构造（C++11）
private:
    int y_ = 1970, m_ = 1, d_ = 1;                // ④ 类内默认值（C++11）
};

如果没有写任何构造函数，编译器会合成一个默认构造函数，它：

  • 对类类型成员调用其默认构造；
  • 对内置类型成员不做初始化（值是随机的！）。

所以务必给内置类型成员写类内默认值（④）。

3.2 初始化列表 vs 构造函数体内赋值

class Good {
public:
    Good(std::string n, int v) : name_(std::move(n)), value_(v) {}   // 推荐：直接初始化
private:
    std::string name_;
    int value_;
};

class Bad {
public:
    Bad(std::string n, int v) { name_ = std::move(n); value_ = v; }  // 先默认构造再赋值，多一次操作
private:
    std::string name_;
    int value_;
};

必须用初始化列表的三种情况（否则编译错误或行为错误）：

class Must {
public:
    Must(int v) : someInt_(v), ref_(someInt_), c_(v) {}  // ① 引用成员 ② const 成员
private:                                                 // ③ 没有默认构造的成员
    int someInt_ = 0;
    int& ref_;
    const int c_;
};

成员初始化顺序 = 声明顺序，与初始化列表中的书写顺序无关：

class Trap {
public:
    Trap(int v) : b_(v), a_(b_) {}    // 实际先初始化 a_（读到未初始化的 b_！）
                                      // gcc -Wall 会警告 -Wreorder
private:
    int a_, b_;                        // 声明顺序决定初始化顺序
};

3.3 构造函数的种类与调用时机

class String {
public:
    String() = default;                                   // 默认构造
    explicit String(const char* s);                        // 转换构造（explicit 阻止隐式转换）
    String(size_t n, char c);                              // 普通构造
    String(const String& rhs);                             // 拷贝构造
    String(String&& rhs) noexcept;                         // 移动构造（C++11，第 10 章）
    String& operator=(const String& rhs);                  // 拷贝赋值
    String& operator=(String&& rhs) noexcept;              // 移动赋值
    ~String();                                             // 析构
};

各种写法对应的调用（极其重要，面试高频）：

String s1;                    // 默认构造
String s2("hello");           // 转换构造（直接初始化）
String s3 = "hello";          // 若有 explicit 则编译错误；否则等价于 String s3("hello")
String s4 = s2;               // 拷贝构造（不是赋值！）
String s5(s2);                // 拷贝构造
String s6 = std::move(s2);    // 移动构造
s1 = s4;                      // 拷贝赋值（s1 已存在）
s1 = String("tmp");           // 移动赋值
String s7{};                  // 默认构造（s7() 会被解析成函数声明！小心 most vexing parse）

3.4 explicit：禁止隐式转换

class Vec {
public:
    explicit Vec(int n) : data_(n, 0) {}     // 加 explicit
};

void f(Vec v);
f(10);            // 若无 explicit：编译通过（10 隐式转成 Vec(10)）—— 通常是 bug
                  // 有 explicit：编译错误，必须写 f(Vec(10)) 或 f(Vec{10})

建议：所有单参数构造函数都加 explicit，除非你确实想要隐式转换（如 std::string 接受 const char*）。C++20 起 explicit(bool) 支持条件 explicit。

3.5 拷贝构造函数：深拷贝 vs 浅拷贝

这是 OOP 入门最容易踩的坑。自己管理资源的类必须写拷贝构造：

// 错误示范：编译器合成的版本只做浅拷贝（逐字节复制指针）
class BadBuffer {
public:
    BadBuffer(size_t n) : size_(n), data_(new int[n]) {}
    ~BadBuffer() { delete[] data_; }
    // 没写拷贝构造和拷贝赋值 —— 灾难
private:
    size_t size_;
    int* data_;
};

BadBuffer a(10);
BadBuffer b = a;      // 浅拷贝：a.data_ 和 b.data_ 指向同一块内存
// 离开作用域：析构两次 → double free → 程序崩溃
// 正确示范
class Buffer {
public:
    explicit Buffer(size_t n) : size_(n), data_(n ? new int[n] : nullptr) {}

    ~Buffer() { delete[] data_; }

    Buffer(const Buffer& rhs)                        // 深拷贝
        : size_(rhs.size_), data_(rhs.size_ ? new int[rhs.size_] : nullptr) {
        std::copy(rhs.data_, rhs.data_ + rhs.size_, data_);
    }

    Buffer& operator=(const Buffer& rhs) {           // 拷贝赋值：注意自赋值 + 异常安全
        if (this != &rhs) {
            Buffer tmp(rhs);      // copy-and-swap：先造副本
            swap(tmp);            // 再交换（不抛异常）
        }                         // tmp 析构释放旧资源
        return *this;
    }

    Buffer(Buffer&& rhs) noexcept                    // 移动构造：偷资源
        : size_(rhs.size_), data_(rhs.data_) {
        rhs.size_ = 0; rhs.data_ = nullptr;
    }

    Buffer& operator=(Buffer&& rhs) noexcept {       // 移动赋值
        if (this != &rhs) {
            delete[] data_;
            size_ = rhs.size_; data_ = rhs.data_;
            rhs.size_ = 0; rhs.data_ = nullptr;
        }
        return *this;
    }

    void swap(Buffer& o) noexcept { std::swap(size_, o.size_); std::swap(data_, o.data_); }
    size_t size() const { return size_; }
    int& operator[](size_t i) { return data_[i]; }
private:
    size_t size_ = 0;
    int*   data_ = nullptr;
};

copy-and-swap 技巧是写拷贝赋值的黄金套路：天然处理自赋值，且提供强异常安全保证。

3.6 析构函数

规则：

  1. 名字是 ~类名，无参数、无返回值、不能重载；
  2. 析构函数不应该抛异常（若在栈展开时抛出，std::terminate 直接终止程序）。C++11 起析构函数默认 noexcept；
  3. 基类若有派生类，析构函数必须是 virtual（第 8 章）；
  4. 析构顺序：先执行函数体，再按声明的逆序析构成员。
class File {
public:
    explicit File(const char* path) : fp_(std::fopen(path, "r")) {
        if (!fp_) throw std::runtime_error("open failed");   // 构造失败 = 抛异常
    }
    ~File() { if (fp_) std::fclose(fp_); }                   // 保证关闭
    File(const File&) = delete;                              // 禁止拷贝（文件句柄不可共享）
    File& operator=(const File&) = delete;
private:
    FILE* fp_;
};

RAII（Resource Acquisition Is Initialization）：资源获取即初始化——在构造函数中拿资源，在析构函数中释放。这样只要对象正常离开作用域，资源一定被释放，即使中间抛异常。这是 C++ 最核心的设计哲学（第 11 章展开）。

3.7 构造/析构的调用顺序（继承场景）

#include <iostream>
struct A { A() { std::cout << "A()\n"; }  ~A() { std::cout << "~A()\n"; } };
struct B { B() { std::cout << "B()\n"; }  ~B() { std::cout << "~B()\n"; } };

struct C : A {
    C() { std::cout << "C()\n"; }
    ~C() { std::cout << "~C()\n"; }
private:
    B b_;            // 成员对象
};

int main() { C c; }
// 输出：A() → B() → C() → ~C() → ~B() → ~A()

顺序总结：

  • 构造：基类 → 成员（按声明顺序）→ 派生类自己的函数体；
  • 析构：完全相反（派生类函数体 → 成员逆序 → 基类）。

因此：不要在构造函数中调用虚函数（此时派生类部分还没构造完，虚调用不会走到派生类版本，见 8.6）。

3.8 = default 与 = delete（C++11）

class NonCopyable {
public:
    NonCopyable() = default;                              // 显式要求编译器生成默认版本
    NonCopyable(const NonCopyable&) = delete;             // 明确禁止拷贝
    NonCopyable& operator=(const NonCopyable&) = delete;
    NonCopyable(NonCopyable&&) = default;                 // 允许移动
};

= delete 可以用于任何函数，甚至非成员函数，用来禁止不想要的重载：

void f(int);
void f(double) = delete;    // f(3.14) 编译错误
f(1);                       // OK

3.9 聚合初始化与指定初始化器（C++20）

struct Point { double x; double y; std::string label; };

Point p1{1.0, 2.0, "origin"};              // 聚合初始化
Point p2{.x = 1.0, .y = 2.0, .label = "A"};// C++20 指定初始化器（顺序必须与声明一致）

第 4 章 拷贝控制与三/五法则

4.1 什么是拷贝控制

拷贝控制指控制对象复制、移动、赋值、销毁行为的一组成员函数：

class T {
public:
    T();                              // 默认构造
    ~T();                             // 析构
    T(const T&);                      // 拷贝构造
    T& operator=(const T&);           // 拷贝赋值
    T(T&&) noexcept;                  // 移动构造（C++11）
    T& operator=(T&&) noexcept;       // 移动赋值（C++11）
};

4.2 Rule of Three（三法则，C++98）

如果你需要显式定义析构函数、拷贝构造函数、拷贝赋值运算符中的任意一个，那么三个都应该显式定义。

原因：需要自定义析构 ⇒ 类在管理资源 ⇒ 合成的拷贝会做浅拷贝 ⇒ 必须自己写深拷贝。

4.3 Rule of Five（五法则，C++11）

C++11 引入移动语义后扩展为五个：析构、拷贝构造、拷贝赋值、移动构造、移动赋值。

五个特殊成员函数：定义了其中一个，就应该考虑全部五个。

class String {
public:
    String() = default;
    explicit String(const char* s) { assign(s, std::strlen(s)); }
    ~String() { delete[] data_; }                             // ① 析构

    String(const String& rhs) { assign(rhs.data_, rhs.size_); } // ② 拷贝构造
    String& operator=(const String& rhs) {                      // ③ 拷贝赋值
        if (this != &rhs) assign(rhs.data_, rhs.size_);
        return *this;
    }
    String(String&& rhs) noexcept                               // ④ 移动构造
        : data_(rhs.data_), size_(rhs.size_) {
        rhs.data_ = nullptr; rhs.size_ = 0;
    }
    String& operator=(String&& rhs) noexcept {                  // ⑤ 移动赋值
        if (this != &rhs) {
            delete[] data_;
            data_ = rhs.data_; size_ = rhs.size_;
            rhs.data_ = nullptr; rhs.size_ = 0;
        }
        return *this;
    }

    const char* c_str() const { return data_ ? data_ : ""; }
    size_t size() const { return size_; }
private:
    void assign(const char* s, size_t n) {
        delete[] data_;
        data_ = new char[n + 1];
        std::memcpy(data_, s, n);
        data_[n] = '\0';
        size_ = n;
    }
    char*  data_ = nullptr;
    size_t size_ = 0;
};

4.4 Rule of Zero（零法则，现代 C++ 首选）

最好的拷贝控制是不写拷贝控制。 用标准库的资源管理类（std::string、std::vector、std::unique_ptr）做成员，编译器生成的默认版本就是正确的。

// 零法则：不需要写任何特殊成员函数
class Person {
public:
    Person(std::string name, std::vector<std::string> tags)
        : name_(std::move(name)), tags_(std::move(tags)) {}
private:
    std::string              name_;   // 自己管内存
    std::vector<std::string> tags_;   // 自己管内存
};  // 拷贝、移动、赋值、析构全部正确，且性能优秀
// 需要自定义析构时，把资源交给 unique_ptr，仍然可以是"零法则"
class Connection {
public:
    ~Connection() = default;                 // 什么都不用写
private:
    std::unique_ptr<Socket> sock_;           // 自动释放
    std::vector<char>       buffer_;
};

优先级：Rule of Zero > Rule of Five > Rule of Three。

4.5 编译器何时合成/删除特殊成员函数

你声明了 编译器还合成默认构造吗 还合成拷贝吗 还合成移动吗
任何构造函数 ❌ 不再合成默认构造 ✅ 视情况
拷贝构造/拷贝赋值/析构（三法则之一） — ✅（已废弃但仍生成） ❌ 不再合成移动
移动构造/移动赋值 ❌ 默认构造不再合成 ❌ 拷贝被 delete —

重要推论：给类加了析构函数（~T();）之后，移动构造/移动赋值不会被合成，于是"移动"退化成"拷贝"——这是很多性能问题的隐秘来源。要么遵循五法则补全移动，要么遵循零法则干脆不写析构。

4.6 拷贝 vs 移动：什么时候发生

String make() { return String("hello"); }   // 返回值优化（RVO），甚至不发生拷贝/移动

String a = make();        // C++17 起： guaranteed copy elision，直接构造，零开销
String b = a;             // 拷贝构造（a 是左值）
String c = std::move(a);  // 移动构造（把 a 转成右值；之后 a 处于"有效但未指定"状态，不应再依赖其内容）
std::vector<String> v;
v.push_back(c);                    // 拷贝一份进去
v.push_back(std::move(c));         // 移动进去，c 变空

移动的价值：把"分配内存 + 复制 N 个字节"变成"复制一个指针"。对 std::vector<String> 这类容器，性能差异巨大。

4.7 一个小测：你能看出输出吗？

#include <iostream>
struct Probe {
    Probe()                       { std::cout << "默认构造\n"; }
    Probe(const Probe&)           { std::cout << "拷贝构造\n"; }
    Probe(Probe&&) noexcept       { std::cout << "移动构造\n"; }
    Probe& operator=(const Probe&){ std::cout << "拷贝赋值\n"; return *this; }
    Probe& operator=(Probe&&) noexcept { std::cout << "移动赋值\n"; return *this; }
    ~Probe()                      { std::cout << "析构\n"; }
};

Probe make() { Probe p; return p; }        // 注意：NRVO

int main() {
    Probe a;                 // 默认构造
    Probe b = a;             // 拷贝构造
    Probe c = make();        // 通常只输出"默认构造"（NRVO 优化掉了拷贝/移动）
    a = std::move(b);        // 移动赋值
}

用 -fno-elide-constructors 编译可以看到"未优化"时的完整调用序列，是理解这一章的好工具。

第二部分 · 核心机制篇

第 5 章 静态成员、const 与友元

5.1 静态成员变量

静态成员属于类本身，不属于任何对象，被所有对象共享。

#include <iostream>
#include <string>

class Student {
public:
    Student(std::string name) : name_(std::move(name)) { ++count_; }
    ~Student() { --count_; }
    static int count() { return count_; }        // 静态成员函数：无 this 指针
private:
    std::string name_;
    static int count_;                            // 类内声明
};

int Student::count_ = 0;                          // 类外定义（C++17 前必须）

int main() {
    std::cout << Student::count() << "\n";   // 0，无需对象即可访问
    { Student a("A"), b("B");
      std::cout << Student::count() << "\n"; // 2
    }
    std::cout << Student::count() << "\n";   // 0
}

C++17 起可用 inline static 直接在类内定义，省掉类外定义：

class Config {
public:
    inline static int max_connections = 100;      // C++17：类内即定义
    inline static const std::string name = "app";
};

静态成员函数的特点：

  • 没有 this，不能访问非静态成员，不能是 const、virtual；
  • 可以通过 对象.静态函数() 调用，但推荐 类名::静态函数()。

5.2 静态成员实战：对象计数器与单例模式雏形

template <typename T>
class Counter {                        // CRTP 风格的对象计数（第 9 章讲 CRTP）
public:
    Counter()  { ++created_; ++alive_; }
    ~Counter() { --alive_; }
    static int created() { return created_; }
    static int alive()   { return alive_; }
protected:
    Counter(const Counter&) { ++created_; ++alive_; }
private:
    inline static int created_ = 0;
    inline static int alive_   = 0;
};

class Widget : public Counter<Widget> {};    // 每个 Widget 自动带计数能力

Widget a, b;
std::cout << Widget::alive();     // 2

5.3 const 的全方位用法

const 是 C++ 里最容易被低估的关键字。位置不同，含义不同：

const int* p1;        // 指向常量的指针：不能通过 p1 改值，但 p1 可以指向别处
int const* p2;        // 同 p1（写法不同）
int* const p3 = &x;   // 常量指针：p3 不能再指向别处，但可以通过它改值
const int* const p4;  // 两者都不可变

int const& r = x;     // 常量引用（常用于函数参数）

记忆口诀：const 修饰它左边的东西；左边没东西才修饰右边。

在函数签名中：

class Data {
public:
    const std::string& name() const;      // 返回 const 引用 + 不修改对象（最佳 getter 写法）
    void   setName(const std::string& n); // const 引用参数：避免拷贝又不夺取所有权
    int    size() const noexcept;         // const + noexcept
private:
    std::string name_;
};

const 成员函数返回引用时要小心悬垂引用：

const std::string& bad_name() const {
    std::string tmp = name_ + "!";
    return tmp;                 // 灾难：返回局部对象的引用，函数返回后 tmp 已销毁
}

5.4 顶层 const 与底层 const（拷贝时的关键区别）

int x = 10;
const int cx = 20;

int* p1 = &cx;              // 错误：const int* 不能转成 int*
const int* p2 = &cx;        // OK

// 拷贝时，顶层 const（对象本身是 const）会被忽略
int a = cx;                 // OK，拷贝的是值

这条规则直接解释了为什么拷贝构造参数是 const T& 而不是 T&：

String(const String& rhs);        // 只能绑定非 const 左值，const 对象拷不了
String(const String& rhs);        // 正确写法，可绑定 const 与非 const、左值与右值

5.5 友元：有节制地打破封装

友元允许指定的函数/类访问本类的私有成员。

class Vector3 {
public:
    Vector3(double x = 0, double y = 0, double z = 0) : x_(x), y_(y), z_(z) {}

    // 友元函数：定义在类内，但是非成员函数（无 this）
    friend Vector3 operator+(const Vector3& a, const Vector3& b) {
        return {a.x_ + b.x_, a.y_ + b.y_, a.z_ + b.z_};
    }
    friend std::ostream& operator<<(std::ostream& os, const Vector3& v) {
        return os << '(' << v.x_ << ", " << v.y_ << ", " << v.z_ << ')';
    }
    friend class VectorInspector;    // 友元类：整个类都能访问私有成员
private:
    double x_, y_, z_;
};

Vector3 a(1, 2, 3), b(4, 5, 6);
std::cout << a + b;      // (5, 7, 9)

要点：

  1. 友元关系是单向的、不可传递的、不可继承的；
  2. 友元破坏了封装，只应在"确实是这个类的一部分"时使用（典型：运算符重载、swap、迭代器与容器的配对、Builder 模式）；
  3. 优先用成员函数实现功能，只有必须让左侧操作数不是本类对象（如 ostream << v）时才用非成员友元。

5.6 隐藏友元（Hidden Friend）技巧（C++ 现代惯用法）

class Point {
public:
    friend bool operator==(const Point& a, const Point& b) {
        return a.x_ == b.x_ && a.y_ == b.y_;
    }
    friend void swap(Point& a, Point& b) noexcept {
        using std::swap; swap(a.x_, b.x_); swap(a.y_, b.y_);
    }
private:
    int x_, y_;
};

好处：这类函数只能通过 ADL（实参依赖查找）找到，不污染全局命名空间，也不会参与隐式转换导致的意外匹配。C++20 的 operator<=>、operator== 推荐这样写。

第 6 章 运算符重载

运算符重载让你自定义的类型能像内置类型一样使用，是 C++ 写出"优雅代码"的关键。

6.1 基本规则

  • 不能创造新运算符（如 **、@）；
  • 不能改变优先级、结合性、操作数个数；
  • 至少一个操作数必须是用户定义类型（不能重载 int + int）；
  • 不能重载的运算符：::、.、.*、?:、sizeof、typeid、#、##；
  • =、[]、()、-> 必须是成员函数；
  • 左操作数需要隐式转换的（如 2 + v）必须是非成员函数。

6.2 算术运算符：+、-、*

class Vec2 {
public:
    Vec2(double x = 0, double y = 0) : x_(x), y_(y) {}

    Vec2& operator+=(const Vec2& rhs) { x_ += rhs.x_; y_ += rhs.y_; return *this; }
    Vec2& operator-=(const Vec2& rhs) { x_ -= rhs.x_; y_ -= rhs.y_; return *this; }
    Vec2& operator*=(double k)        { x_ *= k;      y_ *= k;      return *this; }

    Vec2 operator-() const { return {-x_, -y_}; }            // 一元负号
    bool operator==(const Vec2& rhs) const { return x_ == rhs.x_ && y_ == rhs.y_; }
    bool operator!=(const Vec2& rhs) const { return !(*this == rhs); }

    friend Vec2 operator+(Vec2 lhs, const Vec2& rhs) { lhs += rhs; return lhs; }
    friend Vec2 operator-(Vec2 lhs, const Vec2& rhs) { lhs -= rhs; return lhs; }
    friend Vec2 operator*(Vec2 lhs, double k)        { lhs *= k;   return lhs; }
    friend Vec2 operator*(double k, Vec2 lhs)        { lhs *= k;   return lhs; }  // 支持 2 * v
private:
    double x_, y_;
};

Vec2 a(1, 2), b(3, 4);
Vec2 c = a + b * 2;      // (7, 10)
Vec2 d = 2 * b;          // 需要非成员版本

推荐模式：把 += 写成成员函数（修改自身，返回引用），把 + 写成非成员函数（按值接收左操作数，调用 +=，返回新对象）。这样代码复用、语义正确、性能也好（NRVO）。

6.3 比较运算符与 C++20 三路比较

C++17 及以前要手写 6 个比较运算符；C++20 只需 <=> 和 ==：

#include <compare>
class Version {
public:
    Version(int major, int minor) : major_(major), minor_(minor) {}

    // C++20：一个 <=> 生成 <、>、<=、>=
    auto operator<=>(const Version& rhs) const = default;   // 默认按成员字典序比较
    bool operator==(const Version& rhs) const  = default;
private:
    int major_, minor_;      // 比较顺序 = 声明顺序
};

Version a{1, 2}, b{1, 3};
a < b;   a >= b;   a == b;   // 全部可用

自定义比较逻辑时：

// 按字符串长度比较
auto operator<=>(const Name& rhs) const { return len_ <=> rhs.len_; }

返回值类型：std::strong_ordering（全序）、std::weak_ordering（等价但可区分）、std::partial_ordering（可能不可比较，如浮点 NaN）。

6.4 赋值运算符

class Matrix {
public:
    Matrix& operator=(const Matrix& rhs) {       // 返回非 const 引用，支持链式 a = b = c
        if (this != &rhs) { /* 深拷贝 */ }
        return *this;
    }
    Matrix& operator=(Matrix&& rhs) noexcept { /* 移动 */ return *this; }
    Matrix& operator+=(const Matrix& rhs);
};

注意：赋值运算符必须是成员函数，且要处理自赋值（a = a）。

6.5 下标运算符与函数调用运算符

class IntArray {
public:
    explicit IntArray(size_t n) : data_(n) {}

    int& operator[](size_t i) {                     // 非 const 版本：可写
        if (i >= data_.size()) throw std::out_of_range("index");
        return data_[i];
    }
    const int& operator[](size_t i) const {         // const 版本：只读
        return data_[i];
    }
    size_t size() const { return data_.size(); }
private:
    std::vector<int> data_;
};

IntArray a(5);
a[0] = 42;                     // 调用非 const 版本
const IntArray& ca = a;
// ca[0] = 1;                  // 编译错误，调用 const 版本

函数调用运算符（仿函数 Functor）——让对象像函数一样被调用，是 STL 算法的核心：

class Multiplier {
public:
    explicit Multiplier(int k) : k_(k) {}
    int operator()(int x) const { return x * k_; }      // 可以有状态！
private:
    int k_;
};

Multiplier times3(3);
std::cout << times3(7);        // 21

std::vector<int> v{1, 2, 3};
std::transform(v.begin(), v.end(), v.begin(), Multiplier(10));   // {10, 20, 30}

相比函数指针，仿函数可携带状态且可内联，性能更好。C++11 后 lambda 本质就是编译器生成的仿函数（见 13.4）。

6.6 自增/自减：前置与后置的区别

class Iterator {
public:
    Iterator& operator++() {        // 前置 ++i：返回引用
        ++index_;
        return *this;
    }
    Iterator operator++(int) {      // 后置 i++：占位参数 int，返回旧值的副本
        Iterator tmp = *this;
        ++(*this);
        return tmp;
    }
    Iterator& operator--();
    Iterator  operator--(int);
private:
    size_t index_ = 0;
};

为什么前置更快：后置版本要构造并返回一个临时对象。所以在不需要旧值的场景（for 循环的自增），一律写 ++it。

6.7 流插入/提取运算符

必须是非成员函数（左操作数是 std::ostream）：

class Date {
public:
    Date(int y, int m, int d) : y_(y), m_(m), d_(d) {}
    friend std::ostream& operator<<(std::ostream& os, const Date& dt) {
        return os << dt.y_ << '-' << std::setfill('0') << std::setw(2) << dt.m_
                  << '-' << std::setw(2) << dt.d_;
    }
    friend std::istream& operator>>(std::istream& is, Date& dt) {
        char dash;
        is >> dt.y_ >> dash >> dt.m_ >> dash >> dt.d_;
        if (!is) dt = Date(1970, 1, 1);      // 输入失败时重置，避免半初始化状态
        return is;
    }
private:
    int y_, m_, d_;
};

std::cout << Date(2026, 9, 26);      // 2026-09-26

6.8 解引用与箭头运算符（智能指针的实现基础）

template <typename T>
class UniquePtr {
public:
    explicit UniquePtr(T* p = nullptr) : ptr_(p) {}
    ~UniquePtr() { delete ptr_; }
    UniquePtr(const UniquePtr&) = delete;
    UniquePtr& operator=(const UniquePtr&) = delete;

    T& operator*()  const { return *ptr_; }     // *p
    T* operator->() const { return ptr_; }      // p->member（返回指针，编译器再次应用 ->）
    explicit operator bool() const { return ptr_ != nullptr; }   // if (p)
    T* get() const { return ptr_; }
    T* release() { T* t = ptr_; ptr_ = nullptr; return t; }
    void reset(T* p = nullptr) { delete ptr_; ptr_ = p; }
private:
    T* ptr_;
};

struct Point { int x, y; void show() const { std::cout << x << ',' << y; } };

UniquePtr<Point> p(new Point{1, 2});
(*p).x = 10;         // operator*
p->show();           // operator->（链式：实际是 p.operator->()->show()）
if (p) { /* ... */ } // operator bool

第 7 章 继承

7.1 基本语法与"是一种"关系

class Animal {                 // 基类（父类）
public:
    virtual ~Animal() = default;
    virtual void speak() const { std::cout << "...\n"; }
    void eat() const { std::cout << "eating\n"; }
protected:
    std::string name_;
};

class Dog : public Animal {    // 派生类（子类）：public 继承
public:
    void speak() const override { std::cout << name_ << ": Woof!\n"; }   // 覆盖基类虚函数
    void fetch() const { std::cout << "fetching\n"; }
};

继承的含义：派生类对象"是一种"基类对象，因此

  • 派生类对象可以赋给基类引用/指针（向上转换，安全，不需要显式转换）；
  • 基类指针/引用可以调用基类的接口，运行时会分派到派生类实现（多态）；
  • 派生类拥有基类的所有成员（除构造、析构、赋值运算符、友元外）。

7.2 三种继承方式与访问控制的叠加

基类成员 public 继承 protected 继承 private 继承
public public protected private
protected protected protected private
private 不可访问 不可访问 不可访问
  • public 继承：表达 is-a（"Dog 是一种 Animal"），99% 的场景；
  • private 继承：表达 is-implemented-in-terms-of（"用 B 来实现 A"）。通常优先用组合（成员对象）而不是 private 继承；
  • protected 继承：极少使用。
// 推荐：组合优先于 private 继承
class Stack {                  // 用 vector 实现，但不暴露 vector 接口
public:
    void push(int x) { data_.push_back(x); }
    int  pop() { int v = data_.back(); data_.pop_back(); return v; }
private:
    std::vector<int> data_;    // 组合：清晰、耦合低
};

7.3 构造与析构顺序

struct Base {
    Base(int v) { std::cout << "Base(" << v << ")\n"; }
    ~Base() { std::cout << "~Base()\n"; }
};
struct Derived : Base {
    Derived() : Base(42) { std::cout << "Derived()\n"; }   // 必须在初始化列表里初始化基类
    ~Derived() { std::cout << "~Derived()\n"; }
};
// 构造：Base(42) → Derived()
// 析构：~Derived() → ~Base()

若基类没有默认构造函数，派生类必须在其初始化列表中显式调用基类构造函数，否则编译错误。

7.4 名字隐藏（Name Hiding）

派生类中同名成员会隐藏基类的所有同名重载（不管参数是否相同）——这是 C++ 的一个"反直觉"规则：

struct Base {
    void f(int)    { std::cout << "Base::f(int)\n"; }
    void f(double) { std::cout << "Base::f(double)\n"; }
};
struct Derived : Base {
    void f(std::string) { std::cout << "Derived::f(string)\n"; }
};

Derived d;
// d.f(1);            // 编译错误！Base::f 全部被隐藏
d.f(std::string{});   // OK
d.Base::f(1);         // OK，显式指定

解决：在派生类中用 using 把基类名字引入作用域：

struct Derived : Base {
    using Base::f;                              // 引入 Base::f 的所有重载
    void f(std::string) { /* ... */ }
};
d.f(1);      // OK → Base::f(int)
d.f("x");    // OK → Derived::f(string)

虚函数也受此规则影响：如果派生类只覆盖了 f(int) 而基类还有 f(double)，通过派生类对象调用 f(1.0) 会报错。用 using Base::f; 解决。

7.5 类型转换：向上与向下

Dog dog;
Animal& a = dog;                       // 向上转换（upcast）：安全，隐式
Animal* p = &dog;

// 向下转换（downcast）：不安全，必须显式
Dog* d1 = static_cast<Dog*>(&a);       // 编译期转换，不做运行时检查（若 a 实际是 Cat，UB！）
Dog* d2 = dynamic_cast<Dog*>(&a);      // 运行时检查，失败返回 nullptr（基类必须有虚函数）
try {
    Dog& rd = dynamic_cast<Dog&>(a);   // 引用版本失败时抛 std::bad_cast
} catch (const std::bad_cast&) { /* 不是 Dog */ }

dynamic_cast 需要 RTTI（运行时类型信息），有一定开销，且只在基类含虚函数时可用。

设计建议：频繁需要 dynamic_cast 通常说明类层次设计有问题。优先考虑虚函数、访问者模式，或重新划分接口。

7.6 多重继承

struct Flyable   { virtual void fly() = 0; virtual ~Flyable() = default; };
struct Swimmable { virtual void swim() = 0; virtual ~Swimmable() = default; };

class Duck : public Animal, public Flyable, public Swimmable {
public:
    void speak() const override { std::cout << "Quack!\n"; }
    void fly()  override { std::cout << "flying\n"; }
    void swim() override { std::cout << "swimming\n"; }
};

多重继承的构造顺序：按基类在声明列表中的顺序（与初始化列表顺序无关）。

接口式多重继承（多个纯虚基类，无数据成员）是安全且常用的模式（类似 Java/C# 的 interface）。真正危险的是多重继承带数据成员。

7.7 菱形继承与虚继承

struct A { int value; };
struct B : A {};        // B 有一份 A
struct C : A {};        // C 有一份 A
struct D : B, C {};     // D 有两份 A！

D d;
// d.value = 1;         // 编译错误：歧义，是 B::A::value 还是 C::A::value？
d.B::value = 1;         // 必须显式指定
d.C::value = 2;         // 两份独立的数据 —— 通常不是我们想要的

解决：虚继承，让菱形顶端只保留一份共享实例：

struct A { int value = 0; };
struct B : virtual A {};       // 虚继承
struct C : virtual A {};
struct D : B, C {};            // D 中只有一份 A

D d;
d.value = 1;                   // OK，唯一
d.B::value = 2;                // 也是同一份
std::cout << d.C::value;       // 2
普通继承 虚继承
内存 直接嵌入基类子对象 通过虚基类表指针间接访问
语义 每个路径一份拷贝 共享唯一一份
开销 无额外开销 一次间接寻址 + 构造更复杂
构造顺序 基类先于派生 虚基类最先构造（由最派生类负责初始化） 
struct VBase { VBase(int v) { /* ... */ } };
struct L : virtual VBase { L() : VBase(1) {} };
struct R : virtual VBase { R() : VBase(2) {} };
struct Bottom : L, R {
    Bottom() : VBase(99), L(), R() {}     // 最派生类必须初始化虚基类，L/R 中的初始化被忽略
};

实践建议：菱形继承 + 虚继承是复杂度的来源，能避免就避免。更好的方案是"用组合替代继承"，或让顶层类做成纯接口（无数据成员，就不需要虚继承）。

7.8 继承 vs 组合：决策表

场景 建议
"A 是一种 B"，且需要运行时替换 public 继承 + 虚函数
"A 有 B"（has-a） 组合（成员对象）
"用 B 实现 A" 组合优先；少数情况（需访问 protected、需空基类优化、需覆盖虚函数）用 private 继承

第 8 章 多态与虚函数

8.1 静态绑定与动态绑定

struct Base   { void f() { std::cout << "Base\n"; }   virtual void g() { std::cout << "Base::g\n"; } };
struct Derived: Base { void f() { std::cout << "Derived\n"; } void g() override { std::cout << "Derived::g\n"; } };

Derived d;
Base* p = &d;

p->f();      // "Base"    —— 静态绑定（编译期按 p 的静态类型 Base* 决定）
p->g();      // "Derived::g" —— 动态绑定（运行期按 p 指向的真实对象决定）

只有虚函数才有多态。普通成员函数按指针/引用的静态类型调用——这是初学者的经典困惑点。

8.2 虚函数表（vtable）与虚指针（vptr）

典型实现（Itanium ABI / MSVC 大同小异）：

对象内存:  [ vptr (8字节) ][ 基类成员 ][ 派生类成员 ]
                  |
                  v
虚表:      [ &Derived::g ][ &Derived::h ][ typeinfo ]
  • 每个含虚函数的类有一张虚表（编译期生成，全局唯一）；
  • 每个对象有一个隐藏的 vptr，指向其类的虚表；
  • p->g() 编译成：(*(p->vptr)[slot])(p) —— 一次间接跳转；
  • 构造派生类时，vptr 会随着构造过程从基类虚表切换到派生类虚表（所以构造中调用虚函数不会到派生类版本）。

成本：每对象 8 字节（多继承时可能多个 vptr）；虚调用多一次间接寻址（通常能被 CPU 分支预测器较好处理，但无法内联，且阻碍优化）。

8.3 override 与 final（C++11）

struct Base {
    virtual void f(int);
    virtual void g() const;
    virtual ~Base() = default;
};
struct Derived : Base {
    void f(int) override;         // OK：确实覆盖了
    // void f(long) override;     // 编译错误：签名不匹配，没有覆盖任何基类虚函数（少了 override 就变成"意外新增函数"的经典 bug）
    // void g() override;         // 编译错误：少了 const，其实是新函数
};

struct Final : Derived {
    void f(int) override final;   // final：禁止更下层的派生类再覆盖
};
struct Last : Final {
    // void f(int) override;      // 编译错误：f 是 final
};

struct NoDerive final : Base {};  // final 类：禁止被继承
// struct X : NoDerive {};        // 编译错误

务必养成习惯：覆盖虚函数时永远写 override。 它能把"静默的错误"变成"编译错误"。 final 还能帮助编译器去虚拟化（devirtualization），提升性能。

8.4 纯虚函数与抽象类

class Shape {                      // 抽象类：含至少一个纯虚函数
public:
    virtual ~Shape() = default;

    virtual double area() const = 0;                 // 纯虚函数：只有接口，没有实现
    virtual void   draw(std::ostream&) const = 0;
    virtual std::string name() const { return "shape"; }   // 抽象类也可以有普通虚函数
};

// Shape s;                        // 编译错误：抽象类不能实例化
// Shape* p = new Shape;           // 编译错误

class Circle : public Shape {
public:
    explicit Circle(double r) : r_(r) {}
    double area() const override { return 3.1415926 * r_ * r_; }
    void draw(std::ostream& os) const override { os << "Circle(r=" << r_ << ")"; }
private:
    double r_;
};

抽象类的作用：定义契约（接口）。所有派生类必须实现这些纯虚函数，否则自己也是抽象类。

纯虚函数也可以有实现体（void Shape::draw() {} 写在类外），派生类可以用 Shape::draw() 显式调用它作为默认实现。

8.5 虚析构函数：必须记住的铁律

struct Base   { ~Base()   { std::cout << "~Base\n"; } };
struct Derived: Base { ~Derived() { delete[] buf_; } int* buf_ = new int[100]; };

Base* p = new Derived;
delete p;        // 灾难：只调用 ~Base()，~Derived() 从未执行 → 内存泄漏

原因：delete p 对非虚析构是静态绑定，只调用 Base::~Base()。

铁律：任何被设计为基类的类，析构函数必须是 virtual。

struct Base { virtual ~Base() = default; };      // 正确

反过来：如果类不打算被继承，不要加虚析构（白白付出 vptr 开销），可以用 final 表明意图。

std::string、std::vector 等 STL 类型都没有虚析构——它们不设计为基类，不要去继承它们。

8.6 构造/析构中调用虚函数：不会多态

struct Base {
    Base()   { log(); }                 // 构造函数中调用虚函数
    virtual void log() { std::cout << "Base::log\n"; }
    virtual ~Base() { log(); }
};
struct Derived : Base {
    void log() override { std::cout << "Derived::log\n"; }
};

Derived d;    // 输出两次 "Base::log"，而不是 "Derived::log"

原因：构造 Base 部分时，对象还"不是" Derived，vptr 指向 Base 的虚表。析构时同理。

规则：绝不在构造函数和析构函数中调用虚函数。 如果需要，用"模板方法 + 显式传参"或"构造后调用 init()"替代。

8.7 完整的多态示例：图形系统

#include <iostream>
#include <memory>
#include <vector>
#include <cmath>

class Shape {
public:
    virtual ~Shape() = default;                                   // ① 虚析构
    virtual double area() const = 0;                              // ② 接口
    virtual double perimeter() const = 0;
    virtual void draw(std::ostream& os) const = 0;
    virtual std::unique_ptr<Shape> clone() const = 0;             // ③ 原型模式：多态拷贝
};

class Circle : public Shape {
public:
    explicit Circle(double r) : r_(r) {}
    double area()      const override { return PI * r_ * r_; }
    double perimeter() const override { return 2 * PI * r_; }
    void   draw(std::ostream& os) const override { os << "○ Circle(r=" << r_ << ")"; }
    std::unique_ptr<Shape> clone() const override { return std::make_unique<Circle>(*this); }
private:
    static constexpr double PI = 3.14159265358979;
    double r_;
};

class Rectangle : public Shape {
public:
    Rectangle(double w, double h) : w_(w), h_(h) {}
    double area()      const override { return w_ * h_; }
    double perimeter() const override { return 2 * (w_ + h_); }
    void   draw(std::ostream& os) const override { os << "▭ Rect(" << w_ << "x" << h_ << ")"; }
    std::unique_ptr<Shape> clone() const override { return std::make_unique<Rectangle>(*this); }
private:
    double w_, h_;
};

class Triangle : public Shape {
public:
    Triangle(double a, double b, double c) : a_(a), b_(b), c_(c) {}
    double area() const override {                // 海伦公式
        double s = perimeter() / 2;
        return std::sqrt(s * (s - a_) * (s - b_) * (s - c_));
    }
    double perimeter() const override { return a_ + b_ + c_; }
    void   draw(std::ostream& os) const override { os << "△ Tri(" << a_ << "," << b_ << "," << c_ << ")"; }
    std::unique_ptr<Shape> clone() const override { return std::make_unique<Triangle>(*this); }
private:
    double a_, b_, c_;
};

// 使用多态：这段代码完全不知道具体图形类型
void render(const std::vector<std::unique_ptr<Shape>>& shapes) {
    double total = 0;
    for (const auto& s : shapes) {
        s->draw(std::cout);
        std::cout << "  面积=" << s->area() << "  周长=" << s->perimeter() << "\n";
        total += s->area();
    }
    std::cout << "总面积: " << total << "\n";
}

int main() {
    std::vector<std::unique_ptr<Shape>> shapes;
    shapes.push_back(std::make_unique<Circle>(5));
    shapes.push_back(std::make_unique<Rectangle>(4, 6));
    shapes.push_back(std::make_unique<Triangle>(3, 4, 5));
    render(shapes);          // 新增图形类型时，render 一行都不用改

    // 多态拷贝
    auto copy = shapes[0]->clone();
    copy->draw(std::cout);
}

这个例子体现了 OOP 的全部价值：接口稳定，实现可扩展。

8.8 虚函数的替代方案：什么时候不该用虚函数

方案 绑定时机 开销 适用场景
虚函数 运行时 vptr + 间接调用 类型在运行时才确定；异构集合
模板 / CRTP 编译期 零（可内联） 类型在编译期确定；性能敏感
std::variant + visit 编译期/运行时 无堆分配 类型集合封闭且已知
std::function 运行时 可能一次间接 只需一个行为（回调/策略） 
// std::variant 方案（C++17）：封闭类型集合，无虚表、无堆分配
using AnyShape = std::variant<Circle, Rectangle, Triangle>;
double area_of(const AnyShape& s) {
    return std::visit([](const auto& sh) { return sh.area(); }, s);   // 编译期展开
}
std::vector<AnyShape> shapes;      // 值语义，缓存友好

性能敏感场景（游戏引擎、高频交易）通常偏好 variant/template 方案；业务系统通常虚函数更清晰易维护。

8.9 虚函数常见陷阱汇总

  1. 覆盖时签名不一致（少了 const、参数类型不同）→ 变成新函数，多态静默失效。用 override 杜绝。
  2. 基类析构非虚 → delete 基类指针导致资源泄漏。

  3. 默认参数不参与动态绑定：

    struct B { virtual void f(int x = 1) { std::cout << x; } };
struct D : B { void f(int x = 2) override { std::cout << x; } };
B* p = new D; p->f();     // 输出 1！默认参数按静态类型 B 取

    解决：虚函数不要用默认参数，改用重载或 NVI 模式。

  4. 在构造/析构中调用虚函数（8.6）。
  5. 通过对象（而非指针/引用）调用虚函数没有多态：Derived d; Base b = d; b.g(); → 调用 Base::g（还发生了对象切片，见下）。

  6. 对象切片（slicing）：把派生类对象按值赋给基类对象，派生部分被"切掉"。

    Derived d;
Base b = d;        // 只复制 Base 部分，Derived 的数据丢失
void f(Base b);    // 按值传参同样会切片 —— 接口应写成 const Base&

8.10 NVI（Non-Virtual Interface）模式

把公有接口设为非虚，把可变部分设为私有虚函数：

class GameCharacter {
public:
    // 非虚接口：统一处理前置/后置逻辑（日志、校验、加锁）
    int healthValue() const {
        log("计算生命值");
        int v = doHealthValue();         // 虚钩子
        return std::clamp(v, 0, 100);
    }
    virtual ~GameCharacter() = default;
private:
    virtual int doHealthValue() const { return baseHealth_; }
    int baseHealth_ = 100;
};
class Knight : public GameCharacter {
private:
    int doHealthValue() const override { return 120 + armor_; }
    int armor_ = 20;
};

好处：基类牢牢控制"何时调用"和"附加逻辑"，派生类只决定"怎么做"。也顺便解决了 8.9 的默认参数问题。

8.11 协变返回类型

覆盖虚函数时，返回类型可以"收窄"为派生类指针/引用：

struct Base   { virtual Base*   clone() const { return new Base(*this); } };
struct Derived: Base {
    Derived* clone() const override { return new Derived(*this); }   // 协变：返回 Derived*
};
Derived* p = someDerived.clone();     // 无需向下转换

注意：std::unique_ptr<Derived> 与 std::unique_ptr<Base> 不构成协变（它们是不同的类模板实例），只有裸指针/引用支持。

第三部分 · 现代 C++ 篇

第 9 章 模板与泛型编程

模板是 C++ 的"编译期多态"机制：写一次代码，让编译器为每种类型生成一份特化版本。零运行时开销，是 STL 的基础。

9.1 函数模板

template <typename T>
T max_of(T a, T b) {
    return a > b ? a : b;
}

template <typename T>
void swap_values(T& a, T& b) {
    T tmp = std::move(a);
    a = std::move(b);
    b = std::move(tmp);
}

int    x = max_of(3, 5);            // T 推导为 int
double y = max_of(3.0, 5.0);        // T 推导为 double
// auto z = max_of(3, 5.0);         // 编译错误：T 无法同时是 int 和 double
auto z = max_of<double>(3, 5.0);    // 显式指定 T

模板不是函数，而是一份"生成函数的配方"。编译器在使用点实例化出真实函数。

9.2 类模板

template <typename T, typename Allocator = std::allocator<T>>
class SimpleVector {
public:
    SimpleVector() = default;

    void push_back(const T& value) {
        if (size_ == capacity_) reserve(capacity_ ? capacity_ * 2 : 1);
        data_[size_++] = value;
    }
    void push_back(T&& value) {
        if (size_ == capacity_) reserve(capacity_ ? capacity_ * 2 : 1);
        data_[size_++] = std::move(value);
    }
    T&       operator[](size_t i)       { return data_[i]; }
    const T& operator[](size_t i) const { return data_[i]; }
    size_t   size()     const { return size_; }
    size_t   capacity() const { return capacity_; }
    bool     empty()    const { return size_ == 0; }

    void reserve(size_t n) {
        if (n <= capacity_) return;
        T* nd = static_cast<T*>(::operator new(n * sizeof(T)));
        for (size_t i = 0; i < size_; ++i) new (nd + i) T(std::move(data_[i]));  // 移动构造
        for (size_t i = 0; i < size_; ++i) data_[i].~T();
        ::operator delete(data_);
        data_ = nd; capacity_ = n;
    }
    ~SimpleVector() {
        for (size_t i = 0; i < size_; ++i) data_[i].~T();
        ::operator delete(data_);
    }
private:
    T*      data_     = nullptr;
    size_t  size_     = 0;
    size_t  capacity_ = 0;
};

SimpleVector<std::string> vs;
vs.push_back("hello");
SimpleVector<int> vi;
vi.push_back(42);

9.3 类模板成员函数的类外定义

template <typename T>
class Stack {
public:
    void push(const T& v);
    T    pop();
    bool empty() const;
private:
    std::vector<T> data_;
};

template <typename T>
void Stack<T>::push(const T& v) { data_.push_back(v); }

template <typename T>
T Stack<T>::pop() { T v = std::move(data_.back()); data_.pop_back(); return v; }

template <typename T>
bool Stack<T>::empty() const { return data_.empty(); }

实践提示：模板的定义必须在使用点可见，所以模板类通常把实现直接写在头文件里（不像普通类分成 .h + .cpp）。

9.4 非类型模板参数

template <typename T, size_t N>
class StaticArray {                  // N 是编译期常量，不是类型
public:
    constexpr size_t size() const { return N; }
    T& operator[](size_t i) { return data_[i]; }
private:
    T data_[N];                      // 栈上数组，零堆分配
};

StaticArray<int, 10> a;              // 10 个元素
// StaticArray<int, n> b;            // 编译错误：n 必须是编译期常量

// 现代写法：C++17 可用 auto 非类型参数
template <auto Value> struct Constant { static constexpr auto value = Value; };
Constant<42> c;                      // value = 42

9.5 模板特化

全特化：为特定类型提供完全不同的实现。

template <typename T>
struct TypeName { static const char* get() { return "unknown"; } };

template <> struct TypeName<int>    { static const char* get() { return "int"; } };
template <> struct TypeName<double> { static const char* get() { return "double"; } };
template <> struct TypeName<std::string> { static const char* get() { return "std::string"; } };

TypeName<int>::get();          // "int"
TypeName<char*>::get();        // "unknown"

偏特化：为一组类型提供实现（只有类模板支持偏特化，函数模板不支持）。

template <typename T> struct RemovePointer       { using type = T; };
template <typename T> struct RemovePointer<T*>   { using type = T; };       // 偏特化：指针
template <typename T> struct RemovePointer<T* const> { using type = T; };   // const 指针

RemovePointer<int*>::type   x;    // int
RemovePointer<int>::type    y;    // int

函数模板的"偏特化"替代方案：用重载 + 标签分发，或 C++17 if constexpr。

9.6 可变参数模板（C++11）

// 基础版本：0 个参数
void print_all() { std::cout << "\n"; }

// 递归版本
template <typename T, typename... Args>
void print_all(T first, Args... rest) {
    std::cout << first << ' ';
    print_all(rest...);              // 参数包展开（递归，C++11/14）
}

print_all(1, 2.5, "hello", 'c');     // 1 2.5 hello c

C++17 的折叠表达式更优雅，不需要递归：

template <typename... Args>
void print_all(Args... args) {
    (std::cout << ... << args) << "\n";         // 一元左折叠
}

template <typename... Args>
auto sum(Args... args) { return (args + ...); }  // 一元右折叠
sum(1, 2, 3, 4);       // 10

template <typename... Args>
void print_with_sep(Args... args) {
    ((std::cout << args << ", "), ...) << "\n";  // 逗号折叠
}

sizeof...(Args) 获取参数包大小。

9.7 完美转发与 std::forward

template <typename... Args>
std::unique_ptr<Widget> make_widget(Args&&... args) {   // 转发引用（万能引用）
    return std::unique_ptr<Widget>(new Widget(std::forward<Args>(args)...));
}

这里 Args&& 是转发引用（仅在模板推导语境下），能同时绑定左值和右值；std::forward<Args> 保持值类别不变，把参数原封不动传给构造函数。详见第 10 章。

9.8 模板与继承的结合：CRTP

CRTP（Curiously Recurring Template Pattern，奇异递归模板模式）：基类是模板，派生类把自己作为模板参数传给基类。

template <typename Derived>
class ShapeBase {                     // 编译期多态，无虚表
public:
    double area() const {
        return static_cast<const Derived*>(this)->areaImpl();   // 静态分派，可内联
    }
    void draw() const {
        static_cast<const Derived*>(this)->drawImpl();
    }
    // 提供通用算法，复用派生类的实现
    double areaX2() const { return area() * 2; }
};

class Circle : public ShapeBase<Circle> {
public:
    explicit Circle(double r) : r_(r) {}
    double areaImpl() const { return 3.14159 * r_ * r_; }
    void   drawImpl() const { std::cout << "Circle\n"; }
private:
    double r_;
};

Circle c(2);
c.area();       // 调用 Circle::areaImpl，编译期确定，零开销
c.areaX2();     // 基类提供的通用算法

CRTP 的用途：

  • 静态多态（性能敏感场景替代虚函数）；
  • 混入（mixin）：给类批量添加能力，如计数、比较、序列化。
// 用 mixin 自动生成比较运算符（只写 < 和 ==，其余自动有）
template <typename T>
class Comparable {
public:
    friend bool operator>(const T& a, const T& b)  { return b < a; }
    friend bool operator<=(const T& a, const T& b) { return !(b < a); }
    friend bool operator>=(const T& a, const T& b) { return !(a < b); }
    friend bool operator!=(const T& a, const T& b) { return !(a == b); }
};

class Money : public Comparable<Money> {
public:
    Money(int cents) : cents_(cents) {}
    friend bool operator<(const Money& a, const Money& b)  { return a.cents_ < b.cents_; }
    friend bool operator==(const Money& a, const Money& b) { return a.cents_ == b.cents_; }
private:
    int cents_;
};

Money a(100), b(200);
a > b;  a <= b;  a != b;      // 全部可用，且全部可内联

9.9 类型萃取与 SFINAE（进阶）

SFINAE（Substitution Failure Is Not An Error，替换失败不是错误）：模板匹配失败时编译器不报错，而是换一个重载。

// 只对整数类型启用的函数
template <typename T, typename = std::enable_if_t<std::is_integral_v<T>>>
void process(T value) { std::cout << "整数: " << value << "\n"; }

// 只对浮点类型启用
template <typename T, typename = std::enable_if_t<std::is_floating_point_v<T>>>
void process(T value) { std::cout << "浮点: " << value << "\n"; }

process(42);      // 整数
process(3.14);    // 浮点
// process("x");  // 编译错误：无匹配重载（这正是我们想要的）

C++20 的 Concepts 让这一切变得可读：

#include <concepts>

template <std::integral T>
void process(T value) { std::cout << "整数: " << value << "\n"; }

template <std::floating_point T>
void process(T value) { std::cout << "浮点: " << value << "\n"; }

// 自定义 concept
template <typename T>
concept Drawable = requires(const T& t) {
    { t.draw() } -> std::same_as<void>;
    { t.area() } -> std::convertible_to<double>;
};

template <Drawable T>
void render(const T& shape) { shape.draw(); }

Concepts 的好处：错误信息从几百行模板噪音变成一句"concept Drawable 未被满足"。C++20 起优先用 Concepts 替代 SFINAE。

第 10 章 移动语义与完美转发

C++11 最重大的语言改进。理解它，才能理解现代 C++ 为何性能优异。

10.1 左值与右值

int a = 10;          // a 是左值：有名字、有地址、可以取地址
int& r = a;
// int& r2 = 10;     // 错误：右值不能绑定到非 const 左值引用
const int& cr = 10;  // OK：const 左值引用可以绑定右值（延长生命周期）

int&& rr = 10;       // 右值引用：绑定到临时对象
int&& rr2 = a;       // 错误：a 是左值，不能绑定右值引用
int&& rr3 = std::move(a);   // OK：std::move 只是把左值"转换"成右值引用

一句话区分：

  • 左值（lvalue）：能放在赋值号左边，有持久身份（有名字、可取地址）；
  • 右值（rvalue）：临时的、即将消失的值（字面量、函数返回的临时对象、std::move 的结果）。

关键洞察：std::move 不做任何移动，它只是一个 static_cast<T&&>。真正执行移动的是移动构造/赋值函数。

10.2 为什么需要移动语义

std::vector<std::string> v;
std::string s = "一个很长的字符串...";
v.push_back(s);                 // 拷贝：分配新内存 + 复制所有字符
v.push_back(std::move(s));      // 移动：只复制指针（3 个指针/长度字段），s 变空

对 std::string、std::vector 这类持有堆资源的类型，移动把 O(n) 变成 O(1)。标准库容器重新分配内存时也会用移动（若移动是 noexcept）。

10.3 移动构造与移动赋值

class Buffer {
public:
    explicit Buffer(size_t n) : data_(new int[n]), size_(n) {}
    ~Buffer() { delete[] data_; }

    Buffer(const Buffer& rhs)                            // 拷贝：真复制
        : data_(new int[rhs.size_]), size_(rhs.size_) {
        std::copy(rhs.data_, rhs.data_ + rhs.size_, data_);
        std::cout << "拷贝\n";
    }

    Buffer(Buffer&& rhs) noexcept                        // 移动：偷指针
        : data_(rhs.data_), size_(rhs.size_) {
        rhs.data_ = nullptr;                             // 关键：把源置于"可安全析构"状态
        rhs.size_ = 0;
        std::cout << "移动\n";
    }

    Buffer& operator=(Buffer&& rhs) noexcept {
        if (this != &rhs) {
            delete[] data_;                              // 释放自己的资源
            data_ = rhs.data_; size_ = rhs.size_;        // 接管对方的
            rhs.data_ = nullptr; rhs.size_ = 0;
        }
        std::cout << "移动赋值\n";
        return *this;
    }
private:
    int*   data_;
    size_t size_;
};

移动构造的三条要求：

  1. 参数类型 T&&；
  2. 必须加 noexcept（否则 std::vector 扩容时会退化成拷贝——因为 vector 要保证强异常安全）；
  3. 移动后，源对象必须处于"有效但未指定"状态（可被安全析构、可被赋值），通常就是把指针置空。

10.4 移动语义触发时机

Buffer make() { return Buffer(100); }   // 返回临时对象

Buffer a = make();              // C++17 起保证省略拷贝（guaranteed copy elision）
Buffer b = a;                   // 拷贝
Buffer c = std::move(a);        // 移动（此后不要再依赖 a 的内容）
Buffer d = Buffer(50);          // 直接构造（无拷贝无移动）

std::vector<Buffer> v;
v.push_back(Buffer(10));        // 移动
v.push_back(c);                 // 拷贝
v.emplace_back(10);             // 直接构造，最优

RVO/NRVO（返回值优化）：编译器可以直接在调用者的栈帧上构造返回值，连移动都省了。C++17 起，纯右值（prvalue）的省略是强制的。

// C++17 起，这两行是等价的（都不发生拷贝/移动）
Buffer x = Buffer(10);
Buffer y = make();

10.5 完美转发

问题：写一个泛型包装函数，如何把参数"原样"（保持左值/右值、const 属性）传给内部函数？

// 朴素版本的问题
template <typename T>
void wrapper(T arg) { inner(arg); }        // 总是拷贝一次，且 arg 总是左值

// 完美转发版本
template <typename T>
void wrapper(T&& arg) {                    // T&& 在此是"转发引用"（万能引用）
    inner(std::forward<T>(arg));           // 保持值类别
}

wrapper(10);            // T = int,       arg 是 int&&        → inner 收到右值
int x = 5;
wrapper(x);             // T = int&,      arg 是 int&         → inner 收到左值
const int cx = 5;
wrapper(cx);            // T = const int& → inner 收到 const 左值

引用折叠规则是完美转发的底层机制：

声明的形式 实参类型 推导结果
T&& 左值 int T = int&，T&& → int& && → int&
T&& 右值 int T = int，T&& → int&&
T&& const 左值 T = const int&

规则：只要有一方是左值引用，结果就是左值引用（& 胜出）。

std::forward<T>(x) 就是：若 T 是左值引用就返回左值引用，否则返回右值引用——等价于 static_cast<T&&>(x)。

// 典型应用：工厂函数
template <typename T, typename... Args>
std::unique_ptr<T> make_unique_custom(Args&&... args) {
    return std::unique_ptr<T>(new T(std::forward<Args>(args)...));
}

// 典型应用：emplace 系列
template <typename... Args>
void addItem(Args&&... args) {
    items_.emplace_back(std::forward<Args>(args)...);   // 原地构造，零拷贝
}

注意：std::move 是无条件转右值，std::forward 是有条件转（保持原样）。只在"转发"语境用 forward，在"我要拿走它的资源"语境用 move。

10.6 常见误区

// 误区 1：对已经要返回的对象再 std::move（反而阻止 RVO）
std::string bad() {
    std::string s = "hello";
    return std::move(s);        // 错误做法！应直接 return s;
}
std::string good() {
    std::string s = "hello";
    return s;                   // NRVO 生效，零拷贝
}

// 误区 2：返回局部对象的右值引用（悬垂引用！）
std::string&& bad2() {
    std::string s = "x";
    return std::move(s);        // s 已销毁，返回的引用悬空
}

// 误区 3：以为 std::move 之后源对象一定为空
std::string s = "hello";
std::string t = std::move(s);
// s 处于"有效但未指定"状态：通常是空，但标准不保证。
// 正确做法：移动后要么不再使用 s，要么重新赋值
s.clear(); s = "new value";     // 可以重新赋值让它回到确定状态

// 误区 4：移动构造忘了 noexcept
Buffer(Buffer&& rhs) { /* ... */ }        // 少了 noexcept → vector 扩容时不使用移动

第 11 章 智能指针与 RAII

11.1 RAII 再深入

RAII 的完整含义：

资源的生命周期 = 对象的生命周期。 在构造函数中获取资源，在析构函数中释放。

这个简单规则解决了 C/C++ 最大的痛点：

// C 风格：每个 return 都要记得释放，异常还会跳过清理
void risky() {
    FILE* f = fopen("data.txt", "r");
    if (!f) return;
    char* buf = malloc(1024);
    if (!buf) { fclose(f); return; }
    process(f, buf);
    if (error) { free(buf); fclose(f); return; }    // 容易漏
    free(buf);
    fclose(f);
}

// RAII 风格：无论怎么退出（正常/return/异常），资源一定释放
void safe() {
    File f("data.txt");              // 构造时打开
    std::vector<char> buf(1024);     // 构造时分配
    process(f.get(), buf.data());
    // 若抛异常，栈展开（stack unwinding）自动调用析构函数释放一切
}

栈展开：异常抛出时，C++ 保证从抛出点到处理点之间所有已构造的栈对象按逆序析构。这是 RAII + 异常能协同工作的基础。

11.2 std::unique_ptr：独占所有权

#include <memory>

std::unique_ptr<Widget> p1 = std::make_unique<Widget>(args...);   // 推荐（C++14）
// std::unique_ptr<Widget> p2(new Widget(args...));                // 可以但不推荐

p1->method();                       // 像普通指针一样用
(*p1).method();
if (p1) { /* 非空 */ }

std::unique_ptr<Widget> p3 = std::move(p1);   // 所有权转移（不可拷贝！）
// auto p4 = p1;                              // 编译错误：unique_ptr 禁止拷贝
p3.reset();                                   // 释放资源
Widget* raw = p3.release();                   // 放弃所有权，返回裸指针（需自己 delete）

特点：

  • 零开销（大小等同裸指针，无引用计数）；
  • 独占所有权，语义清晰；
  • 默认选择：80% 的场景用 unique_ptr。

为什么推荐 make_unique：

  1. 异常安全：f(std::unique_ptr<T>(new T), may_throw()) 在参数求值顺序不确定时可能泄漏；
  2. 少写一次类型名，避免重复；
  3. 更少的内存分配次数（配合 make_shared 效果更明显）。

自定义删除器：

// 文件句柄的智能管理
using FilePtr = std::unique_ptr<FILE, decltype(&std::fclose)>;
FilePtr fp(std::fopen("a.txt", "r"), &std::fclose);
// 离开作用域自动 fclose

// 用 lambda 作为删除器（无状态 lambda 不增加 unique_ptr 大小）
auto deleter = [](SDL_Window* w) { SDL_DestroyWindow(w); };
std::unique_ptr<SDL_Window, decltype(deleter)> window(SDL_CreateWindow(...), deleter);

unique_ptr 删除器是类型的一部分（影响 sizeof）；shared_ptr 的删除器不是（存在控制块里）。

11.3 std::shared_ptr：共享所有权

std::shared_ptr<Widget> s1 = std::make_shared<Widget>(args...);
std::shared_ptr<Widget> s2 = s1;        // 引用计数 +1
std::cout << s1.use_count();            // 2

// 最后一个 shared_ptr 析构时，资源自动释放

内部机制：控制块（control block），包含引用计数、弱计数、删除器、分配器。

shared_ptr A ──┐
               ├──> [控制块: strong=2, weak=1]
shared_ptr B ──┘         │
                         v
                    [ Widget 对象 ]

必须用 make_shared：

// 危险：两块独立分配，且可能泄漏
std::shared_ptr<Widget> p(new Widget);
std::shared_ptr<Widget> q(p.get());      // 两个独立控制块！双重 delete！

// 正确
auto p = std::make_shared<Widget>();
auto q = p;                              // 共享同一控制块

make_shared 还把对象和控制块一次分配，更快、更省内存。

shared_ptr 的代价：

  • 大小是裸指针的 2 倍（对象指针 + 控制块指针）；
  • 引用计数是原子操作，有同步开销；
  • 控制块是额外的堆分配（make_shared 可合并）；
  • 循环引用会导致内存泄漏（用 weak_ptr 打破）。

11.4 std::weak_ptr：打破循环引用

struct Node {
    std::shared_ptr<Node> parent;      // 强引用
    std::vector<std::shared_ptr<Node>> children;
};
// 若 parent 也是 shared_ptr 且形成环，所有节点永远不会被释放 → 内存泄漏

// 解决方案：反向引用用 weak_ptr
struct Node {
    std::weak_ptr<Node>   parent;      // 弱引用：不增加引用计数
    std::vector<std::shared_ptr<Node>> children;
};

std::shared_ptr<Node> child = std::make_shared<Node>();
std::weak_ptr<Node>   wp = child;

if (auto sp = wp.lock()) {        // lock() 返回 shared_ptr（对象还活着）
    sp->doSomething();
} else {
    std::cout << "对象已销毁\n";
}
wp.expired();                     // 是否已失效（等价于 use_count() == 0）

典型用途：缓存、观察者列表、树/图的父指针、打破循环。

11.5 智能指针使用准则

场景 选择
独占资源、明确的单一所有者 unique_ptr（默认）
需要共享所有权 shared_ptr
观察但不拥有（可能失效） weak_ptr
不拥有、保证不为空 引用 T&
不拥有、可能为空 裸指针 T*（非拥有语义）

第 12 章 异常处理

12.1 基本语法

#include <stdexcept>

double divide(double a, double b) {
    if (b == 0) throw std::domain_error("除数不能为零");
    return a / b;
}

int main() {
    try {
        std::cout << divide(10, 0);
    }
    catch (const std::domain_error& e) {     // 按 const 引用捕获（避免拷贝和切片）
        std::cerr << "数学错误: " << e.what() << "\n";
    }
    catch (const std::exception& e) {        // 兜底：捕获所有标准异常
        std::cerr << "错误: " << e.what() << "\n";
    }
    catch (...) {                            // 捕获任意异常（最后一道防线）
        std::cerr << "未知错误\n";
        throw;                               // 重新抛出，交给上层处理
    }
}

要点：

  • 捕获顺序：从具体到一般（派生类在前，基类在后）；
  • 按 const T& 捕获（按值捕获会发生对象切片）；
  • throw;（不带参数）表示重新抛出当前异常，保留原始类型。

12.3 异常安全保证的三个级别

级别 含义 例子
基本保证 异常发生后，对象仍处于有效状态，无资源泄漏（但内容可能改变） 大多数代码
强保证 操作要么完全成功，要么完全不改变状态（提交-回滚语义） std::vector::push_back（对可 noexcept 移动的类型）、copy-and-swap
不抛保证（nothrow） 保证不抛异常 析构函数、swap、std::move（对简单类型）、noexcept 函数

实现强保证的黄金技巧：copy-and-swap

class Widget {
public:
    void setValue(const std::string& v) {
        Widget tmp(*this);        // 1. 先做一份副本
        tmp.value_ = v;           // 2. 在副本上修改（这里可能抛异常，但不影响 *this）
        swap(tmp);                // 3. 交换（noexcept，绝不失败）
    }                             // 4. tmp 析构释放旧数据
    void swap(Widget& o) noexcept {
        using std::swap;
        swap(value_, o.value_);
    }
private:
    std::string value_;
};

12.4 noexcept

void f() noexcept;                       // 承诺不抛异常
void g() noexcept(true);                 // 等价
void h() noexcept(false);                // 可能抛

template <typename T>
void swap_them(T& a, T& b) noexcept(std::is_nothrow_move_constructible_v<T>) {
    // 条件 noexcept：是否 noexcept 取决于 T
}
  • 若 noexcept 函数真的抛了异常 → 直接 std::terminate()（不会栈展开）；
  • noexcept 是接口的一部分，不要随意加；也不要随意不加（移动构造、swap、析构应该是 noexcept）；
  • 编译器对 noexcept 函数可以做更多优化；std::vector 扩容时只有 noexcept 的移动才会被使用。

12.5 何时用异常，何时不用

适合用异常：

  • 真正的"异常"情况：文件打不开、网络断开、内存不足；
  • 构造函数失败（构造函数没有返回值，只能抛异常或用"两阶段初始化"）；
  • 跨越多个调用层传播错误（避免层层检查返回值）。

不适合用异常：

  • 常规的控制流（用 if 就好）；
  • 可预期的失败（如"用户输入格式不对"可以用 std::optional 返回）；
  • 性能热路径的频繁失败（异常抛出开销较大，通常几百到几千纳秒）；
  • 析构函数中（C++11 起析构默认 noexcept，抛异常会 terminate）。

现代替代方案（C++17/23）：

std::optional<int>  find(const std::string& key);   // 可能"没有结果"
std::expected<int, Error> parse(std::string_view);  // C++23：要么值要么错误
std::variant<Value, Error> compute();               // C++17 的替代

12.6 异常与 OOP 的结合：不变式保护

class Date {
public:
    Date(int y, int m, int d) {
        if (m < 1 || m > 12) throw std::out_of_range("月份必须在 1-12");
        if (d < 1 || d > daysInMonth(y, m)) throw std::out_of_range("日期非法");
        y_ = y; m_ = m; d_ = d;
    }
    // 一旦构造成功，Date 对象永远是合法的

    int y_, m_, d_;
};

这是 RAII + 异常 + 封装的完美配合：构造要么成功并产生合法对象，要么以异常失败并什么都没留下（不会有半初始化的僵尸对象）。

13.4 Lambda 表达式：现代 C++ 的灵魂

// 完整形式：[捕获] (参数) 修饰 -> 返回类型 { 体 }
auto add = [](int a, int b) -> int { return a + b; };

int factor = 10;
auto mul = [factor](int x) { return x * factor; };        // 按值捕获
auto inc = [&factor]() { ++factor; };                     // 按引用捕获
auto mul2 = [factor](int x) mutable { factor *= 2; return x * factor; };  // mutable：允许修改副本

std::vector<int> data{3, 1, 4, 1, 5};
std::sort(data.begin(), data.end(), [](int a, int b) { return a > b; });   // 降序
auto n = std::count_if(data.begin(), data.end(), [](int x) { return x > 2; });

// 捕获列表速查
[ ]        // 不捕获
[=]        // 按值捕获所有（不推荐，容易误捕获 this）
[&]        // 按引用捕获所有（注意悬垂！）
[x, &y]    // x 按值，y 按引用
[this]     // 捕获 this 指针
[*this]    // C++17：捕获对象副本（异步回调时安全）
[n = 5]    // C++14：初始化捕获（可以移动捕获）
[p = std::move(ptr)]  // C++14：移动捕获，转移所有权

Lambda 的本质：编译器生成一个匿名类（闭包类型），重载 operator()，捕获的变量成为其成员。所以它本质就是第 6.5 节的仿函数。

// 编译器大致这样展开
auto lam = [factor](int x) { return x * factor; };
// ↓
struct __Lambda {
    int factor;
    int operator()(int x) const { return x * factor; }
};
__Lambda lam{factor};

陷阱：按引用捕获的 lambda 若逃逸出作用域，会产生悬垂引用。

std::function<int()> makeBad() {
    int local = 42;
    return [&local] { return local; };     // 灾难：返回后 local 已销毁
}
std::function<int()> makeGood() {
    int local = 42;
    return [local] { return local; };      // 按值捕获，安全
}

13.7 自定义类型与 STL 的协作要求

class Student {
public:
    // 1. 可默认构造（某些容器操作需要）
    Student() = default;
    // 2. 可拷贝/移动（放入 vector）
    Student(const Student&) = default;
    // 3. 可比较（排序）
    bool operator<(const Student& rhs) const { return id_ < rhs.id_; }
    bool operator==(const Student& rhs) const { return id_ == rhs.id_; }
    // 4. 可哈希（放入 unordered_map/set）
private:
    int id_;
};

// 方式 A：特化 std::hash
namespace std {
    template <> struct hash<Student> {
        size_t operator()(const Student& s) const noexcept {
            return hash<int>{}(s.id());
        }
    };
}
// 方式 B：传入自定义哈希器（推荐，不侵入 std 命名空间）
struct StudentHash {
    size_t operator()(const Student& s) const noexcept { return std::hash<int>{}(s.id()); }
};
std::unordered_set<Student, StudentHash> students;

  • 放入 std::map 需要 operator<（严格弱序）或自定义比较器；
  • 用于 std::sort 的比较器必须满足严格弱序（comp(a,a) == false，且不能自相矛盾）；
  • 元素类型最好有 noexcept 的移动构造（容器扩容性能）。

13.9 一个综合例子：用 STL + OOP 实现词频统计

#include <iostream>
#include <sstream>
#include <string>
#include <map>
#include <vector>
#include <algorithm>

class WordCounter {
public:
    explicit WordCounter(std::istream& in) {
        std::string word;
        while (in >> word) {
            clean(word);
            if (!word.empty()) ++counts_[word];
        }
    }

    // 返回出现次数最多的 N 个词
    std::vector<std::pair<std::string, int>> topN(size_t n) const {
        std::vector<std::pair<std::string, int>> result(counts_.begin(), counts_.end());
        std::partial_sort(result.begin(),
                          result.begin() + std::min(n, result.size()),
                          result.end(),
                          [](const auto& a, const auto& b) {
                              return a.second > b.second;      // 按频次降序
                          });
        result.resize(std::min(n, result.size()));
        return result;
    }

    size_t total() const { return counts_.size(); }
private:
    static void clean(std::string& s) {
        s.erase(std::remove_if(s.begin(), s.end(),
                [](char c) { return !std::isalpha(static_cast<unsigned char>(c)); }),
                s.end());
        for (char& c : s) c = static_cast<char>(std::tolower(static_cast<unsigned char>(c)));
    }
    std::map<std::string, int> counts_;      // 有序，输出天然按字母序
};

int main() {
    std::istringstream text("Hello world hello C++ world OOP hello");
    WordCounter wc(text);
    for (const auto& [word, count] : wc.topN(3)) {
        std::cout << word << ": " << count << "\n";
    }
}
// hello: 3
// world: 2
// c: 1

第 14 章 设计原则与常见设计模式

14.1 SOLID 原则

原则 全称 含义 C++ 中的体现
S 单一职责 (SRP) 一个类只有一个变化的原因 把"数据存储"和"格式化输出"拆开
O 开闭原则 (OCP) 对扩展开放，对修改关闭 虚函数 + 工厂；模板策略
L 里氏替换 (LSP) 派生类必须能替换基类 覆盖不强化前置条件、不弱化后置条件
I 接口隔离 (ISP) 客户端不应依赖它不需要的接口 拆成多个小的纯虚基类（接口）
D 依赖倒置 (DIP) 依赖抽象，不依赖具体实现 参数用 const AbstractBase&

LSP 的经典反例：

class Rectangle {
public:
    virtual void setWidth(double w)  { w_ = w; }
    virtual void setHeight(double h) { h_ = h; }
    double area() const { return w_ * h_; }
private:
    double w_ = 0, h_ = 0;
};

// 看似"正方形是一种长方形"，但违反了 LSP
class Square : public Rectangle {
public:
    void setWidth(double w)  override { w_ = w; h_ = w; }   // 悄悄改了高！
    void setHeight(double h) override { w_ = h; h_ = h; }
};

    assert(r.area() == 20);       // 传入 Square 时失败（面积是 16）

14.6 观察者模式（Observer）

一对多的依赖通知。

template <typename Event>
class Subject {
public:
    using Handler = std::function<void(const Event&)>;
    // 返回句柄用于取消订阅（避免回调里删元素的坑）
    class Subscription {
    public:
        ~Subscription() { if (subject_) subject_->unsubscribe(id_); }
        Subscription(const Subscription&) = delete;
        Subscription& operator=(const Subscription&) = delete;
        Subscription(Subscription&& o) noexcept : subject_(o.subject_), id_(o.id_) { o.subject_ = nullptr; }
    private:
        friend class Subject;
        Subscription(Subject* s, size_t id) : subject_(s), id_(id) {}
        Subject* subject_; size_t id_;
    };

    [[nodiscard]] Subscription subscribe(Handler h) {
        handlers_[nextId_] = std::move(h);
        return Subscription{this, nextId_++};
    }
    void notify(const Event& e) const {
        for (const auto& [id, h] : handlers_) h(e);
    }
private:
    void unsubscribe(size_t id) { handlers_.erase(id); }
    std::map<size_t, Handler> handlers_;
    size_t nextId_ = 0;
};

// 使用
struct TemperatureChanged { double celsius; };
Subject<TemperatureChanged> sensor;
auto sub = sensor.subscribe([](const TemperatureChanged& e) {
    std::cout << "温度变为 " << e.celsius << "°C\n";
});
sensor.notify({36.5});
// sub 析构时自动取消订阅

14.8 访问者模式（Visitor）：双分派

当你有一个稳定的类层次，却要不断新增操作时（与策略模式正好互补）。

// 稳定的元素层次
class Circle; class Rectangle;
class ShapeVisitor {
public:
    virtual ~ShapeVisitor() = default;
    virtual void visit(const Circle&) = 0;
    virtual void visit(const Rectangle&) = 0;
};
class Shape {
public:
    virtual ~Shape() = default;
    virtual void accept(ShapeVisitor& v) const = 0;
};
class Circle : public Shape {
public:
    void accept(ShapeVisitor& v) const override { v.visit(*this); }
    double radius() const { return r_; }
private: double r_ = 1;
};
class Rectangle : public Shape {
public:
    void accept(ShapeVisitor& v) const override { v.visit(*this); }
    double width() const { return w_; }
private: double w_ = 1;
};

// 新增操作只需新增一个 visitor，不改 Shape 层次
class AreaVisitor : public ShapeVisitor {
public:
    void visit(const Circle& c) override    { total += 3.14159 * c.radius() * c.radius(); }
    void visit(const Rectangle& r) override { total += r.width() * r.width(); }
    double total = 0;
};
class XmlExportVisitor : public ShapeVisitor { /* 导出 XML */ };

double totalArea(const std::vector<std::unique_ptr<Shape>>& shapes) {
    AreaVisitor v;
    for (const auto& s : shapes) s->accept(v);
    return v.total;
}

        [](const Rectangle& r) { return r.width() * r.width(); }
    }, s);
}

14.9 命令模式（Command）：支持撤销

class Command {
public:
    virtual ~Command() = default;
    virtual void execute() = 0;
    virtual void undo()    = 0;
};

class TextEditor {
public:
    void insert(size_t pos, std::string text) { content_.insert(pos, text); }
    void erase(size_t pos, size_t n)          { content_.erase(pos, n); }
    std::string content() const { return content_; }
private:
    std::string content_;
};

class InsertCommand : public Command {
public:
    InsertCommand(TextEditor& ed, size_t pos, std::string text)
        : editor_(ed), pos_(pos), text_(std::move(text)) {}
    void execute() override { editor_.insert(pos_, text_); }
    void undo()    override { editor_.erase(pos_, text_.size()); }
private:
    TextEditor& editor_; size_t pos_; std::string text_;
};

class EditorInvoker {
public:
    void run(std::unique_ptr<Command> cmd) {
        cmd->execute();
        history_.push(std::move(cmd));
        while (!redoStack_.empty()) redoStack_.pop();    // 新操作清空重做栈
    }
    void undo() {
        if (history_.empty()) return;
        history_.top()->undo();
        redoStack_.push(std::move(history_.top()));
        history_.pop();
    }
    void redo() {
        if (redoStack_.empty()) return;
        redoStack_.top()->execute();
        history_.push(std::move(redoStack_.top()));
        redoStack_.pop();
    }
private:
    std::stack<std::unique_ptr<Command>> history_;
    std::stack<std::unique_ptr<Command>> redoStack_;
};

// ---------- 1. 基础值类型：点（值语义 + 运算符重载 + 三路比较） ----------
struct Point {
    double x = 0.0, y = 0.0;

    Point& operator+=(const Point& rhs) { x += rhs.x; y += rhs.y; return *this; }
    Point& operator-=(const Point& rhs) { x -= rhs.x; y -= rhs.y; return *this; }
    Point& operator*=(double k)         { x *= k;     y *= k;     return *this; }

    friend Point operator+(Point a, const Point& b) { a += b; return a; }
    friend Point operator-(Point a, const Point& b) { a -= b; return a; }
    friend Point operator*(Point a, double k)       { a *= k; return a; }
    friend Point operator*(double k, Point a)       { a *= k; return a; }

    auto operator<=>(const Point&) const = default;      // C++20（C++17 可删除此行）
    bool operator==(const Point&) const  = default;

    friend std::ostream& operator<<(std::ostream& os, const Point& p) {
        return os << '(' << p.x << ',' << p.y << ')';
    }
};

// 变换：把点绕原点旋转（用于图形的 rotate）
Point rotate(const Point& p, double rad) {
    double c = std::cos(rad), s = std::sin(rad);
    return {p.x * c - p.y * s, p.x * s + p.y * c};
}

// ---------- 2. 抽象基类：Shape（接口 + 不变式 + clone 原型） ----------
class Shape {
public:
    virtual ~Shape() = default;                                   // ① 虚析构

    // ② 纯虚接口：所有图形必须实现
    virtual double      area()      const = 0;
    virtual double      perimeter() const = 0;
    virtual std::string typeName()  const = 0;
    virtual void        serialize(std::ostream& os) const = 0;    // 序列化
    virtual std::unique_ptr<Shape> clone() const = 0;             // 原型模式

    // ③ 通用变换（NVI：非虚接口统一处理，虚钩子交给子类）
    void move(const Point& delta)        { doMove(delta); }
    void scale(double factor)            { if (factor <= 0) throw std::invalid_argument("缩放因子必须为正");
                                           doScale(factor); }
    void rotateBy(double rad)            { doRotate(rad); }

    // ④ 通用算法：不依赖具体类型（模板方法）
    virtual void draw(std::ostream& os) const {                   // 默认实现：打印摘要
        os << typeName() << " 面积=" << area() << " 周长=" << perimeter();
    }
    double areaTimes(double k) const { return area() * k; }

protected:
    // 虚钩子：protected，外部只能走 move/scale/rotateBy
    virtual void doMove(const Point& delta) = 0;
    virtual void doScale(double factor)     = 0;
    virtual void doRotate(double rad)       = 0;
};

// ---------- 3. 具体图形：Circle ----------
class Circle : public Shape {
public:
    explicit Circle(Point center, double r) : center_(center), r_(r) {
        if (r <= 0) throw std::invalid_argument("半径必须为正");
    }
    double area()      const override { return PI * r_ * r_; }
    double perimeter() const override { return 2 * PI * r_; }
    std::string typeName() const override { return "Circle"; }

    void serialize(std::ostream& os) const override {
        os << "Circle " << center_.x << ' ' << center_.y << ' ' << r_;
    }
    std::unique_ptr<Shape> clone() const override {
        return std::make_unique<Circle>(*this);
    }
    void draw(std::ostream& os) const override {
        os << "○ Circle(center=" << center_ << ", r=" << r_ << ")";
    }
private:
    void doMove(const Point& d) override { center_ += d; }
    void doScale(double k)      override { r_ *= k; }
    void doRotate(double)       override { /* 圆旋转无效果 */ }
    static constexpr double PI = 3.14159265358979;
    Point  center_;
    double r_;
};

// ---------- 4. 具体图形：Rectangle（可旋转，记录角度） ----------
class Rectangle : public Shape {
public:
    Rectangle(Point center, double w, double h) : center_(center), w_(w), h_(h) {
        if (w <= 0 || h <= 0) throw std::invalid_argument("宽高必须为正");
    }
    double area()      const override { return w_ * h_; }
    double perimeter() const override { return 2 * (w_ + h_); }
    std::string typeName() const override { return "Rectangle"; }

    void serialize(std::ostream& os) const override {
        os << "Rectangle " << center_.x << ' ' << center_.y << ' ' << w_ << ' ' << h_ << ' ' << angle_;
    }
    std::unique_ptr<Shape> clone() const override {
        return std::make_unique<Rectangle>(*this);
    }
    void draw(std::ostream& os) const override {
        os << "▭ Rect(center=" << center_ << ", " << w_ << "x" << h_
           << ", angle=" << angle_ << "rad)";
    }
private:
    void doMove(const Point& d) override { center_ += d; }
    void doScale(double k)      override { w_ *= k; h_ *= k; }
    void doRotate(double rad)   override { angle_ += rad; }
    Point  center_;
    double w_, h_;
    double angle_ = 0.0;
};

// ---------- 5. 具体图形：Triangle（三顶点） ----------
class Triangle : public Shape {
public:
    Triangle(Point a, Point b, Point c) : pts_{a, b, c} {
        if (area() <= 1e-12) throw std::invalid_argument("三点共线，无法构成三角形");
    }
    double perimeter() const override {
        auto d = [](const Point& p, const Point& q) {
            return std::hypot(p.x - q.x, p.y - q.y);
        };
        return d(pts_[0], pts_[1]) + d(pts_[1], pts_[2]) + d(pts_[2], pts_[0]);
    }
    double area() const override {                      // 叉积公式
        const Point& a = pts_[0]; const Point& b = pts_[1]; const Point& c = pts_[2];
        return std::abs((b.x - a.x) * (c.y - a.y) - (c.x - a.x) * (b.y - a.y)) / 2.0;
    }
    std::string typeName() const override { return "Triangle"; }
    void serialize(std::ostream& os) const override {
        os << "Triangle ";
        for (const auto& p : pts_) os << p.x << ' ' << p.y << ' ';
    }
    std::unique_ptr<Shape> clone() const override { return std::make_unique<Triangle>(*this); }
    void draw(std::ostream& os) const override {
        os << "△ Triangle(" << pts_[0] << ',' << pts_[1] << ',' << pts_[2] << ')';
    }
private:
    void doMove(const Point& d) override { for (auto& p : pts_) p += d; }
    void doScale(double k)      override { for (auto& p : pts_) p *= k; }
    void doRotate(double rad)   override { for (auto& p : pts_) p = rotate(p, rad); }
    Point pts_[3];
};

// ---------- 6. 工厂：注册表式（新增类型零改动） ----------
class ShapeFactory {
public:
    using Creator = std::function<std::unique_ptr<Shape>(std::istream&)>;
    static ShapeFactory& instance() {
        static ShapeFactory f;                       // Meyers Singleton，线程安全
        return f;
    }
    void registerType(std::string name, Creator c) {
        creators_[std::move(name)] = std::move(c);
    }
    std::unique_ptr<Shape> create(const std::string& name, std::istream& is) const {
        auto it = creators_.find(name);
        if (it == creators_.end()) throw std::invalid_argument("未注册的图形类型: " + name);
        return it->second(is);
    }
    std::vector<std::string> types() const {
        std::vector<std::string> out;
        for (const auto& [k, v] : creators_) out.push_back(k);
        return out;
    }
private:
    std::map<std::string, Creator> creators_;
};

// 各类型自注册（静态初始化期完成）
namespace {
struct AutoRegister {
    AutoRegister() {
        auto& f = ShapeFactory::instance();
        f.registerType("Circle", [](std::istream& is) {
            Point c; double r; is >> c.x >> c.y >> r;
            return std::make_unique<Circle>(c, r);
        });
        f.registerType("Rectangle", [](std::istream& is) {
            Point c; double w, h, a; is >> c.x >> c.y >> w >> h >> a;
            auto r = std::make_unique<Rectangle>(c, w, h);
            r->rotateBy(a);
            return r;
        });
        f.registerType("Triangle", [](std::istream& is) {
            Point a, b, c; is >> a.x >> a.y >> b.x >> b.y >> c.x >> c.y;
            return std::make_unique<Triangle>(a, b, c);
        });
    }
};
const AutoRegister autoRegister{};      // 触发注册
} // namespace

// ---------- 7. 命令模式：撤销/重做 ----------
class Command {
public:
    virtual ~Command() = default;
    virtual void execute() = 0;
    virtual void undo()    = 0;
    virtual std::string name() const = 0;
};

class Canvas;   // 前向声明

// 泛型命令：用 lambda 表达，避免为每个操作写一个类
// 注意：捕获的对象必须可拷贝（std::function 要求），unique_ptr 需改用下面的专用命令类
class LambdaCommand : public Command {
public:
    LambdaCommand(std::string name, std::function<void()> redo, std::function<void()> undo)
        : name_(std::move(name)), redo_(std::move(redo)), undo_(std::move(undo)) {}
    void execute() override { redo_(); }
    void undo()    override { undo_(); }
    std::string name() const override { return name_; }
private:
    std::string name_;
    std::function<void()> redo_, undo_;
};

// ---------- 8. 画布：容器 + 观察者通知 ----------
class Canvas {
public:
    using Listener = std::function<void(const std::string&)>;

    void addListener(Listener l) { listeners_.push_back(std::move(l)); }

    // 添加图形（可被撤销）
    void add(std::unique_ptr<Shape> s) {
        auto raw = s.get();
        shapes_.push_back(std::move(s));
        notify("添加 " + raw->typeName());
    }
    std::unique_ptr<Shape> remove(size_t index) {
        if (index >= shapes_.size()) throw std::out_of_range("索引越界");
        auto s = std::move(shapes_[index]);
        shapes_.erase(shapes_.begin() + static_cast<long>(index));
        notify("删除 " + s->typeName());
        return s;
    }
    void insert(size_t index, std::unique_ptr<Shape> s) {
        shapes_.insert(shapes_.begin() + static_cast<long>(index), std::move(s));
    }

    size_t count() const { return shapes_.size(); }
    Shape& at(size_t i) { return *shapes_.at(i); }

    // 用 STL 算法做统计
    double totalArea() const {
        return std::accumulate(shapes_.begin(), shapes_.end(), 0.0,
            [](double acc, const auto& s) { return acc + s->area(); });
    }
    std::vector<const Shape*> sortedByArea() const {
        std::vector<const Shape*> v;
        for (const auto& s : shapes_) v.push_back(s.get());
        std::sort(v.begin(), v.end(), [](const Shape* a, const Shape* b) {
            return a->area() > b->area();
        });
        return v;
    }
    std::vector<const Shape*> filterByType(const std::string& type) const {
        std::vector<const Shape*> out;
        for (const auto& s : shapes_) if (s->typeName() == type) out.push_back(s.get());
        return out;
    }

    void render(std::ostream& os) const {
        os << "=== 画布（" << shapes_.size() << " 个图形）===\n";
        for (size_t i = 0; i < shapes_.size(); ++i) {
            os << i << ": "; shapes_[i]->draw(os); os << '\n';
        }
        os << "总面积: " << totalArea() << "\n";
    }

    void save(const std::string& path) const {
        std::ofstream out(path);
        if (!out) throw std::runtime_error("无法打开文件: " + path);
        for (const auto& s : shapes_) { s->serialize(out); out << '\n'; }
    }
    void load(const std::string& path) {
        std::ifstream in(path);
        if (!in) throw std::runtime_error("无法打开文件: " + path);
        shapes_.clear();
        std::string line;
        while (std::getline(in, line)) {
            std::istringstream iss(line);
            std::string type;
            if (!(iss >> type)) continue;
            shapes_.push_back(ShapeFactory::instance().create(type, iss));
        }
    }
    // 深拷贝（体现 clone 的价值）
    Canvas cloneAll() const {
        Canvas c;
        for (const auto& s : shapes_) c.shapes_.push_back(s->clone());
        return c;
    }
private:
    void notify(const std::string& msg) const {
        for (const auto& l : listeners_) l(msg);
    }
    std::vector<std::unique_ptr<Shape>> shapes_;
    std::vector<Listener> listeners_;
};

// ---------- 9. 编辑器：命令栈 ----------

// 专用命令：添加/删除图形（持有 unique_ptr，在 execute 与 undo 之间保存对象）
class AddShapeCommand : public Command {
public:
    AddShapeCommand(Canvas& canvas, std::unique_ptr<Shape> shape)
        : canvas_(canvas), shape_(std::move(shape)) {}

    void execute() override {
        index_ = canvas_.count();                 // 记录插入位置，供 undo 使用
        canvas_.add(std::move(shape_));
    }
    void undo() override {
        shape_ = canvas_.remove(index_);          // 取出并保存，redo 时可原样放回
    }
    std::string name() const override { return "添加图形"; }
private:
    Canvas& canvas_;
    std::unique_ptr<Shape> shape_;
    size_t index_ = 0;
};

class Editor {
public:
    explicit Editor(Canvas& canvas) : canvas_(canvas) {}

    void run(std::unique_ptr<Command> cmd) {
        cmd->execute();
        undoStack_.push(std::move(cmd));
        while (!redoStack_.empty()) redoStack_.pop();     // 新操作清空重做栈
    }
    bool undo() {
        if (undoStack_.empty()) return false;
        undoStack_.top()->undo();
        redoStack_.push(std::move(undoStack_.top()));
        undoStack_.pop();
        return true;
    }
    bool redo() {
        if (redoStack_.empty()) return false;
        redoStack_.top()->execute();
        undoStack_.push(std::move(redoStack_.top()));
        redoStack_.pop();
        return true;
    }
    size_t undoCount() const { return undoStack_.size(); }

    // 便捷封装：添加一个图形（带撤销）
    // unique_ptr 不可拷贝，无法被 std::function 捕获，因此用专用命令类
    void addShape(std::unique_ptr<Shape> s) {
        run(std::make_unique<AddShapeCommand>(canvas_, std::move(s)));
    }
    // 移动图形（带撤销）
    void moveShape(size_t idx, const Point& delta) {
        auto cmd = std::make_unique<LambdaCommand>(
            "移动",
            [this, idx, delta]() { canvas_.at(idx).move(delta); },
            [this, idx, delta]() { canvas_.at(idx).move(Point{} - delta); }
        );
        run(std::move(cmd));
    }
    void scaleShape(size_t idx, double k) {
        auto cmd = std::make_unique<LambdaCommand>(
            "缩放",
            [this, idx, k]() { canvas_.at(idx).scale(k); },
            [this, idx, k]() { canvas_.at(idx).scale(1.0 / k); }
        );
        run(std::move(cmd));
    }
private:
    Canvas& canvas_;
    std::stack<std::unique_ptr<Command>> undoStack_;
    std::stack<std::unique_ptr<Command>> redoStack_;
};

// ---------- 10. 主程序：演示全部功能 ----------
int main() {
    Canvas canvas;
    canvas.addListener([](const std::string& msg) {
        std::cout << "[事件] " << msg << "\n";
    });
    Editor editor(canvas);

    // 添加图形
    editor.addShape(std::make_unique<Circle>(Point{0, 0}, 5));
    editor.addShape(std::make_unique<Rectangle>(Point{10, 10}, 4, 6));
    editor.addShape(std::make_unique<Triangle>(Point{0, 0}, Point{3, 0}, Point{0, 4}));

    canvas.render(std::cout);

    // 变换
    editor.moveShape(0, Point{2, 3});
    editor.scaleShape(1, 2.0);
    std::cout << "\n--- 变换后 ---\n";
    canvas.render(std::cout);

    // 撤销 / 重做
    editor.undo(); editor.undo();
    std::cout << "\n--- 撤销两步后 ---\n";
    canvas.render(std::cout);
    editor.redo();
    std::cout << "\n--- 重做一步后 ---\n";
    canvas.render(std::cout);

    // 统计与查询
    auto byArea = canvas.sortedByArea();
    std::cout << "\n按面积排序: ";
    for (const Shape* s : byArea) std::cout << s->typeName() << '(' << s->area() << ") ";
    std::cout << "\n";

    // 序列化 / 反序列化
    canvas.save("scene.txt");
    Canvas loaded;
    loaded.load("scene.txt");
    std::cout << "\n--- 从文件加载 ---\n";
    loaded.render(std::cout);

    // 深拷贝
    Canvas copy = canvas.cloneAll();
    std::cout << "副本图形数: " << copy.count() << "\n";
}

17.1 语言层面陷阱

# 陷阱 症状 对策
1 基类析构非虚 delete 基类指针泄漏资源 基类析构一律 virtual ~T() = default;

17.2 最佳实践清单（Checklist）

类设计

  • 每个类有明确职责（SRP），名字能一句话说清它是什么
  • 成员变量 private；struct 只用于纯数据
  • 公有接口最小完备：能不放进 public 的就不放
  • 能加 const 的成员函数都加 const
  • 单参数构造加 explicit
  • 优先 Rule of Zero：用 string/vector/unique_ptr 管资源
  • 需要写析构时，同时考虑拷贝与移动（Rule of Five）
  • 移动构造/移动赋值加 noexcept
  • 提供 swap 成员函数（配合 copy-and-swap 与 ADL）

继承与多态

  • 基类析构 virtual
  • 覆盖时写 override；不希望被覆盖时写 final
  • 不在构造/析构中调用虚函数
  • 虚函数不用默认参数
  • 优先组合而非继承；private 继承是最后手段
  • 需要 dynamic_cast 时先反思设计

接口与 API

  • 参数：输入用 const T& 或 T*（非拥有）；输出用返回值；转移所有权用 unique_ptr
  • 返回容器/字符串用值（依赖移动/RVO）
  • 用 std::string_view/std::span 接受只读视图（C++17/20）
  • [[nodiscard]] 标记不该忽略的返回值
  • 明确错误策略：异常 / optional / expected

性能

  • 优先栈对象与值语义，减少堆分配
  • reserve() 预分配避免反复扩容
  • 用 emplace_back 代替 push_back(T(...))
  • 循环里用前置 ++it
  • 大型对象传 const&，返回时依赖 RVO/移动
  • 先测量（perf / vtune / 计时），再优化

工程

  • #pragma once 或 include guard
  • 头文件只包含必需的东西（前向声明、Pimpl 减少依赖）
  • 编译开 -Wall -Wextra -Wpedantic，把警告当错误（-Werror）
  • 开发期开 sanitizer：-fsanitize=address,undefined
  • 单元测试（GoogleTest / Catch2 / doctest）
  • 统一代码风格（clang-format）、静态分析（clang-tidy）

18.2 自测题（检验掌握程度）

<details> <summary>点击展开 10 道自测题（附答案要点）</summary>

  1. class 和 struct 的区别？ → 仅默认访问权限与默认继承方式不同。
  2. 拷贝构造和拷贝赋值的调用时机区别？ → 构造在对象创建时（T b = a;），赋值在对象已存在时（b = a;）。
  3. 为什么基类析构必须是虚函数？ → 否则 delete 基类指针 只调用基类析构，派生部分泄漏。
  4. override 有什么用？ → 让编译器检查是否真的覆盖了基类虚函数，把静默错误变成编译错误。
  5. std::move 做了什么？ → 什么都不"移动"，只是 static_cast<T&&>，把左值转成右值引用，使移动构造/赋值能被选中。
  6. Rule of Three/Five/Zero 分别是什么？什么时候用哪个？ → 见 4.2-4.4；优先 Zero。
  7. 什么是对象切片？如何避免？ → 派生类按值赋给基类对象，派生部分丢失；用引用/指针传参。
  8. unique_ptr 和 shared_ptr 的性能差异？ → unique_ptr 大小=裸指针、零开销；shared_ptr 需控制块（堆分配）、原子引用计数、大小翻倍。
  9. 为什么移动构造要加 noexcept？ → vector 扩容要保证强异常安全，只有 noexcept 的移动才会被使用，否则退化成拷贝。
  10. 构造函数中调用虚函数会发生什么？ → 调用基类版本（vptr 尚未指向派生类虚表），不会多态。

A.2 头文件规范

// shape.hpp
#pragma once                       // 或 #ifndef SHAPE_HPP / #define / #endif

#include <memory>                  // 只包含必需的头
#include <string>

class Point;                       // 能前向声明的就前向声明（减少编译依赖）

class Shape {                      // 声明
public:
    virtual ~Shape() = default;
    virtual double area() const = 0;
};

std::unique_ptr<Shape> makeCircle(double r);   // 自由函数接口

原则：

  • 头文件里只放声明，实现放 .cpp（模板除外）；
  • 不要在头文件里写 using namespace std;；
  • 用 #pragma once（现代编译器普遍支持）或传统 include guard；
  • 减少头文件依赖 = 加快编译（Pimpl、前向声明）。

A.5 快速参考卡片

// ===== 类的标准骨架（现代 C++ 风格）=====
class Widget {
public:
    explicit Widget(std::string name);            // explicit 单参构造
    ~Widget() = default;                          // 或 virtual（若为基类）

    Widget(const Widget&) = default;              // Rule of Zero：能用默认就用默认
    Widget& operator=(const Widget&) = default;
    Widget(Widget&&) noexcept = default;
    Widget& operator=(Widget&&) noexcept = default;

    const std::string& name() const noexcept { return name_; }   // const getter
    void setName(std::string n) { name_ = std::move(n); }

    friend void swap(Widget& a, Widget& b) noexcept {            // 隐藏友元 swap
        using std::swap;
        swap(a.name_, b.name_);
    }
    friend bool operator==(const Widget& a, const Widget& b) {   // 隐藏友元 ==
        return a.name_ == b.name_;
    }
private:
    std::string name_;                            // 类内初始化（若有默认值）
};

// ===== 多态基类骨架 =====
class Interface {
public:
    virtual ~Interface() = default;               // 必须！
    virtual void doWork() = 0;                    // 纯虚接口
    virtual std::unique_ptr<Interface> clone() const = 0;  // 原型
    // 不要拷贝（切片风险），可考虑：
    Interface(const Interface&) = default;
    Interface& operator=(const Interface&) = default;
};

// ===== OOP 决策流程 =====
// 需要运行时替换行为？ → virtual + 基类指针/引用
// 类型集合封闭、性能敏感？ → std::variant + visit
// 编译期即可确定类型？ → 模板 / CRTP
// 只是想复用代码？ → 组合（成员对象），别用继承
// 管理资源？ → RAII + unique_ptr，不写裸 new/delete

结语

面向对象不是"把代码塞进类里"，而是用类型表达概念、用接口约束行为、用不变式保证正确性。

回顾本文的主线：

  1. 封装让你能安全地维护不变式（第 2、3 章）；
  2. 拷贝控制决定了对象能否被安全地复制与移动（第 4、10 章）；
  3. 继承与多态让你写出对扩展开放的代码（第 7、8 章）；
  4. RAII 与智能指针让资源管理自动化、异常安全（第 11、12 章）；
  5. 模板提供零开销的编译期抽象（第 9 章）；
  6. 设计模式与原则是前人总结的、应对变化的经验（第 14 章）。

最后给三条最重要的建议：

  • 优先简单：能不用继承就不用，能不用虚函数就不用，能不用模式就不用；
  • 遵循 Rule of Zero：把资源交给标准库，你的类会又短又对；
  • 让编译器帮你：override、explicit、const、noexcept、static_assert、-Wall -Wextra -Werror——这些都是免费的保险。
